# Правила проекта Xuanxue Cabinet

Кабинет школы тайцзицюань «Сюань-Сюэ». Документы:

- [docs/PLAN.md](docs/PLAN.md) — зачем, для кого, этапы, модель данных, ТЗ этапа.
- [docs/VOICE.md](docs/VOICE.md) — стиль текста для пользователя. Читать перед любой
  user-facing строкой.
- [docs/SECURITY.md](docs/SECURITY.md) — модель угроз, инварианты входа и доступа,
  анти-паттерны. Читать перед правкой auth, API, каналов, шифрования.
- [docs/RUNBOOK.md](docs/RUNBOOK.md) — деплой, откат, логи, инциденты, ротация ключей.
- [docs/adr/](docs/adr/) — архитектурные решения и почему они приняты.

Принцип всего файла: **правило без механизма принуждения не работает.** У каждого
правила ниже назван гейт (CI, тест, eslint, tsc) или сказано «ревью» — и тогда
ревьюер обязан задать указанный вопрос. Правила унаследованы от `telegram-bot-2`
после его аудита 2026-07 и дополнены до старта, чтобы не переделывать потом.

## Структура и слои

```
shared/     типы, константы, чистые утилиты. Не знает ни о Nest, ни о React, ни о Mongo
api/        NestJS + Mongoose. api/src/<домен>/ — module, service, controller, dto, schema, spec
web/        React + Vite + react-router. Один SPA для всех ролей
docs/       PLAN, VOICE, SECURITY, RUNBOOK, adr/
scripts/    CI-храповики и их бейслайны
```

Зависимости идут только вниз: `api → shared`, `web → shared`. `api` и `web` друг о друге
не знают. Типы запросов и ответов API живут в `shared/` и используются обеими сторонами:
DTO в `api` объявляется как `class CreateClassDto implements CreateClassInput` — расхождение
контракта ловит `tsc`. Гейт: eslint `no-restricted-imports` (слои), `import-x/no-cycle`.

Один сервис на Railway: Nest раздаёт `web/dist`, API под `/api`, вебхук Telegram под
`/api/telegram/webhook`. База — MongoDB Atlas. Merge в `main` = деплой.

## Процесс

### 1. Ничего не мержится с красным CI

PR проходит: `tsc` (три пакета), `jest` + e2e (дважды: TZ=Australia/Sydney и с покрытием),
`vitest` с покрытием и под TZ=Australia/Sydney, `eslint`, `prettier --check`, `knip`, `npm audit`, `gitleaks`,
сборка web, сборка Docker-образа с проверкой `/api/health`, все храповики из `scripts/`.
Локально то же самое одной командой: `npm run check` — кроме `gitleaks` (бинаря нет
локально) и Docker-смока, они остаются только в CI. Ручной прогон «по памяти» — не
защита. Репозиторий настроен на squash-only и удаление
ветки после мержа; защита ветки `main` на приватном репозитории без GitHub Pro
недоступна, поэтому «красное не мержится» держится на правиле 1а, а не на кнопке.

### 1а. Мержит агент, не владелец

Агент, открывший PR, доводит его до конца: ждёт CI, при красном чинит и перезапускает,
при зелёном снимает драфт и мержит (squash) без дополнительного вопроса. «Запушил и
ушёл» — незавершённая работа. Исключение — метка `do-not-merge` или «не мержить» в
описании.

### 1б. Маленькие PR, один смысл, заголовок по Conventional Commits

Squash делает заголовок PR сообщением коммита в `main`, поэтому заголовок —
`feat: …`, `fix: …`, `chore: …`, `docs: …`, `refactor: …`, `test: …`, `ci: …`.
Один PR — одна тема. Ориентир — до 400 строк диффа без тестов, lock-файла и бейслайнов;
больше — дели. Рефакторинг и фича — разные PR. Гейт: шаблон PR, ревью.

### 1в. Решение уровня архитектуры = ADR в том же PR

Выбор библиотеки, схемы данных, протокола, способа деплоя, отказ от чего-то — короткий
файл `docs/adr/NNNN-название.md` по шаблону из `docs/adr/README.md`. Без ADR решение
через полгода выглядит случайностью и переделывается. Гейт: чеклист PR, ревью.

### 2. Любой код с логикой приезжает с тестом

В том же коммите. Бэкенд — `*.spec.ts` рядом с кодом; фронт — `*.test.tsx` рядом,
vitest + testing-library. Логика = ветвления, вычисления, работа с данными. Чистый
JSX и стили — нет.

Уровни:

- **Чистая логика** (подстановки шаблона, расчёт времени, форматтеры) — юнит-тест без
  Mongo и без DI.
- **Запросы к базе** (фильтры, индексы, уникальность, агрегации) — против реальной
  Mongo через `mongodb-memory-server`, не через мок модели: мок пропускает ошибки в
  самом запросе.
- **HTTP** — e2e в `api/test/` через `supertest` на настоящем `AppModule`.

**Read-after-write.** Пишем в одном месте, показываем в другом — тест «сохранил →
нашёл», а не только на запись. Обязателен при денормализации, побочном инварианте,
нескольких точках входа.

**Детерминизм.** Время — через `Settings.now` Luxon или явный `now` параметром, не
`Date.now()`. Никаких `setTimeout`-ожиданий, сети, зависимости от порядка тестов.
Мигающий тест чинится или удаляется в тот же день; `retry` запрещён.

Каждый пойманный на проде баг → регрессионный тест с комментарием-ссылкой на инцидент.
Гейты: coverage-храповик api (`scripts/check-coverage-ratchet.mjs`), пороги vitest с
`autoUpdate` в `web/vite.config.ts` — оба могут только расти.

### 3. Новый эндпоинт = DTO с class-validator + e2e на владение

Inline-интерфейсы в `@Body()` — только compile-time иллюзия. Рантайм валидируется
декораторами DTO и глобальным `ValidationPipe({ whitelist: true, transform: true })`.
Каждый новый контроллер — e2e-тест, что пользователь А не видит и не меняет данные
пользователя Б (образец и инструкция — `api/test/e2e-support/`). Гейты: `tsc`
(`implements` общего типа), e2e в CI, `check-route-collisions.mjs`.

### 4. Идентичность для rate-limit — только верифицированная

Бакет троттлинга строится по проверенной подписи (сессия, initData Telegram, подпись
виджета входа). Всё неверифицированное бакетируется по IP (`trust proxy` включён — за
Railway идёт `x-forwarded-for`). Глобальный `ThrottlerGuard` стоит с этапа 0.

### 5. Храповики (CI, `scripts/`)

Счётчик может только уменьшаться; снизил — зафиксируй `--update`:

- `check-file-size-ratchet.mjs` — файл до 150 строк растёт свободно; выше 150 — только
  уменьшается (пересечь границу можно лишь через `--update`, видно в PR); новый файл
  больше 300 строк не рождается. Компонент React больше 150 — выноси хуки и подкомпоненты.
- `check-eslint-ratchet.mjs` — ошибок и предупреждений eslint ноль, бейслайн не растёт.
- `check-jscpd-ratchet.mjs` — дубли ≥70 токенов не растут. Повторяешь блок — в модуль,
  хук или `shared/`.
- `check-coverage-ratchet.mjs` — покрытие api не падает, жёсткий пол на `api/src/utils`.
- `check-robot-phrases.mjs` — канцелярит и «это не X, это Y» в user-facing тексте.
- `check-route-collisions.mjs` — один маршрут, один контроллер.
- `check-env-example.mjs` — каждая читаемая env-переменная описана в `.env.example`.
- `knip` — неиспользуемые файлы, экспорты и зависимости роняют CI.

### 6. Дубли и мёртвый код

Заменяя компонент или сервис новой версией — удаляй старую в том же PR. Файлы-баррели
(`index.ts`, реэкспортирующие всё) не создаём, кроме `shared/src/index.ts`: они
скрывают мёртвый код от `knip` и плодят циклы.

## Код

- **TypeScript строгий**: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`,
  `noImplicitReturns`. `any` не добавляется (каст модели Mongoose на `any` запрещён —
  чини типы). `!` (non-null assertion) — предупреждение, объясни комментарием или убери.
  `@ts-ignore` запрещён, `@ts-expect-error` — только с причиной. `enum` не используем:
  union строк или `as const` объект.
- **Импорты типов** — `import type` / inline `type` (в `api` рантайм-импорт класса нужен
  для DI по классу — там правило действует только на чистые типы).
- **Именование**: файлы `kebab-case` с суффиксом роли (`lesson.service.ts`,
  `lesson.controller.ts`, `lesson.schema.ts`, `create-lesson.dto.ts`); компоненты React
  `PascalCase.tsx`, хуки `useX.ts`. Функции — глагол, булевы — `is/has/can`.
- **Без магических чисел и строк**: константа с именем рядом с использованием или в
  `shared/`. Повторяющийся текст пользователю — тоже константа.
- **Ранний выход** вместо вложенных `if`; функция делает одно; параметров больше трёх —
  объект.
- **Комментарии по-русски и о «почему»**, не о «что». Ссылка на правило или инцидент,
  если код существует из-за них.
- **Логика вне контроллеров и компонентов**: контроллер валидирует и вызывает сервис;
  компонент рендерит и вызывает хук. Гейт: ревью («это можно протестировать без HTTP /
  без DOM?»).

## Конфигурация

Все env-переменные проходят через `api/src/config/env.validation.ts` при старте:
отсутствие или кривой формат — приложение не поднимается с перечнем проблем. Чтение
только через `ConfigService`; `process.env` напрямую — только в валидаторе и в тестовой
инфраструктуре. Новая переменная = поле в схеме валидации + строка с комментарием в
`.env.example`. Гейт: `check-env-example.mjs`, spec валидатора.

## Логи и наблюдаемость

- Логгер — `nestjs-pino`: JSON в production, читаемый вывод в development. Уровень из
  `LOG_LEVEL`. `console.*` в `api/src` запрещён (eslint), используется `Logger`.
- У каждого запроса `requestId` (заголовок `x-request-id`, генерируется если нет); он
  в каждой строке лога и в теле ошибки пользователю — по нему ищут в логах Railway.
- **PII и секреты в логи не попадают**: пароли, ссылки Zoom, токены каналов, cookie,
  `authorization`, email. Список путей — `api/src/logging/redact-paths.ts`, покрыт
  тестом. Тело запроса целиком не логируется никогда.
- Ошибка, которую увидел пользователь, — всегда с `error`-логом и стеком на сервере.
- С этапа 1: сбой доставки после повторов → уведомление учителю в Telegram; ошибки
  планировщика → DM админу. Тихий отказ — самая дорогая ошибка в продукте про рассылки.

## Ошибки

- Сервисы бросают **доменные ошибки** из `api/src/common/errors.ts` (`NotFoundError`,
  `ForbiddenError`, `ConflictError`, `InvalidInputError`), не `HttpException`.
  Глобальный фильтр переводит их в HTTP и в единый конверт
  `{ statusCode, code, message, details?, requestId }` (тип `ApiErrorBody` в `shared/`).
- Неизвестная ошибка → 500 с общим текстом пользователю и стеком в лог. Текст исключения
  наружу не уходит.
- Тексты ошибок для пользователя — по `docs/VOICE.md`, на «вы», с действием: что
  сделать дальше.
- Фронт ходит в сеть только через `web/src/api/http.ts`: один разбор конверта, один
  `ApiError`. `fetch` в компонентах запрещён eslint.
- Telegram: все хендлеры в `try/catch`; `answerCbQuery()` до обращения к БД;
  `editMessageText`/`reply` внутри catch — с `.catch(() => null)`; переходы между
  экранами — `editMessageText`, не `reply`; callback data `действие:параметр`,
  параметры валидируются.

## API

- Префикс `/api`, JSON, `camelCase`, идентификаторы — строки, даты — ISO 8601 в UTC с
  `Z`. Версионирования нет: фронт и бэк деплоятся одним образом.
- Ответ — явный маппер `toDto()` из документа Mongoose в тип из `shared/`. Документ
  Mongoose наружу не возвращается: так секреты (`config` канала, пароль Zoom) не утекают
  «случайно новым полем». Гейт: e2e-тест, что секретные поля отсутствуют в ответе.
- Списки — всегда с лимитом (по умолчанию 50, максимум 200) и фильтром через query-DTO.
  Запрос «дай всё» запрещён.
- Действие с побочным эффектом, которое клиент может повторить (бот, ретрай) —
  идемпотентно: по уникальному индексу или явному ключу.

## Данные (MongoDB)

- Схема Mongoose: `timestamps: true`, все поля типизированы, `Mixed` только с
  комментарием-причиной. Индексы объявлены в схеме; в production `autoIndex: false` и
  `syncIndexes()` при старте; тест-сверка, что уникальные индексы из PLAN.md существуют.
- Чтение через `.lean()` + маппер; выборки скоупятся из сессии: данные ученика — по
  владельцу, данные школы — по роли; `id` из пути — просто строка (см. SECURITY.md).
- **Миграции данных** — `api/src/migrations/`: реестр `{ id, up }`, раннер применяет
  неприменённые до `listen`, пишет в коллекцию `migrations`, при падении приложение не
  стартует. Миграция идемпотентна и совместима со старым кодом (expand → deploy →
  contract), потому что при деплое старый инстанс ещё работает. Тест — на
  `mongodb-memory-server`. Гейт: spec раннера, Docker-смок в CI.
- **Бэкапы**: Atlas M0 бэкапы не делает. Свой `mongodump` по расписанию во внешнее
  хранилище — обязательная часть этапа 1, до первых реальных данных. Дампы в
  репозиторий не кладутся.

### Новая коллекция с полем `userId` — чеклист

1. Имя модели в `USER_OWNED_COLLECTIONS` (`api/src/users/user-data.registry.ts`) —
   удаление и слияние аккаунтов идут по этому списку. Spec-сверка со схемами падает,
   если модель забыта.
2. `EncryptSchema` рядом с методами модели; `encryptRecord` при записи,
   `decryptRecord` при чтении. Не шифровать: id, userId, даты, перечисления.
   `encryption-coverage.spec.ts` требует решения для каждого String/Mixed-поля.
3. Срок хранения: у коллекции с персональными данными записан `retention` (сколько
   живёт и что удаляет). Скриншоты оплат — удаляются после подтверждения + 30 дней.
4. Индексы в схеме, `syncIndexes()`, тест на уникальные.

## Фронтенд

- **Сеть** — только `web/src/api/http.ts`. **Ошибки рендера** — `ErrorBoundary` в
  корне. **Любой `position: fixed; inset: 0`** (лист, оверлей, экран упражнения) —
  через `useHistorySheet(onClose)`, все кнопки «Назад/Закрыть» вызывают `goBack()`:
  иначе «Назад» браузера уводит из приложения. `history.pushState` напрямую запрещён.
- **Загрузка** — скелетоны по форме будущего контента из `web/src/components/Skeleton.tsx`,
  не спиннеры и не пустота. Спиннер допустим только на кнопке действия.
- **Доступность**: семантические элементы (`<button>`, `<label>`), цели нажатия ≥44×44,
  контраст AA, работа с клавиатуры, `prefers-reduced-motion` глушит анимации. Гейт:
  `eslint-plugin-jsx-a11y`, ревью с клавиатуры.
- **Мобильный экран первым**: ученики открывают ссылку с телефона. Макет проверяется на
  360 px до десктопа.
- **Размер**: маршруты грузятся лениво (`React.lazy`), тяжёлые библиотеки не тянутся в
  стартовый бандл. Гейт: `scripts/check-bundle-size.mjs` — суммарный gzip JS стартовой
  страницы не растёт.
- Хуки — `eslint-plugin-react-hooks` (`rules-of-hooks`, `exhaustive-deps` — error).
- Данные пользователя — только из API. Нет данных — пусто, скелетон, «—». Демо-данные
  в рантайм-коде не живут.

## Приложение на телефоне и уведомления

Кабинет с первого дня — устанавливаемое приложение (PWA); push-уведомления —
этап 2 (docs/PLAN.md §5), Telegram и email закрывают этап 1 сами. Решение и
ограничения iOS — [ADR-0006](docs/adr/0006-pwa-and-web-push.md). Правила:

- Manifest и service worker собирает `vite-plugin-pwa` при обычном `npm run build`.
  Гейт: `scripts/check-pwa.mjs` после сборки (manifest, иконки 192/512, SW).
- **`/api/*` никогда не кешируется** SW (NetworkOnly): устаревшее расписание =
  пропущенное занятие, на общем телефоне — чужие данные. Прекеш — только оболочка.
  Обновление — `autoUpdate` + тост.
- **Push — ещё один `ChannelAdapter`** (`webpush`, `VAPID_*` через валидатор env).
  Подписки — `push_subscriptions` в `USER_OWNED_COLLECTIONS`, endpoint и ключи
  зашифрованы (endpoint — capability-URL). 404/410 от push-сервиса → подписку удаляем.
- **Push никогда не единственный канал**: Telegram и email остаются.
- Разрешение на уведомления — по нажатию пользователя после объяснения, не при загрузке.
  На iOS сначала подсказка «На экран „Домой“». Настройки уведомлений — у пользователя.
- Safe-area iOS только в `@media (display-mode: standalone)`. Сессия долгая и rolling:
  в установленном приложении iOS отдельное хранилище, вход заново — норма.

## Продукт

### Кабинет учителя: всё настраивается в интерфейсе

Учитель и админ меняют всё сами: расписание, ссылки, шаблоны постов, за сколько минут
слать, каналы, уведомления, тексты. **Настройка, которую меняет учитель или админ,
живёт в БД и на экране, а не в env и не в константе кода.** Env — только для секретов
и инфраструктуры. Гейт: ревью — «чтобы это поменять, Диме нужен разработчик?». Да —
фича не готова.

### Обращение — только «вы»

Одна форма, без вилки в коде. Согласование во множественном числе: «вы дали», «вы
готовы». Тексты рассылок пишет учитель, мы их не правим.

### Ноль нагрузки на ученика

Ученик «пришёл подвигаться два раза в неделю». Ни одна функция не требует от него
действия, без которого он не попадёт на занятие или не получит запись. Кабинет для
ученика необязателен. Фича, нарушающая это, не мержится.

### Каждая фича объясняет «откуда это и зачем» до первого действия

Объяснение живёт на пути пользователя, не в спрятанном «О разделе». Одно очевидное
главное действие на экран. Ревьюер смотрит глазами новичка: «за 5 секунд понятно, что
это, зачем и что нажать первым?». Нет — не готово.

### Одна механика — один компонент

Одно действие пользователя = один переиспользуемый компонент или хук. Перед новым
контролом, списком, парсером — `grep`: уже есть похожее? Две реализации одного ввода
в разных файлах = фича не готова. Гейт: jscpd, ревью.

### Продуктовая фича = число в «Сводке»

Новая user-facing фича приезжает с числом на странице «Сводка» для админа (отправлено
рассылок, ошибок доставки, оплат за месяц). Чистый форматтер с тестом, включая пустую
БД: на чистой базе — не «0/NaN/мусор», а честное «пока нечего показать». Язык простой.

### Персональные данные учеников — минимум и срок

Собираем только то, что нужно для занятия и оплаты: имя, контакт, статус абонемента.
У каждого поля с персональными данными — причина и срок хранения (см. чеклист
коллекции). Ученик может запросить удаление — `deleteAllUserData` удаляет по реестру.

## Домен: время, каналы, доставка

### Время

- Правило расписания хранится в поясе школы: `{ weekday, time: "19:00", tz }`. Занятие
  «во вторник в 19:00 по Израилю» остаётся в 19:00 через переход времени.
- Конкретные события (`lessons.startsAt`) и отметки отправки — в UTC.
- У пользователя свой пояс в профиле, по умолчанию из браузера. Интерфейс показывает
  его пояс, рядом — пояс школы.
- Только Luxon. `new Date(строка)` и арифметика на миллисекундах в бизнес-логике
  запрещены (eslint `no-restricted-syntax`). Тест на переход летнего времени
  Asia/Jerusalem обязателен для любого кода, который считает «когда».
- CI гоняет jest дважды: в UTC и под `TZ=Australia/Sydney`.

### Каналы

Один интерфейс `ChannelAdapter { send(message, config): Promise<Result> }`, по реализации
на тип: telegram, vk, manual. Импорт SDK мессенджера вне `api/src/channels/`
и `api/src/telegram/` запрещён eslint. Тесты через фейковый адаптер.

### Доставка идемпотентна

Коллекция `deliveries` с уникальным индексом `(broadcastId, channelId)`. Второй тик
планировщика, второй инстанс при деплое, повтор после падения — всё упирается в индекс,
не во флаг в памяти. Повтор после ошибки: через 2 и 10 минут, потом уведомление учителю.

### Посты выглядят как сейчас

Шаблоны по умолчанию повторяют нынешние посты канала слово в слово (PLAN.md, §6).
Пустая подстановка исчезает вместе со своим разделителем. Тест на реальных примерах.

## Безопасность (кратко, полностью — docs/SECURITY.md)

- `helmet` с CSP; внешние источники — только в `api/src/security/csp.ts`, новый = абзац в PR.
- Секреты через валидатор env; реальные ссылки и токены — в `api/seed/*.local.json`
  (`.gitignore`). Гейт: `gitleaks`.
- Свободный текст, токены каналов, ссылки с паролями — AES-256-GCM. Ротация
  `ENCRYPTION_KEY` только с ре-шифрованием (RUNBOOK §6).
- Пароли не храним; сессия — httpOnly cookie, меняющие запросы — с `x-requested-with`;
  токены в `localStorage` запрещены; роль из БД; вебхук с `secret_token`; подписи —
  `timingSafeEqual`. Инварианты и анти-паттерны — SECURITY.md §2–8.

## Зависимости

- Новая зависимость — абзац в PR: что даёт, почему не платформа, кто поддерживает,
  размер для web. Предпочитаем встроенное (`fetch`, `crypto`, `Intl`) библиотеке.
- Версии зафиксированы lock-файлом, установка только `npm ci`. Node — из `.nvmrc`.
- Dependabot раз в неделю, minor/patch одной группой, major отдельно; уязвимости
  prod-зависимостей с уровня high — гейт `scripts/check-npm-audit.mjs`. Уязвимость
  без исправленной версии не снимает гейт: запись в `scripts/audit-allowlist.json`
  с причиной и датой пересмотра, после которой CI снова краснеет. Устаревший PR
  Dependabot не висит дольше недели: мержится или закрывается с причиной.

## Деплой и эксплуатация

- `main` → Railway автоматически. Откат = revert-PR; кнопка Rollback в Railway — только
  при пожаре, и потом всё равно revert-PR, чтобы `main` совпадал с продом.
- `GET /api/health` — версия, Mongo, uptime. SIGTERM обрабатывается
  (`enableShutdownHooks`): тик планировщика завершается, не обрывается.
- Схема данных меняется совместимо (expand → contract): при деплое и откате старый и
  новый код работают одновременно.
- Рискованная фича — за флагом, включается отдельно от деплоя и сначала на добровольцах.
- Инциденты — по `docs/RUNBOOK.md`; после инцидента — запись туда и регрессионный тест.

## Делегирование моделям

Основная модель сессии планирует, ревьюит и отвечает за итог, но не пишет код руками,
пока задача делегируема. Реализация по готовому плану, механические правки, прогоны
сборок и тестов — субагентам (`model: "sonnet"`, совсем механическое — `"haiku"`).
Дорогая модель формулирует ТЗ, принимает работу и дочинивает только то, что дешёвой
модели не удалось. Параллельным агентам — непересекающиеся файлы; зависимости ставит
основной агент заранее одним `npm install`.

## Файлы

- Не создавай файлы без необходимости. Один сервис — один файл; один экран — один
  каталог с компонентом, хуком и тестом.
- `MongooseModule` подключается один раз в `AppModule`; модели регистрируются в своих
  модулях через `MongooseModule.forFeature`.
- Конец сессии — без незакоммиченных правок: либо PR, либо явно отложенная ветка.
