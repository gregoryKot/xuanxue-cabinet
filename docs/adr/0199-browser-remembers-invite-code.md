# 0199. Браузер запоминает код ссылки-приглашения до входа

Дата: 2026-11-06. Статус: принято. Дополняет [ADR-0030](0030-school-invite-link.md)
и [ADR-0036](0036-no-pending-approval.md) (регистрация только по ссылке-приглашению),
соседствует с [ADR-0104](0104-letter-carries-a-code-for-the-app.md) (код из письма).

## Контекст

Ученица 2026-11-06 открыла ссылку-приглашение, попросила код на почту, ушла читать
письмо и вернулась уже на обычный `xuanxue.su`: вкладка внутри мессенджера или почты
закрылась, адрес она набрала сама. Страница входа кода приглашения не знала, и код из
письма упёрся в «откройте ссылку-приглашение от учителя школы» — двадцать минут
повторов. Код приглашения жил только в адресе `/join/<code>` и в параметре `join`
ссылки из письма; любой путь мимо них терял приглашение. Сервер при этом не менялся:
`inviteCode` в `POST /auth/email/request`, `/auth/email/code`, `/auth/telegram`,
`/auth/google/start` был с ADR-0036.

Второй вход в ту же яму — экран «Ссылка-приглашение не действует» (отозванная или
обрезанная ссылка) с кнопкой «На страницу входа» во всю ширину: новичок шёл по ней как
по главному действию и попадал в форму почты.

## Решение

Страница приглашения с живым кодом (`POST /auth/join/check` → `valid`) кладёт код в
`localStorage` (`web/src/auth/inviteMemory.ts`). Страница входа читает его один раз
при монтировании и передаёт во все способы входа так же, как сама страница
приглашения; строка над входом вместо «Первый вход — только по ссылке от учителя»
говорит «Приглашение от учителя у вас есть: войдите любым способом», подсказка «по
почте входят те, кто уже в кабинете» не показывается. Успешный вход стирает код
(`AuthProvider`), мёртвый код стирает сама страница приглашения, если лежал именно он.

`localStorage`, не `sessionStorage`: потерянная вкладка — ровно тот случай, ради
которого код запоминается. Это не токен из SECURITY §2: код один на школу, он уже
лежит в адресе, который человек открыл (история, мессенджер, канал), даёт только
регистрацию учеником и отзывается кнопкой «Обновить» на «Людях».

На экране «не действует» кнопка «На страницу входа» заменена текстовой ссылкой «Уже
входили раньше? На страницу входа»: выход для своих, не действие для новичка.

## Альтернативы

- Класть код в cookie сервером при `join/check` — лишняя cookie и серверное состояние
  ради того, что браузер помнит сам; и cookie тоже не переживает смену браузера.
- Срок жизни у записи — незачем: код отзывается сервером, запись стирает вход или
  отказ сервера; протухшую запись сервер просто игнорирует как неверный код.

## Последствия

- Потерянная вкладка больше не теряет приглашение внутри одного браузера. Смена
  браузера (вкладка в мессенджере → Safari) по-прежнему теряет: хранилища разные.
- Гейты: `inviteMemory.test.ts`, `useJoinByInvite.test.tsx` (запомнил живой, стёр
  мёртвый), `LoginScreen.test.tsx` «запомненное приглашение» (строка, почта с кодом,
  Telegram с `join`, стирание после входа), `JoinScreen.test.tsx` (текстовая ссылка).
