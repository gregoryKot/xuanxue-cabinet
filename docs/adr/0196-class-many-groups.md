# 0196. У занятия и у канала несколько групп

Дата: 2026-11-04. Статус: принято. Уточняет [ADR-0195](0195-group-is-the-only-lever.md):
рычаг рассылки остаётся один — группа, но их у занятия и у канала несколько, а
состояние «Все группы» убрано. Возвращает «несколько групп» из
[ADR-0193](0193-school-groups.md) для занятия и распространяет на канал.

## Контекст

ADR-0195 дал занятию одну группу или «Все группы», каналу — одну группу. Владелец
2026-11-04: «Если мне две группы надо?» — занятие бывает для «Средних» и «Старших»
сразу; следом: и один Telegram-чат бывает общим для двух групп. Одна группа плюс
«Все группы» не выражает «две из трёх», а «Все группы» — лишнее третье состояние: те же
«все» получаются, если отметить каждую группу.

## Решение

Правило одно: **занятие уходит в канал тогда и только тогда, когда его группы и группы
канала пересекаются.** Больше ничего не решает.

- `ClassDto.groupIds: string[]` и `ChannelDto.groupIds: string[]` — в порядке создания
  групп (`_id` группы). Поля `groupId` и `forAllGroups` исчезают из схем, DTO и форм.
  Тело запроса: `groupIds` заменяет список целиком, `[]` — снять все. Неизвестный id —
  400 «Такой группы нет», дубли схлопываются, порядок нормализует сервер; один помощник
  (`groups/group-selection.ts`) на занятие и канал.
- `ClassDto.groupLabel` — названия групп через «, » (`joinGroupNames`); сервер
  пересобирает её при записи занятия и при переименовании группы у **каждого** занятия,
  где группа отмечена. У канала подписи нет.
- Каналы занятия: школьные (`broadcastEligible` не `false`), активные, `groupIds` которых
  пересекается с `groupIds` занятия (`$in`). Канал в ответе один раз, сколько бы общих
  групп ни было, — один пост на канал; от повторов защищает уникальный индекс
  `deliveries (broadcastId, channelId)`, а запрос не порождает дубля сам.
- Личные чаты учеников групп не получают. Канал без групп ничего не получает; занятие без
  групп никуда не уходит; если ни у одной из его групп нет канала — отмена с причиной
  «у группы занятия нет канала», учителю уходит сообщение в Telegram; если есть у части —
  уходит в эти, остальное экран показывает красным.
- Группу нельзя удалить, пока она отмечена у занятия или канала (409, где именно);
  `classCount` и `channelCount` считают документы, где группа есть, — документ с двумя
  группами входит в счёт каждой.
- Экран. Форма занятия и форма канала — один компонент `GroupCheckboxField` («Группы»,
  «Новая группа» тут же, новая отмечается сразу); радио, строка «Все группы» и
  `RadioListField` удалены. Расписание: «→ Средние · Тайцзи онлайн, Старшие · Вечерняя
  группа» (по группе — её каналы; канал с обеими группами назван у каждой — видно,
  откуда занятие до него дойдёт); у части групп нет канала — красное «У группы «Старшие»
  нет канала — туда не уйдёт»; ни у одной — «Ни у одной группы занятия нет канала —
  никуда не уходит»; групп нет — «Без группы — никуда не уходит». Карточка канала:
  «Группы: **Средние, Старшие** · 7 занятий» (занятия, где отмечена хоть одна группа
  канала, без повторов) или красное «Группы не выбраны — посты сюда не уходят».
- Сид занятий (`seed/classes.*.json`): подпись «все группы» значит все группы школы на
  момент импорта; несколько названий через запятую — несколько групп; повторный импорт
  находит занятие по `(title, groupIds)`.

## Миграция `0030-class-group-ids`

1. Занятие без `groupIds`: `forAllGroups: true` → все группы школы в порядке создания;
   `groupId` → `[groupId]`; иначе `[]`. `groupLabel` пересобирается из названий.
   `groupId` и `forAllGroups` снимаются.
2. Канал без `groupIds`: `groupId` → `[groupId]`, иначе `[]`; `groupId` снимается.
3. Документ, у которого `groupIds` уже есть, пропускается: повтор ничего не меняет.

Expand → contract: на время выката старый инстанс ещё читает `groupId`/`forAllGroups`,
которых уже нет, и несколько секунд считает такие занятия и каналы «без группы» —
посты в эти секунды не уходят; окно отправки шире, следующий тик планировщика уже на
новом коде. Приемлемо. Вкладка со старой сборкой, приславшая `groupId`/`forAllGroups`,
получает 400 (`forbidNonWhitelisted`) и просьбу перезагрузиться
([ADR-0101](0101-server-names-its-build-in-a-header.md)). Миграция 0029 хранит литерал
«все группы» у себя: константу `ALL_GROUPS_LABEL` из `shared/` убрали вместе с состоянием.

## Альтернативы

- **Оставить «Все группы» рядом с несколькими.** Два способа сказать одно и то же;
  школа добавит группу — «все» молча перестанет совпадать с «каждой».
- **Канал на одну группу, занятие на несколько.** Общий чат двух групп пришлось бы
  заводить дважды; владелец сказал, что чат бывает общим.
- **Дедуплицировать каналы в строке расписания.** Канал с двумя группами назван у
  каждой; сверка «откуда дойдёт» важнее краткости.

## Последствия

- Закрыто ограничение ADR-0195: «две из трёх групп» выбирается напрямую.
- Гейты: `broadcast-channels.queries.spec.ts` (объединение каналов, один пост на канал с
  теми же двумя группами, группа без канала при живой второй, личный чат, выключенный),
  планировщик и «Отправить сейчас» на реальной Mongo, `groups.service.spec.ts`
  (переименование у занятий с несколькими группами, счёт, запрет удаления), spec
  миграции 0030, e2e `classes`/`channels`/`groups` (в том числе 400 на старые поля),
  vitest форм, строки расписания и карточки канала.
