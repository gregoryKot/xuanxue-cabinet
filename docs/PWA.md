# Приложение на телефоне

Кабинет ставится на экран «Домой» по манифесту — как обычная веб-страница с
ярлыком. Push-уведомления возвращаются всем ролям, включая учеников:
[ADR-0092](adr/0092-web-push-returns.md) заменяет
[ADR-0032](adr/0032-no-service-worker.md) (push отменили 15 сентября), в
основе которого — исходное [ADR-0006](adr/0006-pwa-and-web-push.md). Код едет
отдельными PR (порядок работ — в самом ADR-0092). Service worker (PR №2) уже
стоит и умеет показать push, когда он придёт; там, где ниже всё ещё стоит
будущее время — «появится», «будет», «встанет» — реализации действительно
ещё нет: подписки, отправка с сервера и кнопка разрешения — следующие PR.
Правила:

- Манифест — статический файл `web/public/manifest.webmanifest`, `index.html`
  ссылается на него `<link rel="manifest">`. Гейт: `scripts/check-pwa.mjs`
  после сборки.
- **Знак школы всюду один, и собирается он из одного файла.** Источник —
  `web/brand/school-mark.webp` (круглая печать с черепахой, 512×512, углы
  прозрачные); лежит вне `web/public`, браузеру не раздаётся. Из него
  `node scripts/generate-pwa-icons.mjs` делает все картинки в
  `web/public/icons/`: 192 и 512 для манифеста, maskable 512 для Android, 180
  для iOS, 64 для знака в кабинете (`web/src/components/SchoolMark.tsx`) и
  32/16 для вкладки браузера. Результат лежит в гите. Сменился знак — замени
  источник, выполни скрипт, закоммить картинки
  ([ADR-0085](adr/0085-school-mark-is-a-raster-seal.md)).
- **Цвет оболочки — из палитры кабинета.** `theme_color` и
  `background_color` манифеста, `<meta name="theme-color">` в
  `web/index.html` и сплошной фон под знаком на иконках iOS и Android равны
  токену `--paper` ([ADR-0043](adr/0043-visual-direction-warm-school.md),
  значение — в `web/src/index.css`). Иконку на домашнем экране, заставку и
  полоску браузера человек видит раньше любого экрана. Сменилась палитра —
  правятся все три места и перегенерируется растр:
  `node scripts/generate-pwa-icons.mjs`. Гейт: `scripts/check-pwa.mjs` сверяет
  цвета с токенами, а заодно помнит sha256 источника знака и перечень
  собранных из него файлов — поменять печать и забыть перегенерацию не выйдет.
- Safe-area iOS — только в `@media (display-mode: standalone)`
  (`web/src/pwa/standalone.css`): в браузере вкладка сама рисует чёлку, в
  установленном приложении контент обязан не залезать под неё сам.
- **Service worker снова стоит — но только ради push.** Без прекеша, без
  `fetch`-обработчика, без Workbox: перехватывать запросы и подменять
  страницы ему нечем, поэтому залипание на старой версии, из-за которого
  worker когда-то сносили, не повторяется. Он стоит по тому же адресу
  `/sw.js`, где раньше лежал килсвитч ADR-0032 (`web/public/sw.js`), и
  унаследовал его работу: на `activate` стирает все кеши (добивает старый
  Workbox-прекеш у тех, кто ставил кабинет до сентября), но, в отличие от
  килсвитча, себя не снимает — без постоянной регистрации push не работает.
  `web/src/pwa/registerServiceWorker.ts` регистрирует его молча на каждом
  старте приложения, без запроса разрешения на уведомления (оно просится по
  кнопке — см. ниже). `Cache-Control: no-cache` на `sw.js`, `index.html`,
  манифесте и иконках (`api/src/static/static-cache-control.ts`) остаётся
  как есть и по-прежнему важен: именно он гонит браузер перепроверять файл,
  а не отдавать закешированную версию месяцами. Гейт `scripts/check-pwa.mjs`
  по-прежнему краснеет на `precache`/`workbox` в тексте файла — прекеш не
  должен вернуться вместе с push — и вдобавок проверяет, что файл реально
  умеет push: слушает событие `push`, вызывает `showNotification`.
- **Push без содержимого.** Worker получает пустой пинг и сам читает свежую
  строку из ленты кабинета (`GET /api/me/inbox?limit=20`,
  [ADR-0061](adr/0061-in-app-inbox-becomes-primary-channel.md)) — берёт
  первую непрочитанную запись и показывает её текстом уведомления. Сеть
  откажет, ответ будет не 2xx или непрочитанных не найдётся — показывается
  общая строка «Есть новое уведомление», а не тишина. Слать пинг пока
  некому: подписки лягут в свою коллекцию (`push_subscriptions`, PLAN.md §4);
  эндпоинты подписки/отписки и сама отправка — отдельные PR.
- На iPhone push будет работать только у кабинета, поставленного на экран
  «Домой» (Safari 16.4+ — иначе разрешение не спросить вовсе). Экран, который
  попросит разрешение, обязан объяснить это до первого нажатия.
- Разрешение на уведомления будет запрашиваться **по кнопке**, никогда не
  при входе: браузер запоминает отказ навсегда, а автоматический запрос —
  прямой путь к «Заблокировать».
- Подробности решения, альтернативы и гейты — [ADR-0092](adr/0092-web-push-returns.md).
