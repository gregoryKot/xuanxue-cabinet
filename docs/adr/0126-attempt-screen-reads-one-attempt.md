# 0126. Экран сдачи читает одну попытку своим адресом, не весь список

Дата: 2026-09-23. Статус: принято.

## Контекст

Замер на проде 2026-09-23: экран сдачи экзамена (`web/src/attempt/useAttempt.ts`)
открывал попытку и обновлял её фоновым опросом (`useAttemptVideoPoll.ts`, раз в
15 с, пока ждём видео из Telegram) через `GET /attempts?limit=200` — читал
весь список своих попыток и находил нужную по `id` на клиенте. Своего
`GET /attempts/:id` у API не было (только `GET /attempts` для списка,
`exam-attempts.controller.ts`).

На каждый показ экрана и на каждый тик опроса сервер читал и расшифровывал
(AES-256-GCM, `decryptAttempt`) до 200 чужих снимков формы вместо одного
нужного и отдавал до 80 КБ JSON, из которых клиент оставлял один элемент.
Медиана запроса — 4,7 с, максимум — 15,6 с.

## Решение

`GET /attempts/:id` (`ExamAttemptsController.getOwn`) — владение по сессии,
не по параметру пути (SECURITY §3): чужой или несуществующий `id` отвечает
404 с `ATTEMPT_NOT_FOUND_MESSAGE`, не 403 — не подтверждаем даже факт
существования чужой попытки, тот же инвариант, что у `saveAnswers`/`submit`.
Ленивое закрытие по дедлайну (`closeIfExpiredAttempt`) — тем же путём, что и
у остальных хендлеров попытки.

Владение и Mongo-запрос вынесены в `api/src/exams/exam-attempt-load-own.ts`
(`loadOwnAttempt`) — тот же приём, что `exam-attempt-start.ts` и
`exam-attempt-lifecycle.ts`: `ExamAttemptsService` остаётся диспетчером
правил, файл-храповик держит его не больше 221 строки. `ExamAttemptsService.loadOwn`
(приватный) стал тонким делегатом; `getOwn` — новый публичный метод,
`toAttemptDto(await this.loadOwn(...))`.

Клиент (`useAttempt.ts`) ходит по `attemptPath(attemptId)` вместо
`ATTEMPTS_LIST_PATH` и получает `ExamAttemptDto` напрямую, без поиска по
списку и без поля `notFound` — 404 с сервера уже несёт текст
`ATTEMPT_NOT_FOUND_MESSAGE` через `ApiError`, `error` отдаёт его как есть
(`useAbortableFetch`). Предзагрузка маршрута (`routeModules.ts`) и опрос
видео (`useAttemptVideoPoll.ts`) используют тот же адрес.

## Альтернативы

- **Оставить список, добавить `limit=1&id=...` в query.** `ExamAttemptsService.list`
  не фильтрует по `id`, а заводить такой фильтр ради одного потребителя —
  протаскивать семантику одной записи через маршрут списка (CLAUDE.md «API»:
  списки — списками, запись — записью).
- **Кэшировать список на клиенте между показом и опросом.** Не убирает
  расшифровку 200 снимков на сервере — сама причина замера (80 КБ, 15 с)
  остаётся, а клиентский кэш добавляет второй источник рассинхрона со
  статусом на сервере (ADR-0087: свежее состояние — из ответа записи/своего
  GET, не из локальной копии).

## Последствия

- `ATTEMPTS_LIST_PATH` удалён из `web/src/api/apiPaths.ts` — после перевода
  экрана сдачи и предзагрузки маршрута на `attemptPath` его больше никто не
  импортирует (неиспользуемый экспорт роняет `knip`, CLAUDE.md «Храповики»).
- `GET /attempts` (`ExamAttemptsService.list`) остаётся очередью учителя —
  списком с фильтрами `examId`/`status`, поведение не менялось.
- `UseAttemptResult.notFound` убран — 404 приходит уже с текстом через
  `error`, второе поле с тем же смыслом было бы дублем.
- Тесты: `exam-attempt-load-own.spec.ts` (владение, ленивое закрытие — против
  настоящей Mongo), `exam-attempts.service.spec.ts`/`.controller.spec.ts`
  (`getOwn`), `exam-attempts-ownership.e2e-spec.ts` (А видит свою попытку по
  адресу, Б получает 404 на тот же адрес), `useAttempt.test.ts`/
  `AttemptScreen.test.tsx` (загрузка одной попытки своим адресом, 404 —
  текст «не найдена», фоновый `refresh()` не мигает скелетоном).
