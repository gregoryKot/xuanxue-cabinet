# Правила проекта Xuanxue Cabinet

Кабинет школы тайцзицюань «Сюань-Сюэ». План и этапы — [docs/PLAN.md](docs/PLAN.md).
Стиль текста для пользователя — [docs/VOICE.md](docs/VOICE.md), читать перед любой
user-facing строкой.

Правила унаследованы от проекта `telegram-bot-2` по итогам его аудита 2026-07.
Принцип тот же: **правило без механизма принуждения не работает** — где возможно,
правило дублируется проверкой в CI или тестом.

## Структура

```
api/        NestJS + Mongoose. api/src/<домен>/ — модуль, сервис, контроллер, DTO, spec
web/        React + Vite + react-router. Один SPA для всех ролей
shared/     типы, константы, чистые утилиты, общие для api и web
docs/       PLAN.md, VOICE.md, SECURITY.md
scripts/    CI-храповики и их бейслайны
```

Один сервис на Railway: Nest раздаёт `web/dist` и принимает вебхук Telegram.
База — MongoDB Atlas. Деплой = merge в `main`.

## Процесс

### 1. Ничего не мержится с красным CI
Каждый PR проходит: `tsc --noEmit` для api и web, `jest`, `vitest`, `eslint`,
сборка web, все храповики из `scripts/`. Ручной прогон «по памяти» не защита.

### 1а. Мержит агент, не владелец
Агент, открывший PR, сам доводит его до конца: ждёт CI, при красном чинит и
перезапускает, при зелёном снимает драфт и мержит (squash) без дополнительного
вопроса. Merge в `main` = деплой, поэтому «запушил и ушёл» — незавершённая работа.
Исключение — метка `do-not-merge` или «не мержить» в описании.

### 2. Любой код с логикой приезжает с тестом
В том же коммите. Бэкенд — `*.spec.ts` рядом с кодом, сервис инстанцируется напрямую
с фейковой моделью Mongoose. Фронт — vitest + testing-library. Логика = ветвления,
вычисления, работа с данными. Чистый JSX и стили — нет.

**Read-after-write.** Если фича пишет состояние в одном месте, а показывает в другом —
тест на связку «сохранил → нашёл», а не только на запись. Обязателен, когда есть
денормализованное состояние, побочный инвариант или несколько точек входа.

Каждый пойманный на проде баг → регрессионный тест с комментарием-ссылкой на инцидент.

### 3. Новый эндпоинт = DTO с class-validator + e2e на владение
Inline-интерфейсы в `@Body()` дают только compile-time иллюзию. Рантайм валидируется
декораторами DTO и глобальным `ValidationPipe({ whitelist: true })`. Каждый новый
контроллер — e2e-тест в `api/test/`, что пользователь А не видит данные пользователя Б.

### 4. Идентичность для rate-limit — только верифицированная
Бакет троттлинга строится по проверенной подписи (JWT, initData Telegram, подпись
виджета входа). Всё неверифицированное бакетируется по IP.

### 5. Храповики (CI, `scripts/`)
Счётчик может только уменьшаться; снизил — зафиксируй `--update`, чтобы нельзя
было снова раздуть:
- `check-file-size-ratchet.mjs` — ~150 строк для нового кода, потолок 300. Новый
  файл больше 300 строк не рождается. Исключения: `*.spec`, `*.test`, `*.d.ts`, `dist/`.
- `check-eslint-ratchet.mjs` — ошибки eslint не растут. `no-floating-promises` — error.
  Новые `any` не добавляются, каст модели Mongoose на `any` запрещён.
- `check-jscpd-ratchet.mjs` — дублированные блоки ≥70 токенов не растут.
  Повторяешь блок — выноси в модуль, хук или `shared/`.
- `check-route-collisions.mjs` — один маршрут, один контроллер.
- `check-coverage-ratchet.mjs` — покрытие бэкенда не падает.
- `check-robot-phrases.mjs` — канцелярит и «это не X, это Y» в user-facing тексте.

### 6. Дубли и мёртвый код
Заменяя компонент или сервис новой версией — удаляй старую в том же PR. Раз в квартал
`npx knip --include files` по каждому пакету с grep-верификацией перед удалением.

## Продукт

### Обращение — только «вы»
Одна форма, без вилки в коде. Тексты рассылок пишет учитель как хочет, мы их не
правим. Согласование внутри фразы во множественном числе: «вы дали», «вы готовы».

### Ноль нагрузки на ученика
Ученик «пришёл подвигаться два раза в неделю». Ни одна функция не требует от него
действия, без которого он не попадёт на занятие или не получит запись. Кабинет для
ученика необязателен, всё работает и без него. Фича, нарушающая это, не мержится.

### Каждая фича объясняет «откуда это и зачем» до первого действия
Объяснение живёт на пути пользователя, а не в спрятанном «О разделе». Одно очевидное
главное действие на экран. Ревьюер смотрит глазами новичка: «за 5 секунд понятно,
что это, зачем и что нажать первым?». Нет — не готово.

### Одна механика — один компонент
Одно действие пользователя = один переиспользуемый компонент или хук. Перед новым
контролом, списком, парсером — `grep`: уже есть похожее? Есть — переиспользуй.
Две реализации одного ввода в разных файлах = фича не готова.

### Никаких хардкод-заглушек вместо реальных данных
Всё, что пользователь видит как своё (расписание, статус оплаты, история рассылок),
берётся только из API или БД. Нет данных — пусто, скелетон, «—». Демо-данные не живут
в рантайм-коде.

### Загрузка — скелетоны по форме контента, не спиннеры
Единый примитив `web/src/components/Skeleton.tsx`. Форма скелетона совпадает с
будущим контентом. Спиннер допустим только на кнопке действия.

### Продуктовая фича = видна в «Сводке»
Новая user-facing фича приезжает с числом на странице «Сводка» для админа
(отправлено рассылок, ошибок доставки, оплат за месяц). Чистый форматтер с тестом,
включая пустую БД. Язык простой, без терминов.

## Домен: время, каналы, доставка

### Время
- Правило расписания хранится в поясе школы: `{ weekday, time: "19:00", tz }`.
  Занятие «во вторник в 19:00 по Израилю» остаётся в 19:00 через переход времени.
- Конкретные события (`lessons.startsAt`) и все отметки отправки — в UTC.
- У пользователя свой пояс в профиле, по умолчанию из браузера.
- Только Luxon. `new Date(string)` и арифметика на миллисекундах в бизнес-логике
  запрещены. Тест на переход летнего времени Asia/Jerusalem обязателен для любого
  кода, который считает «когда».
- CI гоняет jest дважды: в UTC и под `TZ=Australia/Sydney`.

### Каналы
Один интерфейс `ChannelAdapter { send(message, config): Promise<Result> }`, по
реализации на тип: telegram, vk, threads, manual. Прямой вызов API мессенджера вне
адаптера запрещён. Тесты через фейковый адаптер, реальные SDK замоканы.

### Доставка идемпотентна
Коллекция `deliveries` с уникальным индексом `(broadcastId, channelId)`. Второй тик
планировщика, второй инстанс, повтор после падения — всё упирается в индекс, не во
флаг в памяти. Повтор после ошибки: через 2 и 10 минут, потом уведомление учителю.

### Посты выглядят как сейчас
Шаблоны по умолчанию повторяют нынешние посты канала слово в слово (см. PLAN.md, §6).
Пустая подстановка исчезает вместе со своим разделителем. Тест на реальных примерах.

## Обработка ошибок

- Все Telegram-хендлеры обёрнуты в `try/catch`.
- `answerCbQuery()` вызывается до обращения к БД или внешним сервисам.
- `editMessageText` / `reply` внутри catch — с `.catch(() => null)`.
- Ошибки через `this.logger.error(...)`, не `console.log`.
- Переходы между экранами бота — `editMessageText`, не `reply`.
- Callback data: `действие:параметр`.

## Безопасность

- Env только через `ConfigService`. Ничего не хардкодится.
- Данные из callback_data и любых query-параметров валидируются перед использованием.
- Админские действия проверяют роль `admin`, не Telegram ID в коде.
- `ENCRYPTION_KEY` — AES-256-GCM для свободного текста, токенов каналов, ссылок с
  паролями. Никогда не ротировать без ре-шифрования: `decrypt()` читает старым ключом
  из `ENCRYPTION_KEY_OLD` как fallback, пишет всегда текущим.
- `JWT_SECRET` — сессии сайта. `BOT_TOKEN` — при компрометации revoke в BotFather.
- Реальные ссылки Zoom, пароли и токены каналов не попадают в git:
  `api/seed/*.local.json` в `.gitignore`.
- Дампы и бэкапы БД никогда не кладутся в репозиторий.

### Новая коллекция с полем `userId` — чеклист
1. Имя модели в `USER_OWNED_COLLECTIONS` (`api/src/users/user-data.registry.ts`) —
   удаление аккаунта и слияние аккаунтов идут по этому списку. Spec-сверка со схемами
   Mongoose падает, если модель забыта.
2. `EncryptSchema` рядом с методами модели; `encryptRecord` при записи,
   `decryptRecord` при чтении. Не шифровать: id, userId, даты, перечисления.
   `encryption-coverage.spec.ts` требует решения для каждого String/Mixed-поля.
3. Индексы объявлены в схеме; `syncIndexes()` при старте; тест-сверка, что
   уникальные индексы из PLAN.md существуют.

## Деплой

- `main` → Railway автоматически. Отдельного push в хостинг нет.
- Сборка в Docker: `npm ci`, `npm run build` для shared, web, api. Nest раздаёт
  `web/dist` со `/`, API под `/api`, вебхук под `/api/telegram/webhook`.
- Health-check `GET /api/health` возвращает версию и статус Mongo. Railway
  перезапускает сервис при падении.
- Планировщик живёт в том же процессе. Тариф Railway без «засыпания», иначе тик
  раз в минуту не идёт.

## Делегирование моделям

Основная модель сессии планирует, ревьюит и отвечает за итог, но не пишет код руками,
пока задача делегируема. Реализация по готовому плану, механические правки, прогоны
сборок и тестов — субагентам (`model: "sonnet"`, совсем механическое — `"haiku"`).
Дорогая модель формулирует ТЗ, принимает работу и дочинивает только то, что дешёвой
модели не удалось.
