# 0093. Повтор попытки — только если её закрыло время, не сам ученик

Дата: 2026-09-21. Статус: принято. Уточняет
[ADR-0024](0024-bot-first-cabinet-as-fallback.md) (бот и кабинет показывают одно и то же
положение ученика по экзамену) и опирается на
[ADR-0038](0038-grading-without-rubric.md) (итог проверки — зачёт, незачёт или
«доработать»).

## Контекст

Кабинет и бот считали правило «когда показывать „Пройти ещё раз“» каждый по-своему.
`web/src/student/examAttemptState.ts` (`getExamAction`) разрешал повтор только для
`status: 'graded'` — с явным комментарием, что сданную, но ещё не проверенную попытку
перезапускать нельзя: вторая попытка тут не доработка, а обход проверки. Бот
(`api/src/telegram/handlers/exam-list-screen.ts`, `examRowStatus`) решал иначе:
`attemptsUsed < attemptsAllowed` → «Начать ещё раз», не глядя на `status` вовсе — то
самое «обход проверки», которое кабинет запрещал. Строка `SUBMITTED_TEXT = 'Сдано,
ждёт проверки.'` в боте была написана, но недостижима: код не успевал до неё дойти,
пока оставалась хоть одна попытка.

Экраны разошлись потому, что решение нигде не лежало одним местом — `shared/` описывал
только форму `MyExamDto`, а «что предложить дальше» каждый экран писал заново.

Отдельно: ни кабинет, ни бот не различали, почему последняя попытка `submitted` — сдал
сам или её закрыло время (дедлайн, `ExamDeadlineCloseService`/`closeIfExpiredAttempt`,
ТЗ 4.4 п.7). Разница уже жила в базе (`exam_attempts.expired`), но `MyExamDto` это поле
не отдавал, и экраны видели только `status`.

## Решение

Владелец на прямой вопрос (2026-09-21): «Пройти ещё раз» показывается, если предыдущую
попытку закрыло время (`expired: true`) и попытки ещё остались. Кто сдал сам и ждёт
проверки — по-прежнему ждёт, кнопки нет.

`MyExamAttemptSummaryDto.expired` — новое обязательное поле контракта
(`shared/src/my-exams.ts`); `MyExamsService` кладёт его из того же `closed.expired`,
что уже даёт ленивое закрытие по дедлайну. Само правило — одна функция
`getMyExamAction(exam: MyExamDto): MyExamAction` там же, шесть веток по порядку:
`in_progress` → «continue» (даже при исчерпанном лимите — попытка уже идёт); лимит
попыток исчерпан → null; попытки не было вовсе → «start»; `graded` → «retry» (учитель
посмотрел, независимо от `expired`); `submitted` и `expired` → «retry»; иначе (`submitted`,
сдал сам) → null. Кабинет (`StudentExamCard.tsx`) и бот (`exam-list-screen.ts`) читают
эту функцию напрямую — местными остаются только подписи кнопок и текст причины, у
каждого экрана свои человеческие слова.

Кнопка «Пройти ещё раз» из-за дедлайна без причины выглядела бы случайной, поэтому
кабинет добавляет рядом строку тем же стилем, что «Осталось N попыток»: «Прошлую
попытку закрыло время» — только когда `retry` вызван именно дедлайном, не оценкой
учителя (у `graded` уже есть свой итог с комментарием, вторая причина рядом была бы
лишней).

## Альтернативы

- **Оставить два решения и синхронизировать вручную** — то, что уже было: один раз
  разъехалось до состояния «обход проверки» (этот ADR — прямое следствие), разъедется
  снова на следующей правке одного экрана без другого.
- **Различать только по `status`, без `expired`** — не отличает «сдал сам» от «не
  успел»: пришлось бы либо всегда пускать `retry` по `submitted` (обход проверки),
  либо никогда (тупик после дедлайна — ровно тот баг, который чинит это решение).
- **Запретить повтор на сервере отдельным кодом ошибки для expired-закрытых попыток** —
  отклонено: лимит попыток (`attemptsUsed < attemptsAllowed`) в `ExamAttemptsService.start`
  уже настоящая защита, вторая проверка того же самого на сервере не нужна. Сервер решает
  «сколько разрешено», экран — «что предложить нажать»; это разные вопросы.

## Последствия

`ExamAttemptsService.start` не меняется и остаётся разрешающим: он и раньше пускал новую
попытку, пока `attemptsUsed < attemptsAllowed`, не глядя на статус последней. Кабинет и
бот теперь предлагают повтор точнее (учитывая `expired`), но то, что API позволяет,
этим решением не сужается — граница только в том, что показывают экраны.

Механизм принуждения — одна функция `getMyExamAction` плюс тест на все шесть веток
(`shared/src/my-exams.spec.ts`), а не два вручную согласованных экрана. Гейт
`check-shared-exports.mjs` не даёт `getMyExamAction`/`myExamAttemptsLeft` остаться
неиспользуемыми в барабане `shared/src/index.ts`.

`MyExamAttemptSummaryDto.expired` — обязательное поле, не опциональное: у попыток
старше этого поля в схеме `.lean()` отдаёт документ вовсе без него, не `false`.
`MyExamsService` нормализует явным сравнением `closed.expired === true` — тот же приём,
что уже был у `description`/`level` в `toMyExamDto` (см. её комментарий).

Гейты: `shared/src/my-exams.spec.ts` (все шесть веток `getMyExamAction`),
`api/src/exams/my-exams.service.spec.ts` (попытка, закрытая дедлайном, приезжает с
`expired: true`, сданная руками — с `false`), `api/src/telegram/handlers/exam-list-screen.spec.ts`
(«Начать ещё раз» у закрытой временем попытки, «Сдано, ждёт проверки.» у сданной
вручную — ветка бота, которая раньше была недостижима), `web/src/student/StudentExamCard.test.tsx`
(кнопка и строка-объяснение у закрытой временем; ни того, ни другого у сданной вручную).
