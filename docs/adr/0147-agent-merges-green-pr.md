# 0147. Агент мержит свой зелёный PR сам; прод — по-прежнему по команде владельца

Дата: 2026-09-29. Статус: принято. Меняет правило 1а CLAUDE.md, заведённое
ADR-0142.

## Контекст

ADR-0142 сделал merge в `main` деплоем на стейджинг и заодно запретил агенту
мержить без команды владельца: тогда ещё шла ночная автоматика, и слитый
коммит сам доезжал до прода. ADR-0144 убрал ночной выкат — прод двигается
только ручным запуском `release.yml`. Стоп на мерже остался и больше ничего не
защищает: зелёный PR висит, пока владелец не напишет «мержи», а проверить
его на стейджинге до этого нельзя. Владелец 2026-09-29: «не уходит же на
прод, только в стейдж — какой смысл не мержить?»

## Решение

Агент, открывший PR, мержит его сам (squash), когда CI зелёный на текущей
голове, конфликтов с `main` нет и открытых замечаний ревью не осталось, и
сообщает владельцу, что изменение на стейджинге. Выкат на прод и откат
(`release.yml`) — только по явной команде владельца. «Не мержи» от владельца
про PR или сессию отменяет самостоятельный мерж.

## Альтернативы

- Оставить мерж по команде — владелец становится узким местом на каждом PR,
  а стейджинг видит изменения позже, чем мог бы.
- Автомерж GitHub — на приватном репозитории без GitHub Pro нет защиты ветки
  и обязательных проверок, автомерж не ждал бы зелёного CI.

## Последствия

- Граница «реальные данные учеников» проходит по выкату, а не по мержу:
  `release.yml` остаётся единственной дорогой на прод.
- Красный `main` бьёт по всем параллельным сессиям, поэтому условие «зелёный
  на текущей голове и без конфликтов» обязательно: после подтягивания `main`
  в ветку CI проходит заново.
- Гейт — ревью и само правило 1а; механизма на стороне GitHub нет (см.
  альтернативы).
