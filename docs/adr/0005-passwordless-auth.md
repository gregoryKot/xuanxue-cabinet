# 0005. Вход без паролей: email-ссылка, Telegram, Google; одна форма «вы»

Дата: 2026-09-04. Статус: принято.

## Контекст

Ученики — взрослые люди разных стран, многие без Telegram; админ работает с почтой.
Принцип «ноль нагрузки на ученика»: кабинет необязателен, вход должен занимать одно
действие. Хранить пароли — ответственность, которую небольшой школе не нужно брать.

## Решение

Три пути входа в один аккаунт (совпадение по email или Telegram ID):

- одноразовая ссылка на email (основной путь для учеников без Telegram и для админа);
- виджет Telegram на сайте и `/start` в боте;
- Google OAuth.

Ученик появляется в системе по приглашению админа или после входа с подтверждением
админом. Сессия — httpOnly cookie, продлевается при использовании. Пароли не хранятся
ни в каком виде. Обращение к пользователю во всех текстах — только «вы», без вилки
ты/вы в коде.

## Альтернативы

- Логин и пароль — восстановление пароля всё равно идёт через email, то есть ссылка на
  email уже является полноценным входом; пароль добавляет поверхность атаки и поддержку.
- Только Telegram (как в мини-аппе `telegram-bot-2`) — часть учеников без Telegram.
- Вилка ты/вы — в `telegram-bot-2` это удвоило каждую строку и дало класс ошибок
  согласования; здесь аудитория взрослая, «вы» уместно всем.

## Последствия

- Инварианты токенов и подписей — в SECURITY.md §2; e2e на каждый путь входа — часть
  этапа 2.
- Письма должны доходить: свой домен, SPF/DKIM/DMARC, отправка через Resend (этап 0–1).
- В установленном PWA на iOS отдельное хранилище: вход заново — норма, поэтому сессия
  долгая и rolling.
- `check-robot-phrases.mjs` следит за голосом; отдельного гейта на форму обращения нет —
  «ты» в тексте ловит ревью и вычитка перед релизом этапа.
