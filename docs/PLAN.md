# Xuanxue Cabinet — план проекта

Кабинет школы тайцзицюань «Сюань-Сюэ» (玄学, xuanxue). Репозиторий `xuanxue-cabinet`.
Документ живёт в `docs/PLAN.md` нового репозитория и правится по ходу.

## 1. Зачем и для кого

Три боли, названные в переписке с Машей:

1. Дима каждый день вручную рассылает ссылку на Zoom за 30 минут до занятия по всем
   каналам, а после занятия — ссылку на запись. Около 20 минут в день, устаёт.
2. Маша ведёт оплаты и переписку с учениками руками. «Большой бардак навожу сама».
3. Ученики теряются в чатах: какое занятие прошёл, какое нет, где запись.

Роли:

| Роль    | Кто                                                      | Что делает                          |
| ------- | -------------------------------------------------------- | ----------------------------------- |
| Админ   | Маша                                                     | Ученики, оплаты, доступы            |
| Учитель | Дима; Мария ведёт часть занятий; позже Гриша (медитация) | Занятия, рассылки, записи, экзамены |
| Ученик  | ~N человек, многие без Telegram                          | Ссылки, записи, оплаты, экзамены    |

Роли не привязаны к людям: учителей несколько с первого дня, одна школа.

### Как это выглядит сейчас

Канал в Telegram, около 65 просмотров на пост. Три вида постов, и в таком же виде они
должны продолжать выходить, только без рук Димы:

```
Через 10 минут цигун для глаз. Запись будет выложена для всех,
кто не может участвовать. https://us02web.zoom.us/j/… пароль 11111

СРЕДНЯЯ ГРУППА
Через 30 минут пятое занятие цикла «Шаги назад: стопы и позвоночник».
https://us02web.zoom.us/j/…?pwd=…

Самомассаж (нижняя часть лица, МФР, сидя). Занятие 30 минут, ведёт Мария —
https://drive.google.com/file/d/…
```

Из постов и расписания на сайте следует:

- У занятия есть **название** («Тайцзицюань онлайн, средняя группа») и у конкретного
  дня — **тема** («пятое занятие цикла „Шаги назад“»). Темы Дима планирует вперёд.
- У ссылки бывает **пароль** отдельной строкой.
- Расписание недельное, около 30 слотов, неделя начинается с **воскресенья**. Часть
  занятий офлайн в парке, часть онлайн, часть «+ онлайн». Расписание меняется
  периодически, ссылки тоже.
- Записи выкладываются двумя способами: ссылка на Google Drive или видеофайл прямо в
  канал (33 минуты, 114 МБ).
- Анонс бывает за 10 минут, за 30 минут, а бывает утром «Сегодня в 19.30».

## 2. Принципы внедрения

Маша боится бардака и просит «внедрять по маленьким функциям». Это и есть план:

- **Нулевая нагрузка на ученика.** Ни одна функция не требует от ученика действий,
  без которых он не попадёт на занятие. Кабинет для него необязателен.
- **Каждый этап полезен сам по себе.** Ссылки рассылаются без оплат, оплаты без экзаменов.
- **Сначала добровольцы, Дима последним.** Каждый этап обкатывается на 3–5 учениках
  и Гриши как втором учителе, и только потом переводится школа.
- **Обращение только «вы».** Одна форма, без вилки в коде. Тексты рассылок пишет учитель.
- **Приложение на телефоне с первого дня.** Кабинет устанавливается на экран «Домой»
  (PWA) и присылает уведомления как обычное приложение. Push дополняет Telegram и email,
  а не заменяет их (ADR-0006).
- **Учитель настраивает всё сам.** Расписание, ссылки, шаблоны, каналы, время рассылки,
  уведомления — с экрана кабинета, без разработчика. Env — только для секретов.

### Время и часовые пояса

Ученики в разных странах, школа в Израиле, где переход на летнее время.

- Правило расписания хранится как `{ weekday, time: "19:00", tz: "Asia/Jerusalem" }`.
  Занятие «во вторник в 19:00 по Израилю» остаётся в 19:00 через любой переход времени.
- Конкретные события (`lessons`) и все отметки отправки — в UTC.
- У пользователя в профиле свой пояс, по умолчанию из браузера. Интерфейс показывает
  время в поясе пользователя, рядом — в поясе школы.
- Библиотека — Luxon. Тест на переход летнего времени обязателен.

### Вход и роли

Три способа входа, все ведут в один аккаунт по совпадению email или Telegram ID:

- **Email-ссылка** без пароля (основной для учеников без Telegram и для админа).
- **Telegram**: виджет входа на сайте и `/start` в боте.
- **Google**: OAuth, для тех, кому так удобнее.

Пароли не храним. Ученик появляется в системе, когда админ добавляет его в список
(имя + email или Telegram), либо когда сам входит и админ подтверждает.

## 5. Этапы

Порядок — от самой острой боли к самой сложной функции. Критерий готовности этапа —
одна фраза, которую можно проверить.

### Этап 0. Скелет и правила — 1–2 дня

Репозиторий, workspaces, CI с храповиками, `CLAUDE.md` с перенесёнными правилами,
деплой пустого приложения на Railway с health-check, подключение Atlas, домен
`xuanxue.su` (ADR-0009).
PWA-оболочка: manifest, иконки, service worker, гейт `check-pwa.mjs`. Рантайм-каркас
api: валидация env, логи с requestId и редакцией, конверт ошибок, троттлинг, helmet,
раннер миграций, e2e-инфраструктура. Фронт-каркас: http-клиент, ErrorBoundary,
`useHistorySheet`, пороги покрытия.

Готово, когда: пустой PR проходит CI, `main` автоматически выезжает на Railway,
приложение ставится на экран «Домой» на Android и iPhone.

### Этап 1. Кабинет учителя: занятия и рассылки — 1–2 недели

Подробное ТЗ в разделе 6. Коротко: 20 занятий с названиями и ссылками, расписание,
каналы, автоматическая ссылка за N минут до занятия, рассылка записи после занятия,
разовые рассылки, журнал доставок. Учитель управляет всем и с сайта, и из Telegram-бота.
Канал `webpush` и подписка на уведомления в установленном приложении — сначала для
учителя (предпросмотр рассылки, сбой доставки), тем же механизмом потом для учеников.

Готово, когда: Дима неделю не отправил ни одной ссылки руками, и в журнале нет
неотправленных доставок.

### Этап 2. Ученики и оплаты — 1–2 недели

- Список учеников: добавить, пригласить ссылкой, статус.
- Вход для учеников тремя способами.
- Абонемент по месяцам: «оплачен / ждёт подтверждения / не оплачен». Ученик присылает
  скриншот перевода в бота или загружает на сайте, админ подтверждает одной кнопкой.
- Напоминания об оплате по расписанию, в тот канал, где ученик есть.
- Личные рассылки: кроме групп, ссылка уходит лично в Telegram, на email или пушем в
  установленное приложение — куда ученик включил. Экран «Уведомления» в профиле:
  какие события, на какие устройства; подсказка установить приложение на iOS.

Готово, когда: Маша месяц не ведёт оплаты в стороннем файле.

### Этап 3. Материалы и архив — 1 неделя

- Библиотека: книги, документы, ссылки, которыми делится Дима. Привязка к занятиям.
- Архив записей по занятиям: ученик видит, какие занятия прошёл, где запись.
- Доступ по статусу оплаты — включаемая настройка, по умолчанию выключена.

Готово, когда: ученик находит запись прошлого занятия без вопроса в чат.

### Этап 4. Экзамены — 2–3 недели

- Конструктор формы для учителя: текст, выбор варианта, задание с видео. Порядок,
  обязательность, подсказки.
- Ученик проходит форму, загружает видео напрямую в R2 по подписанной ссылке,
  черновик сохраняется.
- Учитель видит карточку ученика: все сдачи, ответы, видео, свои комментарии и оценку.
- Результат: зачёт / незачёт / комментарий. Ученику приходит уведомление.

Готово, когда: один экзамен целиком проведён через кабинет.

### Этап 5. Второй учитель и рост

Гриша ведёт онлайн-медитацию на той же платформе: свои занятия, каналы, ученики.
Проверка, что модель «несколько учителей в одной школе» держит нагрузку.

## 6. ТЗ этапа 1: кабинет учителя

### Экраны сайта

1. **Вход.** Email → ссылка на почту. Кнопки «Войти через Telegram», «Войти через Google».
2. **Расписание.** Недельная сетка с воскресенья по субботу, как на сайте школы: слот =
   название, время, формат, ведущий. Карточка слота: ссылка Zoom, пароль, каналы,
   «за сколько минут слать», выключатель. Утренний анонс — после подтверждения Димой
   (§10). Изменение правила действует на будущие занятия, уже спланированные вручную
   не трогает.
3. **Планирование.** Календарь на четыре недели вперёд, построенный из расписания.
   У каждого занятия — тема («пятое занятие цикла „Шаги назад“»), которую учитель
   вписывает заранее. Можно отменить занятие, перенести, поменять ссылку на один раз,
   добавить разовое занятие вне расписания. Статус рассылки: отправлено / ждёт / ошибка.
   После занятия — кнопка «Добавить запись»: ссылка на Drive или видео. Добавил —
   рассылка уходит сама. Записи лежат на YouTube (ответ владельца от 2026-09-06,
   закрывает вопрос §10): `{ссылка}` записи — ссылка YouTube; Telegram получает
   видео по `file_id` напрямую; ВК прикрепляет то же видео с YouTube по ссылке
   (`video.save` с параметром `link`) — это делает адаптер ВК, не учитель руками;
   Boosty — ручной канал (тип `manual`, как Facebook): текст со ссылкой и кнопка
   «скопировал, отправил».
4. **Каналы.** Подключение: Telegram-канал (добавить бота админом), ВК (токен
   сообщества и беседа), «Вручную» для Facebook.
   Проверка «отправить тест».
5. **Рассылки.** Разовая: текст, время, каналы, предпросмотр. Журнал: что, куда, когда,
   с какой ошибкой. Ручные доставки ждут кнопки «скопировать» и «отметить отправленным».
6. **Шаблоны.** Два текста, по умолчанию повторяющие нынешние посты канала слово в
   слово (утренний анонс из §1 сюда не входит — появится после подтверждения Димой,
   вопрос в §10):

   ```
   Анонс:   [{группа}
   ]Через {минут} минут {название}[: {тема}]. Запись будет выложена для всех,
   кто не может участвовать.
   {ссылка}[ пароль {пароль}]
   Запись:  {название}[: {тема}][. Занятие {длительность}][, ведёт {ведущий}][ — {ссылка}]
   ```

   Синтаксис (ADR-0011): плейсхолдер `{имя}` из allow-list ниже; необязательный
   фрагмент `[ … ]` — исчезает вместе со скобками, если внутри него нет ни одного
   плейсхолдера или все плейсхолдеры внутри пустые, иначе остаётся с подстановками.
   Вложенные `[` не поддерживаются. Один проход по исходному тексту шаблона: значения
   вставляются как есть и не разбираются повторно — тема со скобками в названии не
   ломает разметку. Никакого eval (SECURITY.md §4). Реализация и тесты на реальных
   постах — `shared/src/templates.ts`, `shared/src/templates.spec.ts`.

   Подстановки и их поля:

   | Плейсхолдер      | Источник                                                                                  |
   | ---------------- | ----------------------------------------------------------------------------------------- |
   | `{название}`     | `classes.title` (для `recording` — `recordings.title`)                                    |
   | `{тема}`         | `lessons.topic`                                                                           |
   | `{группа}`       | `classes.groupLabel`                                                                      |
   | `{ссылка}`       | `lessons.zoomLinkOverride ?? classes.zoomLink` (для `recording` — `recordings.url`)       |
   | `{пароль}`       | при переопределённой ссылке — только `zoomPasswordOverride`, иначе `classes.zoomPassword` |
   | `{время}`        | `startsAt` в поясе `classes.tz`, формат `HH:mm`                                           |
   | `{минут}`        | `classes.leadMinutes`                                                                     |
   | `{ведущий}`      | имя `lessons.leaderId ?? classes.leaderId`                                                |
   | `{длительность}` | `formatDurationRu(lessons.durationMin)`                                                   |

   Один набор шаблонов на школу (`settings.templates`), можно переопределить на слот.
   Адаптер канала шлёт результат рендера как plain text, без разметки (parse_mode) —
   значения не экранируются намеренно, посты идут как обычный текст.

Первый экран после входа объясняет за пять секунд: «Здесь расписание школы. Впишите
ссылку Zoom в занятие, и ученики получат её за 30 минут до начала сами».

### Telegram-бот для учителя

Дима может не открывать сайт. Бот:

- за 5 минут до автоматической рассылки присылает предпросмотр с кнопками «Отменить»
  и «Изменить тему»;
- после занятия спрашивает «Запись?»: ответ ссылкой или видеофайлом запускает рассылку.
  Видео бот публикует в канал по `file_id` без перезаливки, поэтому лимит загрузки
  в 50 МБ не мешает. Проверить в первые дни этапа;
- для Facebook присылает готовый текст с кнопкой «Скопировал, отправил»;
- по команде `/тема` показывает ближайшие занятия и даёт вписать тему.

### Планировщик

- Раз в минуту: создать `lessons` на 4 недели вперёд по правилам всех активных
  слотов, если их ещё нет. Офлайн-слоты без ссылки занятия создают, рассылку не планируют.
  **Реализовано** — `LessonPlannerService` (`api/src/lessons/`, решения о
  переносе/удалении/вставке — `lesson-reconcile.ts`, запросы —
  `lesson-planner.queries.ts`) и `SchedulerService` (`api/src/scheduler/`),
  лог `scheduler.tick` раз в минуту (RUNBOOK §2 п.4). Разовое занятие вне
  расписания учитель создаёт через `POST /lessons` без `plannedAt` —
  планировщик такие даты не трогает вовсе, они не участвуют в согласовании ниже.
  Согласование с текущим расписанием (тот же тик): изменили или удалили правило,
  выключили или удалили класс — будущие занятия пересчитываются, но
  **тронутое занятие планировщик не удаляет и не переносит**. Тронуто — вписана
  тема, занятие отменено или перенесено вручную, есть переопределение ссылки/пароля,
  заметка, назначен свой ведущий или уже есть запись. Занятие с темой, но иначе
  обычное (не перенесено, не отменено, без записей) — при смене времени правила
  всё равно переезжает на новый момент того же правила, тема остаётся при нём: это
  не «тронуто» в смысле блокировки переноса, только в смысле «не удалять». Перенос
  допустим, только если новый момент реально ожидается тем же правилом и ещё не
  занят другим занятием класса в этом тике — иначе занятие обрабатывается как
  «правила больше нет» (нетронутое удаляется, тронутое остаётся). Поэтому смена
  дня недели у правила (не только времени) старое нетронутое занятие удаляет и
  создаёт новое на новый день, а не переносит на месте; обмен временем между двумя
  правилами одним сохранением рассасывается за один-два тика, не падает ошибкой.
  Класса нет в базе — все его будущие занятия удаляются независимо от тронутости:
  без класса их нельзя отрендерить (нет названия, ссылки). Занятие, чей `startsAt`
  ближе `leadMinutes` класса — не трогаем вовсе: ссылка могла уже уйти. Длительность
  даты из расписания следует правилу и меняется только через него; у разовой даты —
  своя, PATCH меняет её напрямую.
- Раз в минуту: для каждого занятия, у которого `startsAt - leadMinutes` наступило и
  нет `broadcast` вида `lesson_link`, создать рассылку и доставки. Контракт для этого
  шага (реализация — следующий PR): рассылка уходит только когда
  `lesson.status === 'scheduled'` и `class.active === true`; занятие без класса в
  базе — `warn` в лог и пропуск (разослать нечего, ссылки нет); занятие, которое
  между планированием рассылки и её отправкой перестало существовать (учитель
  удалил разовое занятие) — рассылка вида `cancelled`, а не молчание.
- Доставка: адаптер канала по типу. Ошибка → статус `failed`, повтор через 2 и 10 минут,
  потом уведомление учителю.
- Один интерфейс `ChannelAdapter { send(text, config) }`, четыре реализации. Тесты с
  фейковым адаптером, реальные вызовы замоканы.

`GET /lessons` принимает `?from&to&classId`: окно дат обязательно и не шире

401, без ролей (`roles: []`) и `student` — 403, `teacher`/`admin` — 200,
`config` канала не утекает ни в одном ответе ни одной роли.

## 7. Правила, которые переезжают из текущего проекта

Переносятся в `CLAUDE.md` нового репозитория вместе со скриптами-храповиками:

- Ничего не мержится с красным CI. Мержит агент, не владелец.
- Любой код с логикой приезжает с тестом, включая фронт. Read-after-write тесты для
  денормализованного состояния.
- Новый эндпоинт = DTO с class-validator + e2e на владение.
- Лимит файла: ~150 строк, потолок 300, пофайловый храповик.
- Храповики: eslint, jscpd, покрытие, робот-фразы. Стиль-гайд `docs/VOICE.md`.
- Одна механика — один компонент. Скелетоны по форме контента, не спиннеры.
- Никаких хардкод-заглушек вместо данных пользователя.
- Каждая фича до первого действия объясняет «откуда это и зачем».
- Секреты только через `ConfigService`. Свободный текст и токены каналов шифруются.
- Новая коллекция с `userId` = реестр удаления + шифрование + тест-сверка.
- Обработка ошибок Telegram: try/catch, `answerCbQuery` до БД, логгер вместо console.

Что **не** переезжает: вилка ты/вы, кризисная детекция (не терапевтический продукт),
два фронтенда, Prisma и миграции, `/stats` в боте (вместо него страница «Сводка»
для админа с этапа 2).

Новые правила этого проекта:

- **Время**: правила в поясе школы, события в UTC, показ в поясе пользователя. Любая
  работа с датами — через Luxon, `new Date(string)` в бизнес-логике запрещён.
- **Каналы**: только через `ChannelAdapter`. Прямой вызов API мессенджера вне адаптера
  запрещён.
- **Доставка идемпотентна** через уникальный индекс, не через флаги в памяти.
- **Ноль нагрузки на ученика**: фича, требующая от ученика действия без обходного пути,
  не мержится.
- **PWA и push**: `/api/*` не кешируется service worker'ом; push — ещё один
  `ChannelAdapter`, никогда не единственный канал; разрешение спрашивается по нажатию.
- **Учитель настраивает всё сам**: настройка живёт в БД и на экране, не в env.
- **Гейты с первого дня**: env-валидатор, конверт ошибок, requestId, редакция логов,
  миграции данных, e2e на владение, Docker-смок, knip, gitleaks, prettier (ADR-0007).
