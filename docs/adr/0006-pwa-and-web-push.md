# 0006. Устанавливаемое приложение (PWA) и push как канал доставки

Дата: 2026-09-05. Статус: принято.

## Контекст

Ученики открывают ссылку с телефона за минуты до занятия. Нужно, чтобы кабинет жил на
экране «Домой» как приложение и присылал уведомления: ссылка на занятие, запись, оплата.
Публикация в App Store и Google Play — отдельная разработка, ревью магазинов и ежегодные
взносы, несоразмерные школе с десятками учеников. У учителя — личный кабинет, где всё
настраивается без разработчика.

## Решение

- `web/` — PWA: manifest (иконки 192/512 и maskable, `display: standalone`, `lang: ru`),
  service worker через `vite-plugin-pwa` (Workbox). Прекеш — оболочка приложения;
  шрифты и иконки — CacheFirst; `/api/*` — NetworkOnly, никогда не кешируется.
  Обновление — `autoUpdate` с тостом.
- Уведомления — Web Push (VAPID, библиотека `web-push`) как ещё одна реализация
  `ChannelAdapter` (`webpush`): та же коллекция `deliveries`, тот же журнал, те же
  повторы. Подписки — коллекция `push_subscriptions` (`userId`, зашифрованные endpoint
  и ключи, устройство, `lastSeenAt`), в `USER_OWNED_COLLECTIONS`; 404/410 от
  push-сервиса удаляет подписку.
- Разрешение на уведомления запрашивается по нажатию пользователя после объяснения,
  не при загрузке. На iOS сначала подсказка установить на экран «Домой».
- Push никогда не единственный канал: Telegram и email остаются.
- Кабинет учителя: любая настройка (расписание, ссылки, шаблоны, каналы, уведомления)
  живёт в БД и меняется с экрана. Env — только для секретов и инфраструктуры.

## Альтернативы

- Нативные приложения (React Native, Capacitor) — магазины, подписи, два билда,
  ревью Apple; для школы избыточно. Capacitor остаётся запасным путём: тот же SPA
  оборачивается позже, если веб-пуши на iOS окажутся ненадёжными.
- Только Telegram-уведомления — часть учеников без Telegram (ADR-0005).
- Firebase Cloud Messaging — лишний сторонний сервис; стандартный Web Push покрывает
  Chrome, Firefox, Safari 16.4+ без него.

## Последствия

- CI: `scripts/check-pwa.mjs` после сборки проверяет manifest, иконки и service worker.
- `/api/*` в кеше SW запрещён (конфиг + анти-паттерн в SECURITY.md §8).
- Новые env: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — через валидатор.
  Ротация = все подписки мертвы (RUNBOOK §6.4).
- Ограничение iOS принимаем: пуши только установленному приложению 16.4+; вход в
  standalone заново из-за отдельного хранилища.
- Ручная проверка на реальных Android и iPhone после каждого этапа — пункт в RUNBOOK §2.
