# 0193. Группы школы — общий список; занятие входит в несколько групп

Дата: 2026-11-04. Статус: принято. Уточняет [ADR-0072](0072-class-tags-are-the-constant-of-a-course.md): подпись
группы у занятия больше не свободный текст.

## Контекст

`classes.groupLabel` был свободным текстом на каждом занятии. Из сайта пришли семь
написаний одной и той же вещи: «новички», «начинающие», «младшая группа», «средняя
группа», «старшая группа», «продвинутые», «все группы». Ничто не показывало, что
«новички» и «начинающие» — одна группа, а занятие «для всех» нельзя было отнести сразу
к трём. Владелец 2026-11-04: группы — общий список школы (сначала «Начинающие»,
«Средние», «Старшие»), занятие входит в несколько групп, новую группу заводить легко,
в том числе прямо из формы занятия. Медитация остаётся с теми же тремя группами.

## Решение

Новая коллекция `groups`: `name`, `nameKey` (название без регистра и пробелов по краям,
уникальный индекс), порядок — по созданию. У занятия появляется `groupIds[]`.

`groupLabel` остаётся, но **выводится**: названия групп занятия через запятую в порядке
создания групп. Сервер пересобирает её при создании и правке занятия и при
переименовании группы. Клиент подпись не пишет: из `CreateClassInput` и
`UpdateClassInput` она убрана. Вкладка со старой сборкой, приславшая `groupLabel`, получит 400
(глобальный `forbidNonWhitelisted`) и предложение перезагрузиться ([ADR-0101](0101-server-names-its-build-in-a-header.md)).

API `/groups` (штат): `GET` со счётчиком занятий (`classCount`, одна агрегация),
`POST` и `PATCH` с одним полем `name`, `DELETE` — только пока `classCount` равен нулю.
Одно название — одна группа: дубль даёт 409 с именем уже существующей. Неизвестный id
группы у занятия — 400.

Миграция `0027-groups-from-labels` заводит три группы и переводит подписи: «новички»,
«начинающие», «младшая группа» → «Начинающие»; «средняя группа» → «Средние»;
«старшая группа», «продвинутые» → «Старшие»; «все группы» → все три; пустая → без
групп. Подпись не из таблицы (например, «четверг» из первой миграции расписания) не
теряется: под неё заводится группа с тем же названием, и миграция называет её в отчёте.
Занятия, у которых `groupIds` уже есть, пропускаются — повтор безвреден.

В кабинете: раздел «Группы» на экране «Школа» (список, переименование, удаление, добавление)
и список групп галочками в форме занятия с полем «Новая группа» прямо под ним.

## Альтернативы

- **Убрать `groupLabel` совсем.** Около 45 мест читают его: посты (`{группа}`), бот,
  экраны учеников, публичный список занятий, `classDisplayName`. Каждое пришлось бы
  учить собирать подпись из групп — тот самый разнобой, от которого уходим.
- **Группа — тег (`classes.tags`).** Теги — свободный текст без списка и без
  переименования ([ADR-0072](0072-class-tags-are-the-constant-of-a-course.md)); общего списка с счётчиком и защитой
  от удаления это не даёт.
- **Одна группа на занятие.** «Все группы» тогда остаётся отдельным значением, а не
  тремя отметками.

## Последствия

- Переименование группы меняет подпись у всех её занятий сразу: так и задумано, но
  уже разосланные посты остаются как были.
- Удалить группу можно только пока у неё ноль занятий; сначала её снимают на странице
  каждого занятия.
- Занятие, созданное старым инстансом во время выката, остаётся без `groupIds` с
  прежним текстом в `groupLabel`; миграция в тот момент уже отработала. Новый код
  читает такое занятие как «без групп» и не перезаписывает подпись, пока занятие не
  сохранят из формы. Выкат короткий, а занятий, заведённых за это окно, обычно нет.
- Импорт занятий из файла сида (`api/seed`) по-прежнему называет группу текстом
  (`groupLabel`): сервис находит или заводит группу с таким названием.
- Порядок групп — порядок создания; сортировки и цвета не заведены (владелец не просил).
