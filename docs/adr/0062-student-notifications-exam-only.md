# 0062. Дефолт уведомлений ученика — только результат экзамена

Дата: 2026-09-20. Статус: принято.

## Контекст

Отзыв владельца 2026-09-19: «по умолчанию ученики только об экзаменах уведомления
получают». Отзыв владельца 2026-09-20: «сообщения от учителя вообще не запланированы
через кабинет, есть другие каналы» — личным сообщениям учителя ученику кабинет не
нужен вовсе, не только по умолчанию.

До этого PR `STUDENT_NOTIFICATIONS` (`shared/src/notifications.ts`) — три вида:
«Занятие скоро», «Сообщение от учителя», «Результат экзамена». Ни «Занятие скоро», ни
«Сообщение от учителя» не имели доставки (docs/PLAN.md §13, «Отправки здесь нет») —
это был контракт на будущее. «Результат экзамена» — исключение: доставка у него уже
есть (`TelegramExamNotifier`, `MailExamNotifier`, слой 4.7, §11) и она уже проверяет
именно этот переключатель. Из трёх заявленных ученику видов работал ровно один.

## Решение

`STUDENT_NOTIFICATIONS` — один вид, результат проверки работы: единственное, что
требует действия ученика (посмотреть результат) и единственное, что реально приходит.
Остального он не просил и не должен включать вручную вслепую, чтобы не остаться
случайно совсем без уведомлений (CLAUDE.md «Ноль нагрузки на ученика»).

Вид уведомления «Сообщение от учителя» убран из проекта с концами (CLAUDE.md
«Отказались от механики — удаляем с концами»): из `NOTIFICATION_KINDS`, подписи,
подсказки, тестов, документов. У него не было доставки и не будет — у учителя есть
свои каналы для личных сообщений, кабинет эту доставку не планирует вовсе.

Вид «Занятие скоро» в контракте (`NOTIFICATION_KINDS`) остаётся — он определён, у
него есть подпись и подсказка, доставка для него ожидается этапом 3 (docs/PLAN.md
§13). До решения владельца его вернуть в дефолт он просто выключен: это пока
единственный вид, у которого нет ни одной роли-получателя по умолчанию, включая
ученика.

**Данные, а не только код.** У человека, который успел выключить «Сообщение от
учителя» руками до этого PR, в `notification_prefs.overrides` остаётся значение вне
enum подсхемы (`NotificationOverrideSubdoc`, `notification-prefs.schema.ts`) — тип
`NotificationKind` его больше не допускает. На момент этого решения запись не падает:
`NotificationPrefsService.set` пишет через `updateOne` без `runValidators`, `.save()`
на этой модели нигде не вызывается — это не починка существующего бага, а закрытие
скрытой ловушки на будущее (включит кто-то `runValidators` или `.save()` на этой
схеме — откажут ровно те, кто настройки трогал руками, то есть самые заинтересованные
люди). Миграция `0011-notification-prefs-teacher-message-removed`
(`api/src/migrations/`) вычищает это значение из `overrides` — `$pull` по уникальному
историческому значению, идемпотентно, спек на `mongodb-memory-server`.

## Альтернативы

- **Оставить вид выключенным по умолчанию, не удалять код.** Переключатель, у
  которого никогда не было и не будет доставки, — обман: человек видит контрол, за
  которым нет действия.
- **Оставить «Занятие скоро» включённым по умолчанию.** Владелец сказал буквально
  «только экзамен» 2026-09-19 — включать больше этого без нового отзыва означало бы
  подменить решение владельца своим.
- **Не делать миграцию, положиться на фильтр `applyOverrides`.** Он и правда не
  падает на чтении — значение вне списка `NOTIFICATION_KINDS` молча выпадает. Но
  это работает только для чтения; в базе лишнее значение остаётся вне enum, и это
  мина для первого апдейта, который включит валидацию. Не годится как постоянное
  решение при наличии правила «удаляем с концами» — оно распространяется на
  данные, не только на код.

## Последствия

Ученик получает по умолчанию одно уведомление, а не три; экран «Профиль»
(`NotificationPrefsSection`) и меню `/notifications` бота показывают ему один
переключатель вместо трёх — это ожидаемо компактный экран для одной роли, не
сломанный. Добавить уведомление о личных сообщениях учителя через кабинет снова
нельзя без нового решения владельца — версия этого PR закрывает вопрос, а не
откладывает его.

Гейты: `tsc` (тип `NotificationKind` больше не принимает убранное значение —
использование не компилируется), тесты контракта и применения
(`shared/src/notifications.spec.ts`, `apply-overrides.spec.ts`,
`notification-prefs.service.spec.ts`, e2e-владение), миграция
`0011-notification-prefs-teacher-message-removed` со спеком на
`mongodb-memory-server`.
