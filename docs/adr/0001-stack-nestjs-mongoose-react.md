# 0001. NestJS + Mongoose + React, монорепо с `shared/`

Дата: 2026-09-04. Статус: принято.

## Контекст

Автор уже ведёт проект `telegram-bot-2` на NestJS + Prisma + React с двумя фронтендами.
Опыт оттуда: правила и храповики переносимы, а два фронтенда с общим кодом через
копипасту дали 3+ случая расхождения. Команда — один человек и агенты, поэтому стек
должен быть знакомым, а не модным.

## Решение

Монорепо на npm workspaces: `api/` (NestJS 11, Mongoose 9, TypeScript), `web/`
(React 19, Vite, react-router), `shared/` (типы контрактов API, константы, чистые
утилиты). Один SPA для всех ролей. Контракты API объявляются в `shared/`, DTO в `api`
реализуют их через `implements`.

## Альтернативы

- Prisma + Postgres, как в `telegram-bot-2` — миграции Prisma дали крашлуп прода на часы
  (инцидент 2026-07-16); для документов вроде расписания и шаблонов Mongo естественнее.
- Next.js / full-stack фреймворк — второй рантайм-стиль, который автор не ведёт.
- Два фронтенда (сайт + мини-апп Telegram) — отвергнуто из-за расхождений; учитель и
  ученик работают в одном SPA, бот для учителя дополняет, а не дублирует.

## Последствия

- Общий код между `api` и `web` живёт только в `shared/`; eslint запрещает импорты
  между `api` и `web` (правило «Слои» в CLAUDE.md).
- Расхождение типа запроса и DTO ловит `tsc`, а не прод.
- Mongoose требует своей дисциплины: индексы в схеме, `syncIndexes()`, миграции данных
  через собственный раннер (ADR не нужен, см. CLAUDE.md «Данные»).
