# 0197. Тема недели — запись темы в выбранные занятия, не своя сущность

Дата: 2026-11-05. Статус: принято. Опирается на [ADR-0054](0054-lesson-move-syncs-broadcast.md)
(пересборка ещё не ушедшего поста) и правило «тронутого» занятия из PLAN §6 «Планировщик».

## Контекст

Владелец 2026-11-05: «было бы круто задать тему недели и выбрать занятия, для которых
её указать на неделю». Дима планирует темы циклами («пятое занятие цикла „Шаги назад“»),
и одна тема обычно идёт на несколько занятий недели. Сейчас тема вписывается на каждой
дате отдельно (`lessons.topic`, страница занятия или `/тема` в боте) — тридцать слотов
в неделю, одно и то же слово руками.

История связки «расписание → занятия → рассылки» учит двум вещам (ADR-0054, ADR-0168,
ADR-0192, ADR-0195): производное состояние, которое надо догонять при переносе, отмене
или пересчёте планировщиком, рано или поздно расходится; а второй невидимый источник
правды даёт тихий отказ.

## Решение

Темы недели как записи в базе нет. «Тема недели» — действие на экране «Занятия»:
текст плюс галочки занятий одной недели (неделя с воскресенья, как в расписании школы).
Сохранение пишет текст в `lessons.topic` каждого отмеченного занятия одним запросом
`POST /lessons/topic { topic, lessonIds }`, и для каждого занятия пересобирает ещё не
ушедший пост со ссылкой тем же `LessonLinkRebuildService`, что и смена темы с
одной даты.

По умолчанию отмечены неотменённые занятия недели без своей темы; занятие со своей
темой показано с ней и не отмечено. Повторное открытие показывает текущую тему недели —
самую частую непустую тему среди занятий недели — и отмечает занятия, где она стоит;
правка текста перепишет его у отмеченных. Две темы на одну неделю для разных групп —
два сохранения с разными галочками. Тема одного занятия правится на его странице, как
и раньше.

Число раздела: под заголовком недели строка «Тема недели: … · 5 из 12 занятий» или
«Тема недели не задана» — чистый форматтер с тестом, на пустой неделе строки нет.

## Альтернативы

- **Коллекция `week_topics { weekStart, topic, lessonIds }`.** Занятие переносится,
  отменяется, пересоздаётся планировщиком при смене правила — список `lessonIds`
  пришлось бы догонять в каждом из этих мест (ADR-0054 показал цену). Пост при этом
  всё равно читал бы `lessons.topic`, то есть второй источник правды.
- **Тема у правила расписания (`classes`) с датой начала цикла и счётчиком.** Удобно
  для «пятое занятие цикла», но цикл у Димы не всегда совпадает с правилом (одна тема
  на среднюю группу — три разных правила), и счётчик ломается первой же отменой.
- **Тема как тег.** Тег — рубрика для поиска (ADR-0075), в пост не попадает; завести
  второй текст «для поста» значит снова два поля для одного.

## Последствия

- Нового состояния и миграции нет; пост берёт тему оттуда же, откуда брал.
- Занятие с темой становится «тронутым» (PLAN §6): при удалении правила планировщик
  его не удалит. Это уже так для темы с одной даты — ничего нового.
- Смена темы с сайта пересобирает ещё не ушедший пост (починено этим же днём,
  раньше пересобирал только бот). Пост, который уже ушёл, не меняется — как и у смены
  темы из бота.
- Гейты: `lessons-topic.service.spec.ts` (запись и пересборка против настоящей Mongo,
  неизвестный id — 404, пустой список — 400), `lessons-topic.e2e-spec.ts` (ученик — 403,
  «записал → увидел в `GET /lessons`»), vitest на `weekTopic.ts` (черновик, сводка,
  пустая неделя) и на экран.
