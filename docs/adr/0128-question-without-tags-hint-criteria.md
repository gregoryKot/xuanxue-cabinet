# 0128. Вопрос экзамена — без тегов, подсказки и критериев

Дата: 2026-09-23. Статус: принято. Уточняет
[ADR-0022](0022-exam-model-item-bank-and-snapshot.md) (модель вопроса и его версии),
[ADR-0058](0058-material-tags-are-rubrication.md) (рубрикация тегом) и
[ADR-0116](0116-tag-is-picked-from-what-the-school-already-has.md) (общий список
подсказок тегов).

## Контекст

Форма вопроса экзамена несла четыре содержательных поля: формулировку, подсказку
ученику (видна до ответа), критерии проверки (видны только учителю, для текстовых
вопросов без автопроверки) и теги (раздел программы, уровень — тот же способ ввода,
что у материала, ADR-0058).

Владелец школы 2026-09-23 решил убрать все три поля: вопрос должен собираться из
формулировки и вариантов, без лишних шагов. Три поля из четырёх стояли в форме и в
диалоге бота, занимая место и удлиняя путь от «выбрал тип вопроса» до «вопрос сохранён».

## Решение

**Вопрос экзамена несёт только формулировку и (для single/multiple) варианты ответа.**
`hint`, `criteria` и `tags` убираются из контракта целиком: `ExamItemDto`,
`CreateExamItemInput`, `UpdateExamItemInput`, `ExamItemVersionDto` (shared/exam-items.ts),
из снимка попытки (`AttemptQuestionDto`, `AttemptReviewQuestionDto`) и из схемы
`exam_items` — вместе с полями уходит тег-индекс и `EXAM_ITEM_FIELD_POLICY` для них.

**Диалог бота «Новый вопрос» короче на шаг.** Шаг `criteria` убран из
`NewExamItemStep`; после варианта (или сразу после формулировки у text/video) диалог
идёт прямо к подтверждению.

**Сводка тегов школы (`GET /tags`, ADR-0116) считает три источника, не четыре.**
Агрегация по `exam_items` и поле `examItemCount` убраны — тег вопроса решению ADR-0116
предшествовал по времени, но с уходом самого поля терять стало нечего.

**Старые данные не переписываются на лету.** Прошлые редакции внутри зашифрованного
`history` могут по-прежнему хранить `hint`/`criteria` в JSON — тип их просто не
описывает, мапперы их не читают, это не ошибка и не приоритет для чистки. Миграция
`0015-exam-items-without-hint-criteria-tags` снимает верхнеуровневые
`hint`/`criteria`/`tags` документов `exam_items`, заведённых до этой правки.

## Альтернативы

- **Оставить поля, но спрятать за «показать ещё»**: не решает главного — учитель всё
  равно видит лишний шаг при создании вопроса, просто он свёрнут по умолчанию. Раз
  полем не пользуются никогда, ему не место в контракте вовсе.
- **Оставить только критерии (для текстовых вопросов) и убрать подсказку с тегами**:
  владелец попросил убрать все три поля разом.
- **Оставить теги, но убрать только hint/criteria**: конструктор экзамена находит
  вопрос по тексту формулировки, отдельная метка для поиска не нужна.

## Последствия

- Форма вопроса (`ExamItemFormFields.tsx`) — одно поле, не четыре; конструктор экзамена
  ищет вопросы только по тексту (`ExamQuestionSearch.tsx`, `filterQuestionCandidates`).
- Диалог бота «Новый вопрос» — на один шаг короче: `prompt` → (`options`/`correct`) →
  `confirm`, без «Пропустить критерии».
- Экран тега (ADR-0075) не менялся и раньше не показывал вопросы экзамена — здесь без
  изменений.
- `TagsModule` не импортирует `ExamItemModelModule`; `countExamItemsByTag` удалена вместе
  с агрегацией.
- Гейт: `check-shared-exports.mjs` (мёртвый экспорт не проскочит), `encryption-coverage.spec.ts`
  (поля `hint`/`criteria` больше нет в `FieldPolicy` — проверять нечего), e2e
  `exam-items.e2e-spec.ts`/`exam-attempts.e2e-spec.ts` (тело ответа не содержит
  `hint`/`criteria`/`tags`), spec миграции 0015.
