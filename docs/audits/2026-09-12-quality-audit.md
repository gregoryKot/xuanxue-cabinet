# Аудит качества — 2026-09-12

Полный аудит репозитория на коммите `1f66ae5` (после PR #91). Цель — проверить,
что правила CLAUDE.md, SECURITY.md и PLAN.md действительно держатся кодом и
гейтами, и найти дефекты, которые гейты не ловят.

## 1. Итог

Кодовая база для этапа проекта необычно зрелая: слои разделены и гейтованы,
Mongo-логика тестируется против реальной базы, идемпотентность рассылок держится
на индексах, DST-тесты реально пересекают переход, документация кода почти
всегда совпадает с поведением. Полный `npm run check` на чистом дереве: 171
jest-сьюта и 1357 тестов api зелёные, 147 файлов и 1003 теста web зелёные,
все храповики зелёные.

Две находки требуют решения владельца до следующего этапа:

1. **Модель ролей ученика противоречива** — три документа говорят разное, код
   делает третье. Следствие сегодня: любой человек с аккаунтом Telegram входит
   в кабинет без подтверждения и получает ссылки и пароли Zoom всех занятий
   школы. Следствие завтра: настоящий ученик не сможет начать попытку экзамена.
2. **Локальный `npm run check` не проходит** и оставляет грязное дерево, а
   храповик покрытия web в CI заморожен. Заявление «локально то же самое одной
   командой» не выполняется.

Остальное — средние и мелкие дефекты и семь правил CLAUDE.md, у которых нет
названного в них гейта.

## 2. Метод

- Семь направлений параллельно (безопасность api; планировщик, рассылки,
  доставка, время; экзамены, уведомления, люди, каналы; фронтенд и PWA;
  инфраструктура, CI, храповики, документы; качество тестов; пакет `shared`).
- Полный прогон `npm run check` на чистом дереве и повторный прогон
  `test:cov --workspace=web` для воспроизведения дефекта гейта.
- Каждая находка ниже перепроверена вручную по коду главным аудитором:
  указаны файл и строка, сценарий и минимальный фикс. Состязательная
  перепроверка субагентами не состоялась (внешний лимит), поэтому в отчёт
  вошло только то, что подтверждено чтением кода или прогоном.

Обозначения: **H** — чинить до следующей фичи, **M** — в ближайшие PR,
**L** — при касании кода. Объём: trivial / small / medium.

## 3. Находки

### H1. Ученик, гость и роль `student`: три документа, четыре поведения

Где:

- `docs/SECURITY.md` §2: «Пользователь без единой роли (`roles: []`) — гость,
  видит только `/auth/me`».
- `docs/PLAN.md` §3: «Ученик — своё расписание, свои записи…»; ADR-0005:
  «Ученик появляется в системе по приглашению админа или после входа с
  подтверждением».
- `web/src/people/PersonRow.tsx:29`: `ASSIGNABLE_ROLES = USER_ROLES.filter(role
=> role !== 'student')` с комментарием «ученик — это отсутствие остальных
  ролей». Роль `student` назначить нельзя.
- `api/src/exams/exam-attempts.controller.ts:36`:
  `@Roles('student', 'teacher', 'assistant', 'admin')` — старт попытки требует
  именно роль `student`.
- `api/src/lessons/my-lessons.controller.ts` (и `my-exams`,
  `notification-prefs`): без `@Roles`, `AuthGuard` пропускает любую сессию,
  включая `roles: []`.
- `api/src/auth/telegram-auth.service.ts:60-68`: первый вход с любого
  Telegram-аккаунта создаёт пользователя с `roles: []` и сразу выдаёт сессию;
  статус `invited` из `USER_STATUSES` нигде в коде не используется —
  подтверждения из ADR-0005 нет.
- `api/src/lessons/my-lesson.mapper.ts:32-54`: в ответ кладутся расшифрованные
  `zoomLink` и `zoomPassword`.

Сценарий А (сейчас): посторонний открывает `xuanxue.su`, нажимает «Войти через
Telegram», получает `roles: []` и `GET /api/me/lessons` со ссылками и паролями
Zoom на все занятия вперёд. Это угроза №3 из SECURITY.md §1 (зум-бомбинг), и
e2e `api/test/my-lessons.e2e-spec.ts:84` закрепляет это поведение как
ожидаемое.

Сценарий Б (при первом экране экзамена у ученика): `GET /me/exams` покажет
опубликованную форму, `POST /exams/:id/attempts` вернёт 403 — у ученика нет
роли `student`, и назначить её некому. Критерий готовности этапа 4 («экзамен
целиком через кабинет») недостижим без правки Atlas руками — тот же класс
проблемы, что аудит Б3.

Решение — за владельцем, два честных варианта:

1. **Подтверждение** (рекомендуется): новый пользователь получает
   `status: 'invited'`; `AuthGuard` пускает в `/me/*` и в попытки экзамена
   только `active`; админ подтверждает на «Люди» одной кнопкой (сейчас там
   уже есть подсказка «без роли — ученик», кнопка ляжет рядом). Роль
   `student` из `@Roles` экзамена убрать, ученик = `active` без ролей
   учителя. SECURITY §2 переписать под это. e2e: «`invited` не видит
   `zoomLink`», «`active` без ролей начинает попытку». Объём: small.
2. **Открытый доступ**: осознанно принять, что расписание с паролями видно
   любому вошедшему; переписать SECURITY §2 и §1 п.3; убрать `student` из
   `@Roles`; удалить `invited`. Объём: trivial, но модель угроз ослабляется.

### H2. `npm run check` красный на чистом дереве, храповик покрытия web заморожен

Где: `web/vite.config.ts:121-128` (`thresholds.autoUpdate: true`), корневой
`package.json` → `check`, `.github/workflows/ci.yml` (джобы `web` и `checks`).

Воспроизведение (сделано дважды, на чистом дереве):

```
git status --short          # пусто
npm run test:cov --workspace=web
git status --short          #  M web/vite.config.ts  (branches: 98.6 → 98.64, снят финальный \n)
npx prettier --check web/vite.config.ts   # [warn] Code style issues found
```

Последствия:

- `npm run check` всегда падает на `format:check`, как только покрытие выросло,
  и оставляет незакоммиченную правку — нарушены «локально то же самое одной
  командой» и «конец сессии — без незакоммиченных правок».
- В CI vitest тоже переписывает файл, но `prettier --check` бежит в другой
  джобе на чистом checkout, а правка выбрасывается вместе с раннером. Порог в
  репозитории (98.6) уже отстаёт от факта (98.64) — «порог может только расти»
  не работает, работает только «не ниже записанного».

Фикс (small): убрать `autoUpdate`, завести `scripts/check-web-coverage-ratchet.mjs`
по образцу api (читает `coverage/coverage-summary.json`, бейслайн в
`scripts/`, `--update` для поднятия) и подключить в `gates` и в джобу `web`.
Альтернатива — оставить `autoUpdate`, но в том же шаге CI делать
`prettier --write web/vite.config.ts && git diff --exit-code`: рост порога
станет обязательным коммитом.

### M1. Замок миграций снимается без проверки владельца

Где: `api/src/migrations/migration.runner.ts:61-79`.

`acquireLock` перехватывает просроченный замок (`expiresAt < now`), а
`releaseLock` делает безусловный `deleteOne({ _id: '__lock' })`. Если инстанс А
работал дольше `LOCK_TTL_MINUTES` (10), инстанс Б перехватил замок и оба
выполняют `applyPending`; когда А заканчивает, его `finally` удаляет замок Б.
Двойное применение `up()` не ловится: `insertOne({ _id: migration.id })` у
проигравшего бросает E11000, который не перехвачен, — инстанс падает на
старте. Сегодня миграции быстрые и инстанс один, поэтому это не проявляется,
но заявленная защита «два инстанса не выполняют одну миграцию» не держится.

Фикс (small): `ownerId` (случайный id процесса) в документе замка; удаление и
продление только с условием `ownerId`; E11000 на записи «применена» трактовать
как «уже применил другой» и идти дальше.

### M2. Ошибки Telegram: любой 400 — «чат не найден», `retry_after` не читается

Где: `api/src/channels/telegram.adapter.ts:129-141`.

`messageForCode(400)` всегда возвращает `CHAT_NOT_FOUND_MESSAGE`, хотя 400 у
Bot API — это и «message is too long», и «wrong file identifier», и «caption
is too long». Учитель получит DM «чат не найден» и пойдёт проверять бота в
чате, а проблема в тексте или в `file_id`. Код 429 помечается `retryable`, но
`parameters.retry_after` из ответа не берётся — повтор через 2 минуты может
попасть в ещё действующий лимит.

Фикс (small): в текст ошибки брать `description` ответа Telegram (после
`scrubChannelSecrets`), `retry_after` передавать в исход как минимальный
`nextAttemptAt`.

### M3. Диалоги не запирают фокус

Фокус ставится на заголовок, Escape и возврат фокуса работают, скролл фона

Фикс (small): в `useDialog` перехватывать `Tab` по списку фокусируемых
элементов контейнера или ставить `inert` на соседей корня диалога.

### M7. Пересборка темы: окно между проверкой и записью

Где: `api/src/broadcasts/topic-rebuild.service.ts:61-89`.

`deliveryModel.exists({ status: { $ne: 'pending' } })` проверяется один раз, затем
несколько `await` (занятие, класс, настройки, рендер) и `updateOne` текста.
Раннер за это время может захватить и отправить доставку старым текстом;
`updateOne` всё равно пройдёт (`broadcast.status` ещё `scheduled`), и бот
ответит «тема обновлена», хотя часть каналов уже получила старый пост. Окно —
несколько операций с БД, вероятность низкая.

Фикс (small): повторить `exists` непосредственно перед `updateOne` и при
«захвачено» вернуть честный ответ; полностью закрывает только условный апдейт
с версией доставок.

### M9. Парсер шаблона квадратичен на несбалансированных `[`

Где: `shared/src/templates.ts:88-109` (`parseSegments`).

Когда `indexOf(']')` возвращает `-1`, следующая `[` сканирует остаток заново.
Замер на `'['.repeat(n)`: 100k — 56 мс, 200k — 219 мс, 400k — 882 мс (×4 на
удвоение). Сегодня спасает только `@MaxLength(2000)` в
`api/src/settings/dto/update-settings.dto.ts`; в `shared`, где парсер живёт и
переживёт вызывающих (ADR-0011), защиты нет.

Фикс (trivial): если `]` не найдена — дальше её нет нигде, отдать остаток
одним `text`-сегментом и выйти.

## 4. Что проверено и держится

- **Вход и сессия.** HS256 вручную с фиксированным алгоритмом, подпись
  проверяется до разбора тела, `timingSafeEqual` с проверкой длины, `exp`
  через `Number.isFinite`, rolling-перевыпуск, cookie `HttpOnly; SameSite=Lax;
Secure` в production. Виджет Telegram: подпись по сырому телу, окно 24 ч,
  отрицательный возраст отклоняется. CSRF-заголовок обязателен для всех
  мутирующих запросов, включая `@Public()`, единственное исключение — вебхук.
- **Гварды и владение.** У каждого школьного ресурса `@Roles` на классе,
  `users` — `admin` с точечным исключением `GET /users/teachers`; без гварда
  только `/health` и вебхук (`secret_token` через `timingSafeEqual`). Данные
  ученика (попытки, настройки уведомлений) скоупятся по `userId` из сессии,
  чужой id даёт 404. `config` канала не покидает сервер ни одним путём,
  включая текст ошибок (scrub). Роль читается из БД на каждый запрос,
  `blocked` отсекается до ролей.
- **Валидация.** `ValidationPipe({ whitelist, forbidNonWhitelisted, transform })`,
  `@MaxLength`/`@ArrayMaxSize`/`@IsMongoId`/`@IsIn` везде, единственное
  осознанное исключение — `POST /auth/telegram`. NoSQL-инъекция через query не
  проходит: объекты отклоняются декораторами.
- **Шифрование и логи.** AES-256-GCM, случайный IV, тег проверяется, ротация
  через `ENCRYPTION_KEY_OLD`; `encryption-coverage.spec.ts` требует решения на
  каждое строковое поле; `redact-paths.ts` покрывает cookie, authorization,
  email, telegramId, токены, zoom-поля; тело запроса не логируется.
- **Планировщик и доставка.** Только Luxon, `now` параметром; окно рассылки и
  граничные условия совпадают с PLAN §6 и покрыты тестами на границах;
  `waitForCompletion: true` у cron; SIGTERM ждёт тик; лиза доставки —
  `findOneAndUpdate`, просроченная через 10 минут, повторы 2 и 10 минут,
  батч 100; все insert-пути ловят E11000; `refreshBroadcastStatus` проверен на
  всех комбинациях статусов. Reconcile занятий соответствует PLAN построчно.
- **Экзамены.** Снимок формы при старте; правка вопроса не меняет снимок;
  уникальный индекс `{examId, userId, attemptNo}` против двойного клика;
  дедлайн условным апдейтом; мапперы прячут `correct`/`criteria`.
- **Фронтенд и PWA.** Сеть только через `http.ts`, один `ApiError`, 401 без
  циклов, `AbortController` в общем хуке; все экраны `React.lazy`, скелетоны,
  `ErrorBoundary` в корне; все `position: fixed; inset: 0` — через
  `useHistorySheet`; `role="dialog"`, `aria-modal`, Escape; `/api/*` —
  `NetworkOnly`, precache только оболочка; манифест полный; бандл 85 КБ gzip
  при бюджете 200; токенов в `localStorage` нет; `dangerouslySetInnerHTML`
  нет.
- **Тесты.** Нет `.only`/`.skip`/`retry`/`Math.random`/сетевых вызовов; Mongo-
  логика — против `mongodb-memory-server` во всех сервисах с запросами;
  read-after-write — устоявшаяся практика; DST-тесты пересекают оба перехода;
  все 17 контроллеров покрыты e2e с проверкой ролей и владения; миграции и
  раннер — идемпотентность и отказ при старте.
- **Инфраструктура.** Все гейты из CLAUDE.md, кроме перечисленных в M10,
  реально подключены в CI и в `check`; `npm audit` чист (три исключения
  `multer` с датой пересмотра 2026-12-10); секретов в истории нет; 30
  последних коммитов по Conventional Commits; бэкап-скрипты с `set -euo
pipefail`, отказом без пароля и `--yes`-защитой.
