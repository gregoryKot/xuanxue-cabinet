# 0194. У канала нет выключателя: куда уходит занятие, решают только галочки

Дата: 2026-11-04. Статус: принято. Уточняет [ADR-0192](0192-channel-tags-removed.md)
(там «отмечен и включён» — теперь просто «отмечен»).

## Контекст

Владелец 2026-11-04: «один рычаг для рассылки». После ADR-0192 у занятия остался один
видимый механизм — галочки «занятие ↔ канал» (`classes.channelIds`) — и один невидимый:
переключатель «Включён» на странице канала. Выключенный канал оставался отмеченным у
занятий, а посты в него молча не шли. Тот же тихий отказ, что был у тегов: галочка
говорит «да», выключатель на другой странице говорит «нет».

## Решение

**Куда уходит занятие, решают только галочки.** Канал не нужен — его удаляют; нужно
приостановить — «Снять все» в секции «Какие занятия сюда уходят» на странице канала.
Второго способа «молча не слать» нет.

- Переключатель «Включён» и пометка «Выключен» в списке удалены. `active` убран из
  `UpdateChannelInput`, `ChannelDto` и query `GET /channels` (фильтра `?active=` больше
  нет). Списки в «Расписании», «Рассылках» и на странице занятия берут тот же полный
  список: `useChannels()` без аргумента.
- **Миграция `0028-channel-switch-into-links`.** У каждого канала школы
  (`broadcastEligible` не false) с `active: false` его id снимается у всех занятий
  (`$pull` из `channelIds`), затем канал получает `active: true`. «Не слать» учителя
  становится «нет галочек» — маршруты те же, но видны. Личные чаты учеников не трогаем.
  Идемпотентна (второй запуск не находит выключенных каналов), совместима со старым
  кодом на время деплоя: он читает `active: true`, а снятые галочки дают тот же
  маршрут. В лог идут только id каналов и число снятых галочек.
- **Что `active` значит теперь.** Внутренний признак «в чат можно писать», не настройка:
  у личного чата ученика `false` — пока он заблокировал бота (ADR-0027,
  `has-active-telegram-chat.ts`); у канала школы — всегда `true`. Проверки при
  планировании и отправке (`broadcast-channels.queries.ts`, `readConfig().active`)
  остаются: для канала школы они безвредны, для личных чатов нужны.

## Последствия

- Вкладка, открытая до деплоя, при сохранении канала пришлёт `active`, а глобальный
  `ValidationPipe` работает с `forbidNonWhitelisted: true`: ответ 400 «поле не
  поддерживается», в базу ничего не пишется. Достаточно перезагрузить страницу (так же,
  как с `tags` в ADR-0192 и полями занятия в ADR-0193); терпеть удалённое поле в DTO
  ради этого окна не стали. Запрос `GET /channels?active=…` из старой вкладки тоже
  получит 400.
- Ручная рассылка в канал, где `active: false` по другой причине (бота убрали из
  группы), по-прежнему отказывает; её текст больше не предлагает «включить» канал,
  которого выключателя нет.
- Гейты: spec миграции на `mongodb-memory-server` (выключенный канал — галочки сняты и
  `active: true`; включённый и личный чат не тронуты; повтор — без изменений); e2e: PATCH
  с `active` и `GET ?active=` отвечают 400.
