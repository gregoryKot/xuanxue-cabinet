# 0195. Группа — единственный рычаг рассылки

Дата: 2026-11-04. Статус: принято. **Уточнено [ADR-0196](0196-class-many-groups.md)**:
одна группа у занятия и канала стала несколькими, а состояние «Все группы» ушло; рычаг
рассылки — группа, маршрут по группам и красные подсказки остаются. Заменяет «несколько групп у занятия» из
[ADR-0193](0193-school-groups.md) и галочки «занятие ↔ канал» из
([ADR-0108](0108-channel-takes-broadcasts-by-tag.md) →
[ADR-0192](0192-channel-tags-removed.md)); уточняет автоподключение чата в
[ADR-0015](0015-telegram-chats-self-register-as-channels.md).

## Контекст

К 2026-11-04 куда уходит занятие, решали три вещи сразу: список `classes.channelIds`
(галочки на странице занятия и на странице канала, #622/#627), `groupIds[]` у занятия
(несколько групп, ADR-0193) и автоподключение: бот при добавлении в чат сам отмечал
канал у всех активных занятий (ADR-0015). Владелец 2026-11-04: «Каждое занятие можно
прикрепить к одной группе (начинающие, продолжающие, средние … — список школы).
Отправляется занятие или нет, зависит только от того, для какой группы оно. Каждый канал
(Telegram-группа и т. п.) получает занятия одной группы. Других рычагов нет.» Потом
добавил: занятие может быть и «для всех групп» (пятничное). Слово «курс» из продукта
уходит.

## Решение

Рычаг один — группа. У занятия `groupId` (одна группа или нет) и `forAllGroups`
(для всех групп; тогда `groupId` не хранится). У канала школы `groupId` (одна группа или
нет). Ссылка и запись занятия уходят в каналы, которые:

- активны и не личные чаты учеников (`broadcastEligible` не `false`);
- у занятия группы — имеют **ту же** группу;
- у занятия «для всех групп» — имеют **любую** группу.

Занятие без группы и без «для всех» никуда не уходит. Группа без канала — тоже. Канал без
группы ничего не получает. Каждый такой случай экран говорит красным: строка под занятием
в расписании («Без группы — никуда не уходит», «У группы «Начинающие» нет канала — никуда
не уходит», «Ни у одного канала нет группы — никуда не уходит»), строка под каналом
(«Группа не выбрана — посты сюда не уходят»). Рассылка, у которой не нашлось каналов,
отменяется с причиной «у занятия нет группы» или «у группы занятия нет канала», учитель
получает сообщение в Telegram; «Отправить сейчас» отвечает тем же текстом.

`classes.channelIds` убирается из схемы, DTO и форм: страница занятия больше не
перечисляет каналы, страница канала — занятия. `upsertTelegramChat` создаёт канал без
группы и занятий к нему не подключает. `groupLabel` теперь название группы занятия
(«все группы» у занятия для всех).

Группу нельзя удалить, пока она выбрана у занятия или канала (409, где именно). У
`GroupDto` появился `channelCount`; число занятий группы не включает занятия «для всех».
Занятие «для всех групп» входит в счёт занятий канала на карточке канала — оно уходит
в каждый канал с группой.

Ручные рассылки («Новая рассылка») остаются отдельным делом: учитель пишет объявление и
сам выбирает каналы — `broadcasts.channelIds` не трогается.

Вкладка со старой сборкой, приславшая `groupIds` или `channelIds`, получает 400
(`forbidNonWhitelisted`) и просьбу перезагрузиться ([ADR-0101](0101-server-names-its-build-in-a-header.md)).

## Миграция `0029-group-routing`

1. Канал школы (не личный чат), у которого ещё нет поля `groupId`: берутся занятия, где
   он отмечен в `channelIds`, у которых ровно одна группа. Если их группа одна — она
   становится группой канала; нет таких занятий или групп несколько — группы нет, канал
   идёт в отчёт (id и название).
2. Занятие: одна группа → `groupId` и подпись-название; две и больше → `forAllGroups`
   (так записано пятничное «все группы»), подпись «все группы»; ни одной → без группы.
   `groupIds` снимается. Занятие, у которого уже есть `groupId` или `forAllGroups`,
   пропускается.
3. Каналы идут первыми, потому что их правило читает `groupIds`, а правило занятий их
   снимает. `classes.channelIds` **не снимается**: на время выката старый инстанс ещё
   читает его, новая схема поле не знает и игнорирует. Снять отдельной миграцией —
   после выката.

Отчёт: число переведённых занятий и каналы без группы. Занятия, отмеченные у канала с
несколькими группами, при переводе остаются без рассылки, пока владелец не выберет группу
канала: тихо угадывать нельзя.

## Альтернативы

- **Оставить и галочки, и группы.** Два рычага: занятие отмечено у канала, но группа не та
  (или наоборот) — «почему не ушло» без ответа. Это и есть боль.
- **Несколько групп у занятия.** «Для всех» тогда три отметки; и канал с одной группой
  получал бы занятие, у которого эта группа одна из трёх, — смысл «получает занятия одной
  группы» размывается. «Для всех групп» — явное третье состояние.
- **Канал на несколько групп.** Владелец сказал: одна. Нужен второй канал — заводится
  второй.

## Последствия

- Известное ограничение: занятие, которое должно идти ровно двум из трёх групп, либо
  дублируется по группам, либо выбирает «Все группы» (уйдёт и третьей) — решает владелец.
- Занятие «для всех групп» с каналом, у которого группы нет, в этот канал не уйдёт:
  решает группа канала, а не «подходит всем».
- Переименование группы переписывает подпись занятий этой группы; занятия «для всех»
  не затрагиваются.
- Гейты: `broadcast-channels.queries.spec.ts` (отбор каналов по группе, «для всех», личный
  чат, выключенный), планировщик, «Отправить сейчас» и рассылка записи на реальной Mongo,
  `groups.service.spec.ts` (счёт и запрет удаления), spec миграции 0029, e2e
  `classes`/`channels`/`groups`, vitest форм занятия и канала, строки расписания и
  карточки канала.
