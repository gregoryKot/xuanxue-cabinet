# 0143. PostHog — записи сессий в кабинете, всё скрыто маской

Дата: 2026-09-28. Статус: принято.

## Контекст

Кабинет маленький: воронки и когорты на таком объёме людей ничего не покажут,
но совсем не видно, где человек в интерфейсе спотыкается — на какой кнопке
завис, куда не долистал, где бросил форму. Учителю и админу это только
рассказывают ученики сами, когда решат написать. Заодно нужен фундамент под
будущие фиче-флаги (постепенное включение рискованной фичи, CLAUDE.md
«Деплой») — без него каждая новая версия PostHog для этого заводилась бы с
нуля. Персональных данных ученика и так минимум (CLAUDE.md «Продукт»), и
второй источник утечки заводить нельзя.

## Решение

PostHog, облако ЕС (`eu.i.posthog.com`) — записи сессий, просмотры экранов и
autocapture кликов, только для вошедших (`useAuth().status === 'ok'`).
Инициализация — динамическим импортом из `useAnalytics.ts`, только если
`GET /analytics/config` вернул ключ (`POSTHOG_KEY` задан в Railway). Весь
текст и ввод маскируются (`mask_all_text`, `session_recording.maskAllInputs`,
`maskTextSelector: '*'`), картинки/видео/iframe не записываются вовсе
(`blockSelector`), URL-поля событий проходят через `before_send`
(`sanitizeEvent`, `web/src/analytics/analyticsPrivacy.ts`) — сырой путь
заменяется шаблоном маршрута (`/exams/:examId`), чужой referrer — только
origin. Identify — только id и роль(и)/статус, без имени, email, telegram.
Без прокси: браузер шлёт события прямо на `POSTHOG_HOST`, этот хост — в
`connectSrc` CSP; скрипты PostHog с чужого домена не грузятся
(`disable_external_dependency_loading: true`), recorder бандлится импортом
`posthog-js/dist/recorder`, `scriptSrc` остаётся `'self'`. Ошибки браузера
PostHog'ом не ловим (`capture_exceptions: false`) — уже есть свой механизм
(ADR-0071); вторая реализация запрещена правилом «одна механика — один
компонент». Бот аналитикой не покрыт — отдельное решение по запросу, если
понадобится.

## Альтернативы

- Прокси через `/api/analytics` — отвергли: пришлось бы открыть публичный
  маршрут без CSRF и без сессии (события анонимного посетителя тоже не
  редкость), и вся нагрузка записи сессий легла бы на единственный инстанс
  Railway (CLAUDE.md «Один сервис»). Взамен — риск, что часть браузеров с
  блокировщиками рекламы не отправит события вовсе; приемлемо для аналитики
  из категории «полезно, не критично».
- Свой сбор событий и хранилище — дорого для объёма кабинета, дублирует
  готовый продукт без выгоды.
- Session replay в Sentry (или другом APM) — завёл бы второй источник
  «ошибка + контекст», расходящийся с ADR-0071 (`AppErrorsModule`).

## Последствия

Третьей стороне (PostHog, EU) уезжают: `userId` (id аккаунта, не имя),
роль(и) и статус, шаблоны путей вместо сырых адресов, маскированная запись
кликов, скролла и переходов между экранами. Не уезжают: имя, email,
telegram, содержимое полей ввода, содержимое экрана (весь текст и элементы
замаскированы), скриншоты оплат и видео ответов (не записываются). Выключить
— убрать `POSTHOG_KEY` из Railway и передеплоить: кабинет поднимается как
прежде, фронт даже не пытается импортировать `posthog-js` (env.validation.ts,
useAnalytics.ts). Гейты: `check-env-example.mjs` (переменная описана),
`csp.spec.ts` (единственный сторонний `connectSrc`), тесты
`analyticsPrivacy.test.ts`/`posthogOptions.test.ts`/`useAnalytics.test.tsx`.
