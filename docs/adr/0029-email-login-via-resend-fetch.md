# 0029. Вход по email-ссылке: Resend через fetch, без SDK

Дата: 2026-09-15. Статус: принято. Реализует путь «Email-ссылка» из ADR-0005.

## Контекст

ADR-0005 назвал email-ссылку основным путём входа для учеников без Telegram и
для админа. Нужен провайдер писем (домен `xuanxue.su`, PLAN §1) и правила
одноразового токена (SECURITY §2). Отправки писем в проекте раньше не было.

## Решение

Resend HTTP API напрямую через встроенный `fetch` (`api/src/mail/`), без
`resend`-SDK: один вызов `POST https://api.resend.com/emails` с
`Authorization: Bearer <key>` и JSON-телом — SDK ради одного эндпоинта
противоречит правилу «предпочитаем встроенное» (CLAUDE.md «Зависимости»).
`AbortSignal.timeout` обязателен (SECURITY §8). Email-вход выключается
отсутствием `RESEND_API_KEY`/`MAIL_FROM`/`PUBLIC_URL` — ни один не обязателен
в production, Telegram работает без них.

Токен: `randomBytes(32).toString('hex')`, в базе (`email_login_tokens`) —
только `sha256(token)`, TTL 15 минут (TTL-индекс на `expiresAt`).
Потребление — `POST /auth/email/verify` со страницы, не GET по самой ссылке:
сканеры почтовых клиентов открывают ссылки из писем сами и молча сожгли бы
одноразовый токен раньше пользователя. Анти-спам — не больше одного письма
на адрес в 2 минуты (`EMAIL_LOGIN_RESEND_COOLDOWN_MIN`), поверх общего
троттлинга по IP. Ответ на `POST /auth/email/request` — всегда `204`,
известен email или нет: раскрывать список зарегистрированных email через код
ответа нельзя (SECURITY §2).

## Альтернативы

- SDK `resend` — типизированный клиент вокруг одного HTTP-вызова; лишняя
  зависимость (CLAUDE.md «Зависимости»: предпочитаем `fetch`, когда разница —
  один запрос).
- Потребление токена самим переходом по ссылке (`GET`) — стандартно для
  «magic link», но сканер антивируса/почтового клиента открывает ссылки из
  письма превентивно и сжигает токен до пользователя; POST с отдельной
  кнопки на странице этого не ловит.
- Троттлинг только по IP — не защищает конкретный адрес от разных IP;
  cooldown на email нужен отдельно.

## Последствия

- Нужен от владельца школы: домен для писем и настроенные SPF/DKIM/DMARC в
  Resend — без них письма уходят в спам или не проходят DMARC-проверку
  получателя (RUNBOOK §5, «Email-вход: как подключить»).
- `email_login_tokens` — не в `USER_OWNED_COLLECTIONS`: ключ документа —
  email, не `userId`, срок жизни — 15 минут, решение зафиксировано в
  комментарии схемы (`email-login-token.schema.ts`).
- Этот PR — только API; экран входа на почту во фронтенде — следующий PR
  (PLAN.md §6).
- Гейты: `mail.service.spec.ts` (мок `fetch`), `email-login-token.service.spec.ts`
  (mongodb-memory-server — TTL, одноразовость, cooldown), `email-auth.service.spec.ts`,
  `auth-email.e2e-spec.ts` + `auth-email-resend.e2e-spec.ts`.
