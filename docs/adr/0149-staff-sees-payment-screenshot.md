# 0149. Штат открывает снимок перевода, загруженный в кабинете

Дата: 2026-09-29. Статус: принято. Дополняет [ADR-0050](0050-payment-screenshot-via-bot.md)
и [ADR-0049](0049-payment-month-and-statuses.md).

## Контекст

По ADR-0050 снимок перевода приходит двумя путями. Ученик со связанным Telegram
шлёт фото боту: у нас только `file_id`, а копию бот уже переслал бухгалтеру.
Ученик без Telegram грузит файл в кабинете: байты лежат у нас, зашифрованные, в
`payment_screenshots`. Но экран «Оплаты» знал лишь `hasScreenshot: true`, и Маша
не могла открыть загруженный снимок, не выходя из кабинета.

## Решение

Снимок из кабинета штат открывает по `GET /api/payments/:userId/:month/screenshot`.
Доступ тот же, что у всего `/payments`: бухгалтер и админ, учитель и помощник —
403 (ADR-0049). Сервис находит оплату по `(userId, month)`, берёт байты по
`screenshotImageId` и расшифровывает на лету. Ответ с `Cache-Control: private,
no-store`: снимок заменяется новым по тому же адресу, его убирает уборщик, а на
нём реквизиты.

Снимок бота не проксируем: ADR-0050 решил, что байты бота через нас не идут
(`getFile` не зовётся). Маршрут отвечает 404 с текстом, где снимок лежит.
Поэтому в `PaymentDto` поле `hasScreenshot` заменено на `screenshotKind`
(`telegram` | `upload`): экран честно говорит, где снимок, и показывает кнопку
только там, где байты есть. `MyPaymentDto` не меняется: ученику вид снимка не нужен.

## Альтернативы

- Проксировать `getFile` Telegram: исходящий вызов на каждое открытие, токен бота
  в пути и отказ от ADR-0050 без новой причины.
- Хранить у себя копию байтов бота: вдвое больше персональных данных и уборки.
- Отдавать base64 в JSON списка: список тяжелеет на каждый снимок.

## Последствия

- Есть повод для вопроса на ревью: новый ответ с байтами снимка обязан быть
  `no-store` и только для `accountant`/`admin`.
- Гейты: e2e `payment-screenshot-staff.e2e-spec.ts` (401/403, байты байт в байт,
  `no-store`, в списке нет байтов и id), `check-ownership-e2e.mjs`.
- Экран «Оплаты» переходит с `hasScreenshot` на `screenshotKind` отдельным PR.
