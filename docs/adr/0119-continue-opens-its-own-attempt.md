# 0119. «Продолжить» открывает попытку по id, список правится ответом записи

Дата: 2026-09-22. Статус: принято.

## Контекст

Подтверждённый владельцем баг, воспроизводится руками: ученик отправляет
работу (попытка становится `submitted`), возвращается на «Задания» без
перезагрузки страницы, видит «Продолжить» и жмёт её. Кнопка звала
`startAttempt` → `POST /exams/:id/attempts`. Сервер (`ExamAttemptsService.start`,
exam-attempts.service.ts) незакрытой попытки не находит и заводит новую,
пустую — ответы «обнуляются», а попытка молча сгорает из лимита.

Механизм провала — два независимых факта, сложенных вместе:

1. Список `/me/exams` общий на всё приложение (`MyExamsProvider.tsx`,
   ADR-0063) и грузится один раз — после отправки попытки он не перечитывался
   (второй `GET` того же списка запрещён ADR-0087, а точечной правки ответом
   записи для этого случая не было). Карточка ещё держала
   `lastAttempt.status: 'in_progress'`.
2. `POST /exams/:id/attempts` идемпотентен только для `in_progress`-попытки
   (тот же запрос второй раз отдаёт её же). Для уже отправленной — это не
   повтор того же действия, а «начать заново»: сервер не может отличить одно
   от другого, у него нет понятия «устаревший клик». Комментарий у
   `startAttempt` в `MyExamsProvider.tsx` называл POST идемпотентным без этой
   оговорки — что и усыпило бдительность при первой реализации.

## Решение

Два независимых замка, нужны оба:

**Замок 1.** `getMyExamAction(exam) === 'continue'` значит, что попытка уже
есть и её `id` известен из самого списка (`exam.lastAttempt.id`) — кнопка
«Продолжить» ведёт на `/attempts/<id>` напрямую, без единого запроса
(`resolveTaskStartTarget.ts`, чистая функция, вызывается из
`useTaskStart.ts`). `POST /exams/:id/attempts` остаётся только у «Начать» и
«Пройти ещё раз» — там новая попытка действительно нужна. Худшее, что теперь
может сделать устаревший клик по «Продолжить», — открыть экран уже
отправленной попытки («Отправлено, ждём проверки»), а не сжечь попытку
впустую.

**Замок 2.** Список чинится из ответа самой записи, без перезагрузки
страницы и без второго `GET` (ADR-0087). `MyExamsProvider` отдаёт
`applyAttempt(attempt: ExamAttemptDto)` — патчит `lastAttempt` (`id`,
`status`, `expired`) нужного экзамена по `attempt.examId`, а если пришёл id,
которого в `lastAttempt` ещё не было, увеличивает `attemptsUsed` на 1
(`applyExamAttempt.ts`, чистая функция). Зовётся в двух местах: после
успешного `startAttempt` («Начать»/«Пройти ещё раз» — счётчик использованных
попыток растёт сразу) и после успешной отправки (`useAttempt.ts`, `submit()`
— тем же ответом `POST /attempts/:id/submit`, что уже правит список самой
попытки, ADR-0094). Экран сдачи получает функцию из
`useMyExamsApplyAttempt()` — обёртки над контекстом, которая тихо ничего не
делает, если провайдера нет (изолированный тест самого экрана,
`AttemptScreen.test.tsx`); в проде провайдер есть всегда — `AttemptScreen`
смонтирован внутри `MyExamsProvider` (`AppShell.tsx` → `cabinetRoutes.tsx`).

## Альтернативы

- **Перечитывать `/me/exams` после каждой отправки/старта.** Запрещено
  ADR-0087 и создаёт лишний запрос там, где ответ самой записи уже несёт всё
  нужное; замок 1 при этом всё равно был бы обязателен — устаревшая карточка
  успевает существовать между отправкой и перечитыванием.
- **Разрешать серверу отличать «повтор» от «начать заново».** Сервер видит
  только запрос POST без контекста клика — «устаревший клик по уже показанной
  кнопке» и «честное пожелание начать заново после отправки» неразличимы на
  его стороне. Различие видно только клиенту, у которого есть история одного
  экрана; туда замок и поставлен.
- **Второй источник данных (свой fetch попытки на экране сдачи).** Список
  экзаменов остаётся один (ADR-0063) — новая копия состояния воспроизвела бы
  ровно ту находку, из-за которой список стал общим.

## Последствия

- `startAttempt` вызывается только при «Начать»/«Пройти ещё раз» — его
  комментарий про идемпотентность переписан с явной оговоркой про
  `in_progress`.
- Тест на сам баг (регрессия): отправили попытку → карточка на «Заданиях»
  без перезагрузки перестаёт предлагать «Продолжить» и показывает
  «Отправлено, ждём проверки», без второго `GET /me/exams`
  (`TasksScreen.test.tsx`).
- Тест на замок 1: «Продолжить» не шлёт `POST`, ведёт на `/attempts/<id>`;
  «Начать» и «Пройти ещё раз» по-прежнему шлют (`TasksScreen.test.tsx`).
- Тест на замок 2: `applyAttempt` для новой попытки увеличивает
  `attemptsUsed` (`MyExamsProvider.test.tsx`), сама правка списка — чистыми
  тестами без DOM и сети (`applyExamAttempt.test.ts`).
- Гейт `check-write-then-reload.mjs` по-прежнему держит инвариант: новых мест
  «мутация + `reload()`» не появилось — правка идёт через `applyAttempt`.
