# 0144. Выкат на прод — только по команде владельца

Дата: 2026-09-28. Статус: принято. Частично заменяет ADR-0142 (ночной выкат
отменён; стейджинг из `main` и промоут через `release.yml` остаются).

## Контекст

ADR-0142 завёл ночной cron: раз в сутки `release.yml` сам подбирал
отстоявшийся зелёный коммит `main` и катил его на прод. Владелец решил, что
прод — с реальными данными учеников — не должен обновляться сам, пока он не
скомандовал явно: он хочет решать момент выката, даже если кандидат готов и
здоров. Требование прежним: кодить часто, тестировать на стейджинге до
прода, откатываться легко.

## Решение

Из `release.yml` убран триггер `schedule`, остаётся только
`workflow_dispatch`. Промоут (`mode: promote`) запускает владелец руками:
без `sha` — тот же выбор кандидата, что был у ночной джобы (самый новый
зелёный коммит `main`, отстоявший `SOAK_HOURS` на здоровом стейджинге); с
`sha` — конкретный коммит без выдержки, для срочного фикса. Откат
(`mode: rollback`) не меняется. Issue `release-hold` остаётся защитой после
отката: пока он открыт, промоут отказывает с этой причиной.

## Альтернативы

- Оставить cron, но с ручным подтверждением перед push — лишний механизм
  поверх того, что `workflow_dispatch` уже даёт бесплатно.
- Убрать `release.yml` совсем, катить прод вручную `git push` — теряем
  бэкап-перед-промоутом, выбор кандидата и алерт в Telegram; ровно то, что
  `release.yml` даёт поверх голого пуша.

## Последствия

- Прод может отставать от `main` сколько угодно — до тех пор, пока владелец
  не запустит `release.yml` с `mode=promote`. Это ожидаемо, не инцидент.
- Бэкап перед каждым промоутом остаётся: джоба `backup` в `release.yml`
  выполняется независимо от того, что запустило `promote`.
- Суточный `backup.yml` по расписанию остаётся — он не зависит от промоутов
  и защищает данные даже в паузы между выкатами.
- `scripts/release-pick.mjs` больше не проверяет `EVENT_NAME === 'schedule'`
  (ветка удалена вместе с веткой workflow, которая её вызывала).
- Гейт: тесты `release-candidate.test.mjs` (выбор кандидата не изменился),
  `docs/RUNBOOK.md` §2 описывает выкат командой, а не расписанием.
