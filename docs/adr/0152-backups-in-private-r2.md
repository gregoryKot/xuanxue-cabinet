# 0152. Бэкапы Mongo — в приватный R2 (EU), не в артефакты публичного репозитория

Дата: 2026-09-29. Статус: принято. Заменяет способ хранения из
[ADR-0017](0017-mongo-backups.md) (артефакты Actions); шифрование, скрипты и
проверка восстановления из него остаются.

## Контекст

ADR-0017 (2026-09-07) отправил зашифрованный дамп в артефакт Actions на 90 дней. Довод
против незашифрованного дампа там был такой: «артефакты видны всем с доступом на
чтение репозитория». Репозиторий тогда был приватным. 2026-09-12 владелец сделал его
публичным, потому что минуты Actions на приватном кончились (ADR-0019, дополнение).
Допущение ADR-0017 сломалось молча: workflow не менялся, и ни один гейт не смотрит на
видимость репозитория. С тех пор каждый ночной дамп — артефакт, который скачает любой,
кто вошёл в GitHub. В дампе имена, почта, Telegram id и статусы оплат учеников.

Шифрование (AES-256-CBC + PBKDF2, пароль — 32 случайных байта, RUNBOOK §7.1) перебором
не вскрывается. Риск в другом: одна утечка `BACKUP_PASSPHRASE` (лог, менеджер паролей,
чужой ноутбук) разом раскрывает все копии за 90 дней, а уже скачанные файлы отозвать
нельзя. Кроме того, GitHub становится необъявленным обработчиком персональных данных.

Правила защиты приватности (безопасность информации) 2017 года, п. 15, требуют договор
с каждым внешним обработчиком. Правила о передаче данных за границу (2001), п. 2(8),
отдают предпочтение странам ЕС. Cloudflare R2 в аккаунте школы уже есть (ADR-0057,
материалы), у него есть EU-юрисдикция.

## Решение

**Бэкапы лежат в приватном бакете Cloudflare R2 с юрисдикцией EU** (адрес
`https://<account>.eu.r2.cloudflarestorage.com`). `backup.yml` после `backup-mongo.sh`
кладёт файл `aws s3 cp` (AWS CLI уже есть на раннере) под ключ
`mongo/backup-<UTC-метка>.archive.gz.enc`. Бакет и токен — **отдельные** от бакета
материалов: токен даёт Object Read & Write только на этот бакет, поэтому утечка ключа
бэкапов не открывает файлы учеников, а утечка ключа приложения — дампы. Четыре секрета
(`BACKUP_R2_ENDPOINT`, `BACKUP_R2_BUCKET`, `BACKUP_R2_ACCESS_KEY_ID`,
`BACKUP_R2_SECRET_ACCESS_KEY`) живут в GitHub Actions, не в env приложения, как
`BACKUP_PASSPHRASE`. Срок 90 дней держит правило жизненного цикла бакета, кода
удаления нет.

**Переходный запасной путь.** Пока любой из четырёх секретов пуст, ночные бэкапы не
должны прекращаться: файл уходит в артефакт, как раньше, но громко. В прогоне жёлтая
аннотация, в Telegram-чат алертов каждую ночь сообщение с перечнем недостающих секретов
и ссылкой на RUNBOOK §7.1. Когда секреты заданы, артефакт не создаётся вовсе. Выбор
делает `scripts/backup-destination.mjs`, а не шелл в YAML. Упала загрузка в R2 при
заданных секретах — упал весь прогон и пришёл алерт; молча откатываться в публичный
артефакт нельзя.

## Альтернативы

- **Сделать репозиторий приватным.** Из-за платных минут Actions он и стал публичным
  (ADR-0019). Возврат — постоянный платёж ради одного файла в сутки.
- **Оставить артефакты.** Отклонено: сильный пароль публичность файла не отменяет, а
  необъявленный обработчик остаётся.
- **AWS S3.** Новый вендор, новый аккаунт и карта при том, что R2 уже подключён и
  умеет EU-юрисдикцию; за исходящий трафик при восстановлении S3 берёт плату.
- **Приватный репозиторий GitHub для дампов.** История git вечна: удалить старый дамп
  можно только переписав историю; у репозитория и файла есть лимиты размера; срок
  90 дней там не выразить.
- **Тот же бакет и токен, что у материалов.** Проще на один шаг настройки, но ключ,
  который приложение держит в Railway, тогда читал бы все дампы.
- **Удаление старых файлов кодом в workflow** (`aws s3 rm` по возрасту). Токену пришлось
  бы иметь право удаления в скрипте, который мы можем сломать; правило бакета проще и
  работает, даже когда Actions лежит.

## Последствия

- Владельцу нужна разовая настройка: бакет EU, правило удаления через 90 дней, токен на
  один бакет, четыре секрета, затем удаление старых `mongo-backup-*` (RUNBOOK §7.1).
  Договор с Cloudflare как обработчиком заключает владелец школы (SECURITY §5).
- Запасной путь — переходный. После того как владелец подтвердил первый зелёный прогон
  с R2, отдельный PR делает секреты `required: true` и удаляет артефактную ветку, шаг
  напоминания и его тексты (CLAUDE.md §6: отказались от механики — удаляем с концами).
- Ключ R2 умеет и стирать: злоумышленник с ним может удалить накопленные копии.
  Запрет удаления средствами бакета не включаем; ночной прогон создаёт свежую копию,
  и окно потери — сутки. Пересмотреть при первом признаке чужой активности в бакете.
- Что держит решение. `scripts/backup-destination.test.mjs` (входит в
  `node --test scripts/*.test.mjs`, джоба `checks`): решение по четырём секретам,
  тексты напоминания, доходят ли секреты до шагов `backup.yml`, артефакт создаётся
  только при `target=artifact`, R2 — только при `target=r2`, и артефакты в репозитории
  публикуют лишь `ci.yml` (покрытие) и этот запасной путь.
- Чего гейт не видит: правило жизненного цикла и права токена живут в Cloudflare, не
  в репозитории. Их держит квартальная проверка (RUNBOOK §7.3: самому старому файлу в
  бакете не больше 91 дня) и строка в SECURITY §9 на случай утечки ключа.
- Восстановление то же (`restore-mongo.sh`), файл скачивается из R2 через `aws s3 cp`
  с `--endpoint-url` (RUNBOOK §7.1).
