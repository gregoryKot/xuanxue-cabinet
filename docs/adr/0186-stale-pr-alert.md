# 0186. Забытые PR ловит плановый прогон и алерт в Telegram

Дата: 2026-10-25. Статус: принято.

## Контекст

Правило 1а (агент доводит PR до зелёного и мержит сам) и абзац «Зависимости» (PR
Dependabot не висит дольше недели) не имели механизма принуждения. PR висели
неделями: #310 с 2026-09-21 (черновик), #417 с 09-26, #557–#559 с 10-03. Пока
владелец не заглянет в список PR, никто не видит, что что-то забыто: красного CI у
забытого PR нет, он просто стоит.

## Решение

Workflow `.github/workflows/stale-prs.yml` раз в сутки запускает
`scripts/check-stale-prs.mjs`: открытый PR старше 7 дней (черновики тоже) — прогон
красный, список PR с возрастом, автором и ссылкой уходит в Telegram тем же каналом,
что алерты `uptime.yml` и `backup.yml` (`scripts/notify-telegram.mjs`, RUNBOOK §10.2).
Если `gh` не ответил или список обрезан лимитом, прогон тоже красный: молчаливый
«всё в порядке» хуже любого шума. Закрывает или мержит PR человек или агент,
скрипт ничего не трогает.

## Альтернативы

- **Action `stale` (stale-bot).** Закрывает PR автоматически, а закрытие требует
  причины от того, кто понимает, что в PR. Нужно напоминание, не уборка.
- **Обязательная проверка в `ci.yml`.** Покраснел бы каждый новый PR из-за старых
  чужих, а забытые старые она не трогает: проверка бежит по событию нового PR, а не по времени.
- **Issue в GitHub вместо Telegram.** Владелец уже читает алерты uptime и backup в
  Telegram; issue — ещё один ящик, который тоже можно не открывать.

## Последствия

Пока висит хотя бы один PR старше недели, алерт приходит каждый день: это намеренно,
молчание отключало бы напоминание. Снимается мержем или закрытием с причиной.
Порог — константа `DEFAULT_MAX_AGE_DAYS` в скрипте. Гейт: `stale-prs.yml`, ядро
покрыто `scripts/check-stale-prs.test.mjs` (граница ровно 7 суток, черновики,
порядок). Бюджет Actions — один короткий прогон в день (ADR-0111).
