# 0027. Личный канал ученика — не канал школы

Дата: 2026-09-15. Статус: принято. Дополняет ADR-0015, ADR-0026.

## Контекст

Аудит 2026-09-15, блокер: `/start` (ADR-0015) заводил личный чат-канал только для
`isStaffRole(user.roles)`. Ученику бот отвечал отказом «этот бот для учителя», его
личный канал не создавался нигде — `PersonalChats.chatFor(userId, kind)` (слой 4.7,
PLAN.md §11) для ученика всегда отдавал `null`, и `TelegramExamNotifier.notifyExamGraded`
тихо выходил: результат экзамена не мог дойти ни одному ученику ни при каких условиях, и
ни строки в логе — `telegram-exam-notifier.spec.ts` этого не ловил, потому что заводил
канал напрямую в Mongo, а не через `/start`.

Наивный фикс — звать тот же `ChannelConfigService.upsertTelegramChat`, что и для
штата, — создал бы вторую, худшую дыру: этот метод подключает новый канал ко всем
активным классам (`$addToSet`, ADR-0015 — «бот, в который по времени приходит всё
расписание») и делает канал видимым на экране «Каналы» (`ChannelsService.list`) и в
`ClassesService.defaultTelegramChannelIds` (новый класс подхватывает все активные
Telegram-каналы). Личный чат ученика после `/start` стал бы получателем рассылки
ссылок Zoom всех занятий школы, и учитель увидел бы в «Каналах» личные чаты чужих
учеников — прямая утечка данных школы конкретному человеку, а не наоборот.

## Решение

`ChannelRecord` получает `broadcastEligible: boolean` (default `true`). Личный канал
ученика создаётся отдельным методом `ChannelConfigService.upsertPersonalTelegramChat`
(общий идемпотентный `findOrReviveChannel`, но БЕЗ подключения к классам) с
`broadcastEligible: false` только при создании. Три места, где канал школы отличается
от личного канала ученика, теперь фильтруют `{ $ne: false }`: `ChannelsService.list`
(экран «Каналы»), `ClassesService.defaultTelegramChannelIds` (подписка нового класса),
`ChannelConfigService.listActiveTelegramChatIds` (проверка членства в группе,
ADR-0026 — на момент этого решения; сам метод и механика, которую он
обслуживал, удалены вместе с автоподтверждением ADR-0036). `PersonalChats.list()`/`listFor()` уже были ограничены штатом школы через
`UsersService.listTeacherContacts()` — от этой дыры они не зависели, менять не пришлось.
`chatFor(userId, kind)` ищет канал только по `(type, target, active)`, флаг ему не
нужен: адресность уже даёт `userId`.

`StartHandler` теперь разбирает доступ единой точкой `BotUserAccessService.resolve()`
(было — `UsersService.findByTelegramId` без проверки статуса, из-за чего заблокированный
или неподтверждённый учитель получал общий отказ «бот для учителя» вместо
`ACCESS_MESSAGE`/`PENDING_APPROVAL_MESSAGE`, аудит 2026-09-15): `active` подключается
(штат — прежним путём и меню, ученик — новым личным каналом и узким меню
`buildStudentMenu`, только кнопка «Экзамены» — «Ближайшие занятия» и «Уведомления»
штата ученику не показываются, CLAUDE.md «Ноль нагрузки на ученика»), `denied` получает
готовый текст, `unknown` — прежний вежливый отказ без канала. Кнопки «Экзамены» и «В
меню» в `CallbackQueryHandler` теперь тоже проверяются через `BotUserAccessService`, а
не только `PersonalChats` (та отвечает «штат ли это», а на эти два экрана штат — не
единственный, кому они открыты) — та же причина, по которой кнопки экзамена уже были
исключением из этой проверки.

## Альтернативы

- **Отдельная коллекция для личных каналов.** Отклонено: `chatFor`/раннер доставок уже
  читают `channels` по `(type, target)`, вторая коллекция удвоила бы модель ради одного
  булева поля.
- **`broadcastEligible` как enum `channelKind: 'school' | 'personal'`.** Тот же смысл,
  но проект не использует `enum`/готовые перечисления там, где хватает булева поля
  (CLAUDE.md «Код»), а инверсия по умолчанию (`true`) не требует миграции старых
  документов.
- **Полное меню штата ученику, но с проверкой роли внутри каждого экрана.** Отклонено:
  «Ближайшие занятия» показывает Zoom-ссылки и пароли ВСЕХ занятий школы, а привязки
  ученика к своим занятиям ещё нет (PLAN.md §11 слой 4.1) — рано показывать это как
  «своё расписание».

## Последствия

Обязательно: новый способ создать `channels`-документ для одного человека обязан
проходить через `upsertPersonalTelegramChat` (или задавать `broadcastEligible: false`
явно), иначе он утечёт в рассылки и на «Каналы». Любой новый источник списка
Telegram-каналов школы (`type: 'telegram', active: true`) обязан добавить тот же
фильтр — иначе фикс придётся находить заново.

Гейты: `channel-config.service.spec.ts` (не подключает классы, флаг выставлен),
`channels.service.spec.ts`/`classes.service.spec.ts` (личный канал не виден),
`start.handler.spec.ts` (denied/unknown/active веток), `callback-query.handler.menu.spec.ts`
(menu:exams/menu:back ученику), `start-then-exam-graded.spec.ts` — сквозной тест
именно того пути, которого не было: `/start` → `notifyExamGraded` → сообщение дошло.
