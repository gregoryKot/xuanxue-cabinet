# 0015. Каналы Telegram регистрирует бот, не админ

Дата: 2026-09-07. Статус: принято.

## Контекст

Ожидание владельца (06.09.2026): «первый шаг — бот, в который по времени приходит всё
расписание, и который при добавлении в группу начинает слать туда по тому же
расписанию». Ноль настройки руками: чат, где есть бот, сам становится каналом — без
экрана «Каналы» и без ручного ввода `chatId`.

`ChannelConfigService.upsertTelegramChat` (PR F) уже умеет идемпотентно
создавать/находить Telegram-канал по `chatId`. Не хватало входа со стороны Telegram:
вебхука и реакции на события бота.

## Решение

`POST /api/telegram/webhook` принимает апдейты Telegraf, проверенные заголовком
`x-telegram-bot-api-secret-token` (`TelegramWebhookGuard`, `timingSafeEqual` — SECURITY
§2); гвард требует и `TELEGRAM_WEBHOOK_SECRET`, и `BOT_TOKEN` — без токена бот всё равно
не смог бы ответить, поэтому оба отсутствия дают одинаковый 503, не только секрет.

`my_chat_member` реагирует на ПЕРЕХОД статуса бота, не на голое значение
`new_chat_member.status`: `old_chat_member.status ∈ {left, kicked}` (бота не было в
чате) → `new ∈ {member, administrator}` (появился) — это и есть «бота добавили»,
вызывает `upsertTelegramChat({ chatId, title })`; `new ∈ {left, kicked}` — «бота
убрали», канал выключается (`active: false`), документ не удаляется — на него
ссылается журнал доставок. Прочие переходы (`member` ↔ `administrator` — повышение или
понижение прав без выхода из чата) не про членство в канале и игнорируются: апдейт
`my_chat_member` Telegram шлёт при любом изменении прав, не только при
входе/выходе. `upsertTelegramChat` подключает канал ко всем активным классам
(`classes.channelIds` += `channelId`, `$addToSet`, идемпотентно) ТОЛЬКО при создании
нового документа — учитель мог руками отключить лишние классы от существующего чата в
кабинете (позже), и повторное добавление бота в тот же чат (после кика) такое решение
не отменяет: E11000 на повторной вставке «оживляет» канал (`active: true`, обновлённый
`title`, обрезанный до `CHANNEL_LIMITS.title`), но classModel не трогает.

`/start` от пользователя с ролью `teacher`/`admin` (по `telegramId` в `users`) —
тот же `upsertTelegramChat` с `chatId = from.id`: личный чат с ботом становится каналом,
и учитель получает всё расписание себе в личку без единой настройки. `/start` от
незнакомого Telegram ID — вежливый отказ по VOICE, без создания канала.

Вебхук регистрируется (`setWebhook`) при старте приложения только если заданы
`BOT_TOKEN`, `PUBLIC_URL`, `TELEGRAM_WEBHOOK_SECRET` и `NODE_ENV=production` — иначе
`warn` в лог, без падения приложения. Без `TELEGRAM_WEBHOOK_SECRET` или `BOT_TOKEN` в
env вебхук отвечает 503 (`NotAvailableError`) — бот выключен целиком, тот же приём, что
у входа через Telegram без `BOT_TOKEN`. Прогрев `botInfo` и `setWebhook` при старте —
fire-and-forget (не блокируют старт остального приложения), с таймаутом
`AbortSignal.timeout` на каждый сетевой вызов (`TELEGRAM_CALL_TIMEOUT_MS`,
`api/src/channels/telegram-client.ts`) и собственным error-логом на отказ; `getMe` перед
каждым апдейтом переспрашивается заново, если прошлая попытка не удалась — свой
`ensureBotInfo()`, а не ленивый вызов внутри `telegraf` (тот кэширует и отклонённый
промис, см. комментарий в `telegram-bot.service.ts`).

## Альтернативы

- **Учитель вводит `chatId` вручную на экране «Каналы».** Отклонено: владелец прямо
  просил ноль настройки; `chatId` группы не виден в интерфейсе Telegram без сторонних
  ботов-помощников — лишний барьер для нетехнического пользователя.
- **Регистрация только через `/start` в личке, без `my_chat_member`.** Отклонено:
  тогда группа учеников не становится каналом при добавлении бота — придётся отдельно
  писать боту команду из группы, а не просто добавить его.
- **Хранить `chatId` в env или константе кода.** Отклонено: противоречит правилу
  «настройка, которую меняет учитель, живёт в БД, не в env» (CLAUDE.md «Продукт») — а
  каждый новый чат учителя означал бы правку кода и деплой.

## Последствия

- Проще: подключение канала для учителя — одно действие («добавить бота в группу» или
  «/start»), без экрана и без копирования `chatId`.
- Сложнее: канал школы теперь может появиться без действия админа в кабинете — список
  каналов может расти сам по себе; экран отключения лишних классов от чата (упомянут в
  ожидании владельца) — отдельная задача, не в этом PR.
- Обязательно: `TELEGRAM_WEBHOOK_SECRET` — новая секретная переменная (валидатор +
  `.env.example` + RUNBOOK §5), без неё бот не работает вовсе.
- Гейты: `channel-config.service.spec.ts` (подключение ко всем активным классам только
  при создании, без переподключения при повторном добавлении, обрезка title),
  `handlers/*.spec.ts` (переходы my_chat_member, /start только из приватного чата),
  `telegram-bot.service.spec.ts` (retry `ensureBotInfo`, fire-and-forget регистрация),
  `telegram-webhook.e2e-spec.ts` (403 без/с неверным секретом, 503 без
  `TELEGRAM_WEBHOOK_SECRET`, 200 с верным и на минимальных телах апдейта).
