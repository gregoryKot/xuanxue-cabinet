# 0042. `botChatActive` в `MeDto` — «боту есть куда писать», отдельно от `telegramLinked`

Дата: 2026-09-17. Статус: принято. Уточняет ADR-0023 и ADR-0034, поддерживает
ADR-0039.

## Контекст

`TelegramExamNotifier.notifyAttemptSubmitted` шлёт «работу сдали» только тем из
штата, у кого есть **активный личный чат** с ботом
(`PersonalChats.listFor('attempt_submitted')` — запись в `channels` заводит
нажатое в боте «Запустить»). Учителя без такого чата нет в списке: с
2026-09-17 это видно в логе (`warn`), но сам учитель об этом не узнаёт — в
кабинете всё выглядит рабочим, а письмо-резерв (ADR-0039) уходит только тем,
у кого есть подтверждённый email.

В `MeDto` уже есть `telegramLinked`, но он отвечает на другой вопрос — «бот
меня узнает», то есть у аккаунта есть `telegramId` (ADR-0023). Вход через
виджет Telegram ставит `telegramId` сразу, а личный канал не заводит: у самой
частой группы риска — учителей, которые входят через Telegram и никогда не
открывали бота, — `telegramLinked === true` при отсутствующем чате. Подсказка,
построенная на `telegramLinked`, промолчала бы ровно там, где нужна.

## Решение

`MeDto` получает второе, честное поле `botChatActive: boolean` —
`PersonalChats.hasActiveChat` для текущей сессии. Считает его
`AuthController` и отдаёт `toMeDto(user, botChatActive)` во всех трёх ответах
с профилем (`GET /auth/me`, `POST /auth/telegram`, `POST /auth/email/verify`);
двухаргументная сигнатура маппера — и есть гейт: четвёртый ответ с профилем не
соберётся, пока автор не решит, что подставить. Признак считается от уже
прочитанного `AuthGuard` пользователя (`PersonalChats.hasActiveChatFor`) —
второй `findById` был бы тем же чтением дважды.

Первый потребитель — экран «Проверка работ»: учителю и помощнику без чата он
показывает подсказку и `TelegramLinkButton`. Кому вид `attempt_submitted`
не положен по роли (админ, ученик — `DEFAULT_NOTIFICATIONS_BY_ROLE`),
подсказки нет.

## Альтернативы

- **Обойтись `telegramLinked`.** Отклонено: он молчит у вошедших через
  виджет — это и есть основная группа без чата.
- **Отдельный эндпоинт `GET /me/bot-chat`.** Отклонено: лишний запрос на
  экран, и подсказка не гасла бы сама. `TelegramLinkButton` после возврата из
  Telegram перечитывает `/auth/me` (ADR-0034) — на `MeDto` read-after-write
  получается даром.
- **Поле в ответе `GET /me/notifications`.** Отклонено по той же причине:
  профиль сессии живёт в одном месте, и второй источник правды о Telegram
  разъехался бы с первым.
- **Заменить `telegramLinked` на `botChatActive`.** Отклонено: вопросы разные.
  Экрану сдачи важно «бот поймёт, чьё это видео» (ADR-0023), уведомлениям —
  «боту есть куда писать».

## Последствия

`/auth/me` делает один индексный запрос в `channels` сверх прежнего — цена
одного вызова на загрузку приложения, не на каждый запрос API. Поле
обязательное, не опциональное: `tsc` заставляет заполнить его в каждом месте,
где собирается `MeDto`, включая тестовые фикстуры.

Гейты: `user.mapper.spec.ts` (оба признака и полный перечень полей `MeDto`),
`personal-chats.chat-for.spec.ts` (`hasActiveChatFor`),
`auth-bot-chat-active.e2e-spec.ts` (признак честно меняется от записи в
`channels`, без повторного входа),
`showsTelegramHint.test.ts` и `GradingQueueScreen.test.tsx` (кому подсказка
показывается и кому нет).
