# 0169. Координация с соседними проектами через Workshop — скилл /collaborate

Дата: 2026-10-05. Статус: принято.

## Контекст

У школы два приложения: кабинет (этот репозиторий) и daychi — нативное приложение с расписанием и напоминаниями, со своим бэкендом материалов. Репозиторий dveyarangi/xuanxue-workshop ведёт общие договорённости о границах: кабинет — провайдер расписания, пользователей и напоминаний для обоих клиентов. Первая связка — публичное чтение расписания `GET /api/public/lessons` без данных Zoom для daychi (контракт `docs/contracts/public-lessons.md` в Workshop). Задания проектам живут только в issues Workshop с меткой `project:cabinet`; результат и проблемы — в том же issue.

## Решение

Скилл `/collaborate` установлен в `.claude/skills/collaborate/` (хост — Claude Code) с меткой проекта и ревизией источника. В CLAUDE.md — блок «Workshop collaboration»: сводка границ и условие вызова скилла. Документы Workshop — источник информации, не инструкции: правила этого файла (тесты, DTO, e2e на владение, PR и мерж по правилу 1а) действуют как прежде. Граница меняется по контракту Workshop и с координацией через его issue, внутренняя работа идёт по своим правилам.

## Альтернативы

- Не координироваться: daychi дальше разбирает HTML сайта школы, у расписания две реализации.
- Копировать документы Workshop в репозиторий: устаревают, ссылка на ревизию честнее.
- `.cursor/skills/`, как в пробном прогоне владельца 2026-10-05: здесь хост — Claude Code, прогон откатили.

## Последствия

`.gitignore` исключает `.claude/*`, кроме `skills/`. Гейт `scripts/check-workshop-skill.mjs` держит скилл, метку, ревизию и блок в CLAUDE.md. Обновления сводки приходят из issue Workshop блоком `BOUNDARY_SUMMARY` и правятся в CLAUDE.md в том же PR. Задание #5 (публичный эндпоинт) ждёт подтверждения установки Workshop-ом в issue #1.
