# 0164. Троттлер считает вошедшего по сессии, а не по IP

Дата: 2026-10-01. Статус: принято.

## Контекст

Глобальный `ThrottlerGuard` стоит с этапа 0 и бакетирует всех по `req.ip`: 120
запросов в минуту на пару «маршрут × IP», потом минута отказа. Правило 4 CLAUDE.md и
SECURITY §7 с самого начала требовали считать верифицированную идентичность по ней
самой и откладывали это «на этап 2». Этап 2 прошёл, а завтра экзамен: ученики за
одним Wi-Fi школы (один NAT, один IP) делят лимит на всех. Нагрузочный тест аудита
2026-10-01 (`docs/audits/2026-10-01-pre-exam-audit.md`) показал: десять человек за
одним IP при автосохранении ответов получают 429 с 65-й секунды; у тридцати две
трети сохранений отбиты; картинки вариантов (16 на «Форму 1») упираются на восьми
учениках; 429 на последнем сохранении перед сдачей кабинет показывает как
«Проверьте интернет» и не даёт сдать до конца минуты. RUNBOOK §8.6 предлагал на этот
случай поднять лимит хотфиксом — то есть ослабить защиту входов ради вошедших.

## Решение

Ключ бакета строит `throttleTracker` (`api/src/auth/throttle-tracker.ts`): валидная
cookie сессии (та же подпись `verifySession`, что у `AuthGuard`) — `user:<id>`, всё
остальное — `ip:<адрес>`. Лимит не меняется: 120 в минуту на маршрут, теперь на
человека. Входы и публичные маршруты по-прежнему считаются по IP с прежними
лимитами. Секрет сессии троттлер берёт из того же `SESSION_SECRET` (экспорт
`AuthModule`), второй фабрики нет.

## Альтернативы

- Поднять лимит по IP (RUNBOOK §8.6 до этого решения) — ослабляет защиту входов от
  перебора и всё равно упирается: сто учеников за одним NAT не влезут ни в какой лимит.
- Отключить троттлер для вошедших — вошедший с утёкшей cookie или сломанный клиент
  (шторм повторов) остался бы без потолка вовсе.
- Бакет по `request.user` после `AuthGuard` — гвард троттлера стоит раньше него;
  проверка подписи cookie дешевле (HMAC без базы) и порядок гвардов не трогает.

## Последствия

- Ученики за одним Wi-Fi не делят лимит; шторм от одного клиента упирается в его
  собственные 120 в минуту на маршрут.
- Гейты: `api/test/throttle-session.e2e-spec.ts` — два вошедших за одним IP, тот же
  вошедший с двух IP, без сессии и с битой cookie — по IP;
  `api/src/auth/throttle-tracker.spec.ts` — чистая функция.
- RUNBOOK §8.6 переписан: 429 у вошедшего — один клиент, а не NAT.
