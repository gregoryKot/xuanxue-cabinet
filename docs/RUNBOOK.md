# Runbook — эксплуатация Xuanxue Cabinet

Что делать руками, когда что-то случилось или нужно выкатить. Пишется для человека,
который открыл документ в панике: сначала команда, потом объяснение. После каждого
инцидента — запись в раздел 9 и регрессионный тест.

## 1. Локальный запуск

```bash
nvm use                 # версия из .nvmrc
npm ci
cp .env.example .env    # заполнить MONGODB_URI; секреты вне production не обязательны
npm run dev             # api :3000, web :5173 (прокси на /api)
```

Проверка перед PR одной командой — всё то же, что в CI:

```bash
npm run check
```

## 2. Деплой

Merge в `main` → GitHub → Railway собирает `Dockerfile` и переключает трафик после
успешного `GET /api/health`. Отдельных команд нет.

После деплоя проверить (две минуты):

1. `curl -fsS https://xuanxue.su/api/health` → `"status":"ok"`, `"mongo":"up"`, версия новая.
2. В логах Railway нет `error` за первую минуту (фильтр `level:50` для pino).
3. Открыть кабинет с телефона: приложение обновилось (тост «новая версия» или свежая
   сборка после перезапуска). Залипание старого service worker — см. 8.4.
4. Планировщик тикает: в логе раз в минуту `scheduler.tick` (с этапа 1).

### 2.1 Домен xuanxue.su и DNS

Домен зарегистрирован 2026-09-05 (ADR-0009). Единственный публичный адрес кабинета —
`https://xuanxue.su`; служебный `*.up.railway.app` пользователям не показывается.

Привязка (делается один раз, повторяется только при пересоздании сервиса):

1. Railway → Service → Settings → Networking → **Custom Domain** → `xuanxue.su`, затем
   ещё раз → `www.xuanxue.su`. Railway покажет, куда направить каждую запись.
2. У регистратора в DNS-зоне `xuanxue.su`:
   - `www` — `CNAME` на значение из Railway;
   - апекс (`@`) — `CNAME`/`ALIAS`-запись на то же значение. Если панель регистратора
     не умеет `CNAME` на апексе (частая ситуация в зоне `.su`), перенести DNS-зону на
     бесплатный Cloudflare (режим «DNS only», серое облако) — там апекс-CNAME работает
     через flattening. `A`-записи не подходят: у Railway нет статического IP.
3. Ждать статуса «Verified» в Railway (обычно минуты, по TTL — до суток). Сертификат
   Let's Encrypt Railway выпускает и продлевает сам, ничего настраивать не нужно.
4. Railway → Variables: `PUBLIC_URL=https://xuanxue.su`. Перезапуск: приложение само
   переставит вебхук бота на новый адрес (`setWebhook` при старте, см. 6.2).

Проверка:

```bash
curl -fsSI https://xuanxue.su/ | head -1          # HTTP/2 200
curl -fsS  https://xuanxue.su/api/health           # "status":"ok"
curl -fsSI https://www.xuanxue.su/ | head -1       # тот же сервис
curl -s "https://api.telegram.org/bot$BOT_TOKEN/getWebhookInfo"   # url = https://xuanxue.su/api/telegram/webhook
```

Сменить домен = все сессии, установленные приложения и подписки на пуши сгорают
(cookie, scope PWA и push привязаны к origin). Не делать без предупреждения Димы и Маши.

Почта с домена (`SPF`, `DKIM`, `DMARC`) настраивается на этапе 1 вместе с Resend;
записи выдаёт Resend при добавлении домена, они не пересекаются с записями выше.

## 3. Откат

Пожар: Railway → Deployments → предыдущий успешный → **Rollback**. Это секунды.
Потом обязательно revert-PR, чтобы `main` снова совпадал с продом:

```bash
gh pr list --state merged --limit 5
git revert -m 1 <sha-мержа> && git push -u origin revert/<кратко>
gh pr create --fill
```

Откат с миграцией данных: код совместим со старой и новой схемой (expand → contract),
поэтому откат кода не требует отката данных. Если миграция что-то удалила
(contract-шаг), откат невозможен — поэтому contract делается отдельным PR не раньше,
чем через неделю после expand.

## 4. Логи

Railway → Service → Logs. Формат JSON (pino). Полезные фильтры:

- по запросу пользователя: `"requestId":"<id из ошибки на экране>"`;
- ошибки: `"level":50` (error), `"level":60` (fatal);
- доставка: `"broadcastId":"…"` или `"channelId":"…"`.

Секреты и PII в логах замаскированы (`[Redacted]`); если видишь открытый токен или
email — это баг, правь `api/src/logging/redact-paths.ts` и тест к нему.

## 5. Переменные окружения

Railway → Variables. Изменение = перезапуск сервиса. Полный список с описанием —
`.env.example`; валидатор при старте откажется подниматься, если чего-то не хватает или
формат неверный — читать первую строку ошибки в логах, там перечень.

Новую переменную добавляют в трёх местах: `api/src/config/env.validation.ts`,
`.env.example`, Railway. Первые два проверяет CI.

`BOOTSTRAP_ADMIN_TELEGRAM_ID` — разовая: даёт первому входу с этим Telegram ID
роли admin и teacher. После первого входа Димы её можно убрать из
Railway — дальше роли назначаются в интерфейсе, не через переменную.

## 6. Ротация секретов

### 6.1 `ENCRYPTION_KEY` — только с ре-шифрованием

1. Сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
2. В Railway: `ENCRYPTION_KEY_OLD=<старый>`, `ENCRYPTION_KEY=<новый>`. Перезапуск.
   С этого момента чтение идёт обоими ключами, запись — новым.
3. Запустить перешифровку: `npm run rotate-encryption --workspace=api` — команда ещё
   не написана: до первой ротации её нужно сделать по `MODEL_DEFINITIONS`
   (`api/src/common/model.registry.ts`), обойдя список и взяв
   `encryptSchemaFrom(fieldPolicy)` для каждой модели — другого реестра шифруемых
   полей в проекте нет.
4. Убрать `ENCRYPTION_KEY_OLD`. Перезапуск.

Никогда не менять `ENCRYPTION_KEY` без шага 2–3: данные превратятся в мусор.

### 6.2 `BOT_TOKEN`

BotFather → `/revoke` → новый токен в Railway → перезапуск. При старте приложение само
вызывает `setWebhook` с новым `secret_token`. Проверить: `getWebhookInfo` без ошибок
(`curl https://api.telegram.org/bot<token>/getWebhookInfo`).

### 6.3 `JWT_SECRET`

Новое значение → перезапуск → все входят заново. Предупредить Диму и Машу.

### 6.4 `VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY`

`npx web-push generate-vapid-keys` → обе переменные → перезапуск. Все подписки на пуши
мертвы: сервис удалит их при первой попытке отправки (410), пользователям придёт
подсказка включить уведомления заново при следующем входе.

## 7. База данных

- Atlas → Cluster → Metrics: соединения, операции, размер. M0 — 512 МБ.
- Бэкап (с этапа 1): `scripts/backup-mongo.sh` — `mongodump | gzip | openssl enc`
  → внешнее хранилище. Расписание — GitHub Actions cron раз в сутки. Восстановление:
  расшифровать, `mongorestore --drop`. Проверка восстановления — раз в квартал на
  локальной Mongo.
- Индексы: приложение делает `syncIndexes()` при старте; если индекс не создался
  (дубликаты в данных) — в логе `error` с именем коллекции, приложение не
  поднимается (как с миграциями, ниже): удалить дубли через Atlas, передеплоить.
  Любой индекс, включая TTL для срока хранения, объявляется в схеме —
  `syncIndexes()` при старте удаляет всё, чего там нет.
- Миграции: коллекция `migrations` хранит применённые id. Приложение не поднимается,
  если миграция упала — в логе первая ошибка с id миграции. Чинить миграцию, не
  удалять запись руками.

## 8. Инциденты и симптомы

### 8.1 Ссылка на занятие не пришла

1. Кабинет → Рассылки → журнал: статус доставки по каналу и текст ошибки.
2. `failed` после трёх попыток → учитель уже получил DM с готовым текстом — отправить
   руками, потом разбираться.
3. Причины по частоте: бот удалён из канала или лишён прав; токен ВК протух; сервис
   спал (тариф Railway) — проверить `uptimeSec` в health.

### 8.2 Бот молчит

`getWebhookInfo`: `last_error_message` и `pending_update_count`. Если URL не наш или
пустой — перезапустить сервис (он ставит вебхук при старте). Если 401 — токен сменился,
см. 6.2.

### 8.3 Mongo `down` в health

Atlas → Network Access: IP-allowlist должен содержать `0.0.0.0/0` (у Railway нет
статического IP) или актуальные адреса. Atlas → Database Access: пользователь активен.
Проверить `MONGODB_URI` в Railway.

### 8.4 Старая версия приложения на телефоне не обновляется

Service worker в режиме `autoUpdate`: новая версия подхватывается при следующем открытии.
Если залипло: в браузере «Сведения о сайте → Очистить данные», в установленном
приложении — удалить и поставить заново. Если массово — проверить, что `sw.js` отдаётся
с `Cache-Control: no-cache` (ServeStatic настроен в `app.module.ts`).

### 8.5 Пуши не приходят

Порядок: пользователь дал разрешение? (в настройках устройства) → подписка есть в
`push_subscriptions`? → в журнале доставок статус по каналу `webpush`? → 410 значит
подписка мертва, пользователю нужно включить заново. iOS: только установленное
приложение, 16.4+.

### 8.6 Всплеск 429

Троттлер по IP: 120 запросов в минуту. Ученики за одним NAT (школа, офис) могут
упереться. Временно поднять лимит в `app.module.ts` через PR; постоянное решение —
бакет по сессии (CLAUDE.md, правило 4).
