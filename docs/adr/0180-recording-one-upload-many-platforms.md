# 0180. Запись занятия: один файл на сайт — кабинет раскладывает по площадкам

Дата: 2026-10-10. Статус: принято. Пересматривает отказ от своего Bot API server в
[ADR-0023](0023-exam-video-via-telegram-and-links.md) (там он был не нужен — здесь без
него нельзя) и путь «запись = ссылка или `file_id`» из PLAN §6 п.3.

## Контекст

Отзыв владельца 2026-10-10: Дима монтирует запись и загружает готовый файл руками
отдельно в каждое место: YouTube, Telegram, дальше ВК, кабинет, Boosty. Нужно
минимум действий на максимум площадок. Брать запись прямо из облака Zoom нельзя:
Дима часто её редактирует.

Ограничения площадок (проверено по документации 2026-10-10):

- **Telegram** — облачный Bot API принимает от бота файл до 50 МБ, по URL до 20 МБ.
  Запись занятия — 0,3–2 ГБ. Свой `telegram-bot-api --local` принимает до 2000 МБ;
  дальше бот рассылает по `file_id` без лимита — это у нас уже есть.
- **ВК** — `video.save` работает только с ключом пользователя и правом `video`, а
  это право выдаёт поддержка ВК по письму, «в исключительных случаях».
- **YouTube** — `videos.insert` с OAuth аккаунта школы. Приложение в статусе
  «Testing» получает refresh-токен на 7 дней — нужен статус «In production».
  Непроверенный проект может получить загрузки, запертые в «private», до аудита
  (справка YouTube говорит «да», страница метода — «нет»; решает пробная загрузка).
- **Boosty** — открытого API нет. **Facebook-группы** — Groups API удалён
  22.04.2024.

## Решение

**Источник один — файл на сайте.** На странице занятия, в разделе «Запись», учитель
выбирает файл. Он уходит в R2 тем же загрузчиком частями с докачкой (ADR-0165),
новым видом видео — запись занятия, потолок **2 ГБ**, без сжатия в браузере:
файл уже смонтирован, а сжатие часа видео держит весь результат в памяти вкладки.

**Дальше раскладывает сервер, шагами тика планировщика.** У записи — список
публикаций, по одной на площадку, со статусом `pending → done | failed` и
повторами, как у доставок: тик берёт шаг, пишет результат, падение сервиса не
теряет работу.

1. **Кабинет** — сразу: запись играет на странице занятия и в «Записях занятий».
2. **YouTube** (если школа подключила аккаунт) — `videos.insert` частями из R2,
   ссылка ложится в `{ссылка}` поста.
3. **Telegram** — бот загружает файл один раз, в личку загрузившему, через свой
   Bot API server; полученный `file_id` записывается в запись.
4. **Рассылка** — существующая `RecordingBroadcastService`, когда шаги 2–3 дошли
   до конца: Telegram — видео с текстом поста в подписи, ВК — текст со ссылкой,
   Boosty и Facebook — ручной канал, бот присылает готовый текст. Площадка, которая
   не справилась после повторов, не держит остальные: пост уходит без неё, учителю
   — сообщение, что и где не вышло.
5. **ВК файлом** — только после того, как поддержка ВК выдаст право `video`. До
   того ВК получает ссылку в тексте, как сейчас.

**Одна запись = один пост.** `Recording` несёт сразу файл, ссылку и `file_id`;
ключ идемпотентности рассылки — id файла, если он есть. Ссылка, вписанная руками
рядом с файлом, тоже попадает в тот же пост.

## Альтернативы

- **Брать запись из облака Zoom** — ноль действий, но Дима монтирует запись;
  отвергнуто владельцем.
- **Отправлять файл боту в Telegram** — привычнее, но облачный бот не скачает
  файл больше 20 МБ, значит, всё равно свой Bot API server; владелец выбрал сайт.
- **GramJS (MTProto) под токеном бота вместо своего Bot API server** — второй
  клиент Telegram в коде, неофициальная библиотека, лимит для ботов официально не
  описан, `file_id` для Bot API получается обходом. Свой сервер — тот же Bot API
  и тот же Telegraf.
- **Ссылка на кабинет вместо файла в Telegram** — ученики в каналах не обязаны
  иметь кабинет (CLAUDE.md, «ноль нагрузки на ученика»).
- **Загрузка с сервера в браузер Димы на каждую площадку** — те же N загрузок.

## Последствия

- Бот работает через свой `telegram-bot-api` — второй сервис на Railway с томом.
  Лёг он — лёг весь бот, не только видео: смок в CI, `/api/health` проверяет его,
  RUNBOOK — переезд туда и обратно (`logOut`, 10 минут без возврата).
- Байты записи идут через наш инстанс дважды (приём частями, отдача площадкам) —
  потоком, без буфера в памяти. Тик не ждёт загрузку целиком: шаг публикации —
  отдельная работа с лизингом, как у доставок (ADR-0014).
- Записи в R2 стоят денег: срок хранения — настройка школы на экране «Школа»
  (по умолчанию 90 дней), потом в кабинете остаётся ссылка YouTube.
- Новые секреты: `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` (сервис Bot API), OAuth
  YouTube и ключ ВК — в БД, зашифрованы, подключаются админом с экрана, не в env.
- Порядок работ и что нужно от владельца — PLAN §18.
