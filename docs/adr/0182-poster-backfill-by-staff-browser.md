# 0182. Кадр-превью для старых видео снимает браузер штата из байтов через кабинет

Дата: 2026-10-13. Статус: принято. Уточняет
[ADR-0165](0165-one-video-pipeline.md).

## Контекст

Кадр-превью появился 2026-10-02 (ADR-0165): браузер снимает его при загрузке и отдаёт в
`complete`. Видео, загруженные раньше, кадра не имеют — ADR-0165 так и записал:
«перегнать их можно только на сервере, и этого решения здесь нет». Контрольная работа
2026-10-12 целиком на таких видео: в плеере чёрные плитки без кадра (снимок владельца
2026-10-13), ученику до нажатия не видно, что за ролик. Снять кадр на сервере нечем:
декодера видео в Node нет, а ffmpeg в образе отвергнут в ADR-0165. Снять его в браузере
из `<video src="/api/exam-videos/:id">` тоже нельзя: ответ — 302 на R2, кадр из чужого
домена на холст не рисуется (tainted canvas), CORS у бакета не настроен (ADR-0133).

## Решение

Кадр для видео без кадра снимает **браузер штата** тем же кодом, что при загрузке
(`captureVideoPoster`: Mediabunny, запасной путь — `<video>`), только источник байтов —
не выбранный файл, а **`GET /api/exam-videos/:id/bytes`**: кабинет отдаёт байты объекта R2
со своего домена, с проходом `Range` — декодер читает индекс и первые кадры, а не файл
целиком (2–4 МБ из 50). Маршрут только для штата (`@Roles`), со своим лимитом троттлера:
декодер ходит за байтами кусками. Готовый кадр уходит в **`PUT /api/exam-videos/:id/poster`**
— та же проверка JPEG и размера, что у `complete`, и тот же `setPosterIfAbsent`: первый
записанный кадр не перетирается, повтор идемпотентен. Список кандидатов —
**`GET /api/exam-videos/without-poster`**, пачками по `VIDEOS_WITHOUT_POSTER_BATCH`; число
таких видео — поле `withoutPosterCount` в сводке раздела «Экзамены» (CLAUDE.md
«Продуктовая фича = число в своём разделе»). Кнопка «Снять кадры» на экране раздела
проходит пачки, пока список не опустеет, и показывает «снято N из M».

Байты через инстанс — исключение из ADR-0057 (байты идут мимо инстанса): один проход на
видео, штат, а не каждый просмотр, и только куски по `Range`. Общие части (поток байтов,
запись кадра, выборка без кадра) лежат в `api/src/video-uploads/`, чтобы видео-ответ и
запись занятия подключились тем же путём, когда понадобится.

## Альтернативы

- **ffmpeg на сервере** — отвергнут в ADR-0165, довод не изменился.
- **CORS у бакета R2 и `crossorigin` у `<video>`** — настройка вне репозитория, у каждого
  окружения своя; инвариант «право проверил кабинет, ссылка живёт час» становится зависим
  от конфигурации бакета.
- **Учитель перезагружает видео** — 54 файла руками с телефона; кадр при этом снимется
  сам, но ценой часа работы и новых объектов в R2.
- **Фрагмент `#t=0.5` в `src` плеера** — iOS показал бы кадр, но ценой первых мегабайт
  каждого несжатого ролика у каждого ученика при открытии экрана.

## Последствия

- У старых видео появляется кадр после одного нажатия штата; сжатия это не даёт — ролик,
  снятый iPhone в HEVC, по-прежнему не откроется в браузере без аппаратного декодера
  (ADR-0165, «Плеер»). Перекодировка тем же путём (байты → `compressVideo` → замена
  файла) — отдельное решение, если понадобится.
- Кадр снимает тот браузер, который умеет декодировать файл: Safari и Chrome на Mac —
  HEVC, Chrome на Windows — как повезёт; что не снялось, остаётся в списке, кнопка
  честно показывает «не вышло N».
- Гейты: e2e на роли у трёх маршрутов (ученику 403), e2e прохода `Range` и записи кадра
  «сохранил → отдал», spec сводки без кадра на `mongodb-memory-server`, тесты хука и
  снимка из адреса в web.
