# 0034. Статуса «ждёт подтверждения» больше нет — регистрация только по ссылке

Дата: 2026-09-16. Статус: принято. Отменяет ADR-0026 в части статуса `invited`
и обоих путей его подтверждения; дополняет ADR-0030.

## Контекст

Владелец 2026-09-15 открыл ссылку-приглашение, вошёл через Telegram и на
мгновение увидел экран «Вы вошли, осталось дождаться подтверждения. Учитель
откроет доступ…», хотя тут же попал в кабинет. Причина — вход по ссылке
оставался двухшаговым даже после ADR-0030: `POST /auth/telegram` создавал
человека со `status: 'invited'`, кабинет успевал отрисовать
`PendingApprovalScreen`, и только следующим запросом `POST /auth/join`
переводил его в `active`. ADR-0026 держало этот статус ради школы,
подтверждающей незнакомцев вручную или по членству в Telegram-группе;
ADR-0030 добавило третий путь — ссылку-приглашение — и тем самым сделало
оба прежних пути (ручную кнопку и автоподтверждение по группе) избыточными
для любого, кто попал в кабинет через неё. Решение владельца: «удаляем с
концами», а не чиним гонку между шагами.

## Решение

Регистрация в кабинете возможна только по ссылке-приглашению школы
(ADR-0030) — открытого набора «зарегистрируйтесь и ждите» больше нет.
Статусов у человека два: `active` и `blocked`. Вход — один запрос, не два:
`POST /auth/telegram` принимает необязательный `inviteCode` (в query
`?join=<code>` — подпись Telegram считается по телу запроса целиком,
добавлять туда поле, которого сам виджет не подписывал, нельзя),
`POST /auth/email/verify` принимает его в теле (страница читает код из
`?join=` и просто пересылает). Единый сервис `LoginIdentityService`
(`api/src/users/login-identity.service.ts`) решает: существующий человек —
вход как обычно, код игнорируется, `blocked` — 403 тем же `ACCESS_MESSAGE`;
нового нет, код валиден — создать `active` сразу с `joinedViaInviteAt`;
нового нет и кода нет или он неверен — не создавать аккаунт и бросить 403
с текстом «Чтобы попасть в кабинет, откройте ссылку-приглашение от учителя
школы» (`NO_INVITE_LINK_MESSAGE`, shared/src/auth.ts). Исключение — прежнее:
`BOOTSTRAP_ADMIN_TELEGRAM_ID` заводится без кода, подтверждать его некому.

`POST /auth/join` удалён — шага «войти, затем присоединиться» больше нет.
`POST /auth/join/check` остаётся: страница `/join/<code>` до входа должна
сказать «ссылка не действует», не гнать человека логиниться зря.

Автоподтверждение по членству в Telegram-группе (ADR-0026 п.2) удалено
целиком: `StudentMembershipApprovalService`, `ChatMemberJoinHandler`,
`GroupMembershipService` и `chat_member` в `ALLOWED_UPDATES` вебхука —
механика существовала только ради снятия `invited`, снимать больше нечего.
Бот на `/start join_<code>` заводит незнакомца с валидным кодом сразу
`active` тем же способом, что и раньше (`join-invite-deep-link.ts`), но
напрямую через `UsersService`/`InviteLinkService`, без промежуточного
статуса и без `JoinByInviteService` (удалён — его единственным делом был
переход `invited` → `active`, переходить больше неоткуда).

Миграция `0007-invited-users-active` (`api/src/migrations/`) переводит уже
накопленных `invited`-людей в `active` до того, как раннер отпускает
приложение слушать порт — решение владельца (через агента): они уже входили
хотя бы раз, лишних школа блокирует вручную на «Людях» после миграции, а не
агент решает это заранее за неё.

## Альтернативы

- Оставить `invited` для входа без ссылки (email/Telegram напрямую, без
  кода) — отвергнуто владельцем: «удаляем с концами», отдельная ветка входа
  без ссылки означала бы, что промежуточный статус жив, просто реже виден.
- Одноразовые ссылки-приглашения вместо капабилити-ссылки — отклонено ещё в
  ADR-0030: одна ссылка должна работать на весь поток учеников.

## Последствия

Проще: вход — один HTTP-запрос вместо двух, `PendingApprovalScreen` и вся
логика вокруг «ждёт/не ждёт» пропадают из `AuthGuard`, `RequireAuth`,
`AppShell`, экрана «Люди» (кнопка «Подтвердить», бейдж и сортировка «ждущие
вверху» — тоже удалены, подтверждать больше некого). Сложнее: без ссылки
в кабинет не попасть вовсе — человек без Telegram и без ссылки идёт к
учителю за ней, это осознанный компромисс (ADR-0030 уже его сделал, здесь
только убирается запасной путь, которым фактически не пользовались).
Бот на `/start` без кода отвечает как раньше — вежливым отказом незнакомцу
или доступом для уже известного человека, `join_<code>` — единственный
способ завести аккаунт через бота.

Гейты: `login-identity.service.spec.ts` (ветвления резолва), e2e
`auth-telegram.e2e-spec.ts`/`auth-email-resend.e2e-spec.ts` (новый без кода
→ 403 и не создан; с валидным кодом → 200, active, joinedViaInvite;
существующий без кода → 200; blocked → 403), `auth-join.e2e-spec.ts`
(только `/auth/join/check` остался), `telegram-webhook-join.e2e-spec.ts`,
миграция `0007-invited-users-active.migration.spec.ts`, веб —
`JoinScreen.test.tsx`, `LoginScreen.test.tsx` (403-текст с действием),
`EmailLoginCallbackScreen.test.tsx`, `PeopleScreen.test.tsx` (без
«Подтвердить»), `RequireAuth.test.tsx`. Регрессионный тест на инцидент
2026-09-15 — на всём флоу `/join/<code>` ни в один момент не рендерится
текст «дождаться подтверждения».
