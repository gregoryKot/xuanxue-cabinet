# 0082. Экзамен показывает N случайных вопросов из списка

Дата: 2026-09-21. Статус: принято.

## Контекст

У владельца экзамен на 50 вопросов, а сдающему он хочет давать 15 — каждому свои,
случайно из общего списка. Сейчас попытка получает все вопросы формы: снимок
(`exam-attempt-snapshot.ts`) берёт `blocks[].itemIds` целиком и только
перемешивает их, если у блока стоит `shuffle`.

## Решение

У блока формы появляется необязательное поле `questionsPerAttempt` — рядом с
`shuffle`, потому что оба про вопросы одного списка и оба применяются один раз,
при старте попытки, в снимок (ADR-0033). Нет поля — сдающий получает все
вопросы, как раньше. Есть — при старте из `itemIds` случайно выбирается столько
вопросов; с `shuffle` они идут в случайном порядке, без него — в порядке
списка. Поле живёт внутри зашифрованного `blocks`, отдельной политики
шифрования не нужно. Число не может быть больше длины списка: сервис отказывает
при сохранении понятным текстом, снимок на всякий случай берёт не больше, чем
есть. Для учителя это одно числовое поле в «Как проходит экзамен»: «Вопросов
ученику», пусто — все. Разные попытки одного ученика независимы: вторая может
повторить часть вопросов первой.

## Альтернативы

- Поле у самой формы (`exams.questionsPerAttempt`), как `shuffleOptions`: у
  старых многоблочных форм пришлось бы делить число между блоками; у блока —
  ни одного особого случая.
- Не повторять вопросы прошлых попыток того же ученика: нужна выборка попыток
  при старте и правило «что делать, когда неповторённых не хватает» — никто не
  просил, а `attemptsAllowed` по умолчанию 1.
- Отдельная сущность «пул» и ссылка на неё из экзамена: вторая модель ради
  одного числа.

## Последствия

Снимок попытки теперь может быть короче формы: список вопросов в экзамене — пул,
а не то, что видит каждый сдающий. Строка списка экзаменов показывает «15 из 50
вопросов», предпросмотр говорит об этом словами. Гейты: `tsc` на общем
контракте `shared`, юнит-тест снимка с инъекцией `random` (выборка, порядок,
число больше списка), spec сервиса формы на отказ при `questionsPerAttempt` >
длины списка, тест попытки «старт → в попытке ровно N вопросов из формы», e2e на
поле в ответе `/exams`, vitest формы web на валидацию и сборку тела запроса.

## Дополнение 2026-09-21: обязательные вопросы

Владелец попросил отметку «обязательный» у вопроса: такой вопрос должен попасть
каждому сдающему при любой выборке. Отметка живёт у блока формы, а не у вопроса
банка: один вопрос может стоять в нескольких экзаменах и быть обязательным только
в одном. Поле `requiredItemIds` — подмножество `itemIds`, рядом с
`questionsPerAttempt`; без выборки (поле пустое) ни на что не влияет. При старте
попытки обязательные входят всегда, остаток до `questionsPerAttempt` добирается
случайно из остальных; порядок — как у выборки (`shuffle` или порядок списка).
Обязательных не может быть больше `questionsPerAttempt`, id вне списка сервис
отбрасывает молча (вопрос убрали из экзамена — отметка ушла вместе с ним). На экране
отметка ★ у строки вопроса появляется, когда заполнено «Вопросов ученику», и объяснена
подсказкой под этим полем.
