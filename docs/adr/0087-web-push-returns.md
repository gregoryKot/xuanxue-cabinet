# 0087. Push-уведомления возвращаются — всем ролям, пинг без содержимого

Дата: 2026-09-21. Статус: принято. Заменяет [ADR-0032](0032-no-service-worker.md),
возвращает отменённую там часть [ADR-0006](0006-pwa-and-web-push.md).

## Контекст

15 сентября владелец отменил этап 2, а вместе с ним push. Service worker остался без
работы — тост «новая версия» и прекеш оболочки без данных — и при этом рисковал сутками
отдавать закешированную старую версию; его снесли килсвитчем (ADR-0032). 21 сентября
владелец решение пересмотрел: push нужен, причём всем ролям, включая учеников.

Ограничение, которое никуда не делось, — CLAUDE.md «Ноль нагрузки на ученика»: кабинет
для ученика необязателен. Push просит у ученика два действия: поставить кабинет на экран
«Домой» (на iPhone иначе разрешение не спросить вовсе, Safari 16.4+) и нажать
«Разрешить». Владелец про это знает и решение принял (диалог 2026-09-21). Противоречия
с правилом нет ровно до тех пор, пока push остаётся **добавкой**: ученик, не поставивший
ничего, получает всё, что получал, — Telegram и ленту кабинета.

## Решение

**Service worker возвращается, но только ради push**: без прекеша, без
`fetch`-обработчика, без Workbox. Файл — по тому же адресу `/sw.js`, где сейчас
килсвитч, и наследует его работу: на `activate` стирает все кеши (старый
Workbox-прекеш умирает), но себя не снимает. Люди со старым worker'ом получат новый при
первом заходе — `sw.js` отдаётся с `Cache-Control: no-cache`
(`api/src/static/static-cache-control.ts`), браузер его перепроверит.
`web/src/pwa/unregisterServiceWorker.ts` заменяется регистрацией: оставить его нельзя,
он снимет новый worker на старте.

**В push не кладётся текст.** Сервер шлёт пустой пинг, worker будит вкладку, сам читает
свежую строку из ленты кабинета (`GET /api/me/inbox`, ADR-0061) и показывает её. Лента
уже система записи, а шифрование содержимого push (RFC 8291: ECDH P-256 + HKDF +
AES-128-GCM) — единственное, ради чего пришлось бы тянуть `web-push`. Подпись VAPID
(ES256 JWT) остаётся, её встроенный `crypto` делает сам — тем же приёмом, что HMAC-JWT
сессии (ADR-0012). Cookie сессии `HttpOnly; SameSite=Lax` (`session-cookie.ts`), запрос
worker'а к своему же origin её несёт. Сеть отказала — показывается общая строка «Есть
новое уведомление», а не тишина (CLAUDE.md: тихий отказ — самая дорогая ошибка).

**Push — не `ChannelAdapter`.** Адаптер канала шлёт один пост в канал школы,
идемпотентность у него по `(broadcastId, channelId)` (ADR-0004). Push адресный: у одного
человека несколько подписок (телефон, ноутбук), у одного события — десятки адресатов.
Поэтому push — третье плечо уведомлений рядом с `InAppExamNotifier` и
`TelegramExamNotifier` (ADR-0061): адресаты выбираются по роли и включённому виду через
`NotificationPrefsService`, как у остальных плеч. `CHANNEL_TYPES` остаётся
`telegram | vk | manual` — тип `webpush` обратно не заводится.

**Подписки — коллекция `push_subscriptions`** (чеклист CLAUDE.md «Новая коллекция»):
`userId` — владение, в `USER_OWNED_COLLECTIONS`; `endpoint` — уникальный индекс, он же
идемпотентность повторной подписки того же устройства; ключи `p256dh` и `auth`
шифруются (`EncryptSchema`) — это секреты доставки, как токен канала; `retention` —
живёт, пока жив аккаунт, плюс удаление сразу по ответу 404/410 от push-сервиса
(подписка мертва: браузер снесён или разрешение отозвано).

**Ничто не зависит от push.** Ни один сценарий не требует подписки; она включается
отдельно от деплоя и сначала на владельце (CLAUDE.md «Рискованная фича — за флагом»).

## Альтернативы

- **Оставить без push** — то, что решил ADR-0032; владелец пересмотрел.
- **`web-push` с шифрованием содержимого** — текст приезжает сразу, без второго запроса
  и без общей строки при офлайне. Нет: вся крипта RFC 8291 в проекте ради одного места,
  а лента и так держит текст (ADR-0061); проект предпочитает встроенное (CLAUDE.md
  «Зависимости»), прецедент — ADR-0029, Resend голым `fetch`.
- **Push как `ChannelAdapter` (`webpush`)** — так планировал ADR-0006. Нет: разная
  механика, см. выше; пришлось бы ломать смысл `deliveries (broadcastId, channelId)`.
- **Нативные приложения в App Store / Google Play** — отвергнуто ещё в ADR-0006: ревью
  магазинов и взносы несоразмерны школе на десятки учеников.

## Последствия

- Возвращаются переменные `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`:
  валидатор `env.validation.ts` + строка в `.env.example` (гейт `check-env-example.mjs`),
  ротация — раздел RUNBOOK §6 (смена пары обнуляет все подписки, людям придётся
  разрешить заново — это и есть процедура).
- `scripts/check-pwa.mjs` меняет проверку `/sw.js`: не заглушка-килсвитч, а push-worker;
  гейт по-прежнему краснеет на `precache`/`workbox` в тексте файла — прекеш не должен
  вернуться вместе с push.
- На iPhone push работает только у кабинета, поставленного на экран «Домой» (Safari
  16.4+). Экран выдачи разрешения обязан это объяснять до первого действия (CLAUDE.md
  «Каждая фича объясняет откуда это и зачем»).
- Частично возвращается риск ADR-0032 — залипание на старой версии. Смягчение: worker
  без `fetch`-обработчика ничего не перехватывает, отдавать закешированное ему нечем.
- Разрешение на уведомления просится **по кнопке**, никогда не на входе: браузер
  запоминает отказ навсегда, автоматический запрос — прямой путь к «Заблокировать».
- Гейты: `check-pwa.mjs`, spec валидатора env, e2e на владение подписками (пользователь
  А не видит и не снимает подписку Б), `user-data.registry.spec.ts`,
  `encryption-coverage.spec.ts`.

## Порядок работ

Одним PR не влезает (CLAUDE.md 1б), по одной теме на PR:

1. Этот ADR и правки документов (PWA.md, статус ADR-0032, PLAN §4).
2. `web`: push-worker вместо килсвитча, регистрация вместо снятия, `check-pwa.mjs`.
3. `api`: коллекция `push_subscriptions`, VAPID в env, эндпоинты подписки и отписки.
4. `api`: отправка — VAPID-подпись на встроенном `crypto`, плечо-нотификатор, удаление
   мёртвых подписок.
5. `web`: кнопка «Включить уведомления» с объяснением, переключатель в «Профиле».
