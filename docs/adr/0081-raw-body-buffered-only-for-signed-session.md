# 0081. Сырое тело буферизуется только для подписанной сессии, число одновременных загрузок ограничено

Дата: 2026-09-21. Статус: принято. Уточняет
[ADR-0035](0035-exam-option-images-in-mongo.md) и
[ADR-0057](0057-material-files-in-r2.md), ничего не отменяя.

## Контекст

`app.useBodyParser('raw', { type: predicate })` в `app.setup.ts` — express-middleware,
она отрабатывает раньше, чем Nest дойдёт до `ThrottlerGuard` и `AuthGuard`. Предикат
проверял только форму пути, метод и заявленный `Content-Type`: неавторизованный
`POST /api/materials/<24 hex>/file` с `Content-Type: application/pdf` буферизовался в
память инстанса целиком (до 30 МБ, `MATERIAL_FILE_LIMITS.maxBytes`) и только потом
получал 401 — с картинками ADR-0035 (потолок 1 МБ) та же механика была безобидна,
файл материала ADR-0057 поднял её цену до заметной.

## Решение

Две независимые меры, обе нужны.

**Мера 1.** Предикат сам проверяет подписанную сессию — `verifySession`/`readCookie`
синхронны, в БД не ходят (`common/raw-body-session.ts`, `hasSignedSession`), последним
условием, после дешёвых проверок метода/пути/типа. Без пригодной сессии сырой парсер
не включается, запрос получает 401 от `AuthGuard` как обычно. Это не авторизация: роль
и `blocked` по-прежнему проверяет только гвард из БД — предикат может лишь отказать в
буферизации, никогда не разрешить доступ.

**Мера 2.** Валидная сессия своего ученика или утёкшая cookie всё ещё может занять
память параллельными запросами (роль синхронно не проверить). `common/raw-upload-concurrency.ts`
считает сырые загрузки «в полёте» и отказывает сверх `RAW_UPLOAD_CONCURRENCY_LIMIT`
(4 — до 120 МБ Buffer-памяти разом) — 503 с `Retry-After`, единственное место, где
конверт `ApiErrorBody` собирается вручную: гварды сюда не доходят.

## Альтернативы

- Только мера 2 без меры 1 — не закрывает неавторизованный поток, только его размер.
- Стриминг в R2 вместо буферизации — отдельное решение с ADR, не нужно при нынешней
  нагрузке (учитель грузит файлы по одному); граница задачи, не трогаем.

## Последствия

Предикаты `isMaterialFileUpload`/`isRawImageUpload` стали фабриками
(`makeIsMaterialFileUpload(secret)`/`makeIsRawImageUpload(secret)`), секрет — из DI
(`SESSION_SECRET`), один раз в `app.setup.ts`. Гейты: юнит на `hasSignedSession` и на
оба предиката (сессия — последним условием), юнит на счётчик (потолок, оба пути
освобождения слота, без двойного освобождения), e2e — неавторизованный `POST` даёт 401,
а не 400 «файл не пришёл».
