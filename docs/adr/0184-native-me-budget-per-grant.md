# 0184. Бюджет GET /api/auth/native/me — по гранту, а не по IP

Дата: 2026-10-19. Статус: принято.

## Контекст

Бэкенд Daychi пересылает bearer приложения в `GET /api/auth/native/me` перед каждым чтением
закрытого содержания. Все читатели приходят с одного серверного адреса Daychi, и общий бакет
по IP (`NATIVE_AUTH_THROTTLE` и глобальный троттлер) превращает одного активного читателя в
отказ для всех. Ёмкость задаёт контракт Workshop
[native-content-session](https://github.com/dveyarangi/xuanxue-workshop/blob/a07f08747aa7d97e4d3496e87e1d8319db413698/docs/contracts/native-content-session.md)
(ревизия `a07f087`, Workshop issue #15, раздел «Capacity and identity»): 60 успешных проверок
на проверенный грант в скользящем окне 60 секунд, общий бюджет у прежнего и продлённого
ключа одного гранта, целый `Retry-After` до выхода старейшей засчитанной проверки из окна
(1–60), отказ окно не продлевает, разные гранты независимы. Невалидный трафик сохраняет
защиту по IP и не тратит бюджет гранта; ключ бакета не берётся из непроверенного текста.

## Решение

**Сначала проверка, потом бюджет.** Маршрут `me` помечен `@SkipThrottle()` и проходит мимо
`ThrottlerGuard`; лимит держит `NativeMeLimiter` (`native-auth/native-me-limiter.ts`).
`admit()` вызывает обычную проверку bearer и только по её итогу выбирает бакет:

| Итог проверки                                         | Бакет             |
| ----------------------------------------------------- | ----------------- |
| грант принят                                          | `grant:<grantId>` |
| `invalid_token`, `account_blocked`, `invalid_request` | `ip:<адрес>`      |
| сбой базы и прочее                                    | не считается      |

Продлённый ключ указывает на тот же грант, поэтому бюджет у них общий без отдельного кода.
Адрес — `req.ip` после `trust proxy` (`app.setup.ts`), заголовки запроса в ключ не идут.

**Окно — журнал отметок.** `SlidingWindowLog` хранит время каждой засчитанной проверки по
ключу. Отметка ровно 60-секундной давности уже не считается; отказ отметку не добавляет;
ключи, где последняя отметка вышла из окна, убираются раз в окно. Переполнение — доменная
`NativeRateLimitedError(retryAfterSec)`, фильтр нативных ошибок отдаёт 429
`{ "error": "rate_limited" }` и `Retry-After`.

**Хранение — память процесса**, как у троттлера: сервис на Railway один инстанс, а потеря
счётчиков при деплое лишь обнуляет минутное окно.

## Альтернативы

- Счётчики в Mongo: переживают деплой и работают на нескольких инстансах, но добавляют запись
  в базу на каждую проверку ради выигрыша, которого при одном инстансе нет.
- Свой трекер `ThrottlerGuard` по гранту: гвард работает до контроллера и не знает итога
  проверки, а окно `@nestjs/throttler` фиксированное — `Retry-After` по контракту из него не
  посчитать.
- Проверка IP до проверки гранта: снова общий бакет для всех читателей Daychi.

## Последствия

- При двух и более инстансах бюджет делится на них — переход на несколько инстансов требует
  общего хранилища.
- Renew и revoke по-прежнему под `NATIVE_AUTH_THROTTLE` по IP.
- Гейты: `native-me-limiter.spec.ts` — граница окна, округление `Retry-After`, отказ без
  продления, независимость ключей, уборка, выбор бакета по итогу проверки;
  `native-error.filter.spec.ts` — 429 с заголовком; e2e `native-me-budget` на настоящем
  `AppModule` — общие случаи контракта C09–C12.
