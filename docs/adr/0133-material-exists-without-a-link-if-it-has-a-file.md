# 0133. Материал существует без ссылки, если у него есть файл

Дата: 2026-09-27. Статус: принято. Уточняет
[ADR-0057](0057-material-files-in-r2.md) (файл материала в R2) и
[ADR-0047](0047-materials-bound-to-classes.md) (модель материала).

## Контекст

Владелец подключил Cloudflare R2 2026-09-27, и файлы материалов заработали на проде.
Тут же выяснилось: материал по-прежнему не может существовать без ссылки. `url` был
обязателен и в форме (`Вставьте ссылку на материал.`), и в DTO сервера, и в схеме
Mongo. Учитель, которому нужно выложить методичку PDF, обязан придумать какой-то адрес
— при том что файл уже лежит в хранилище и скачивается.

Требование было верным, пока материал по определению был ссылкой (ADR-0047: «название,
ссылка, вид, занятие»). Слой 3.10 (ADR-0057) это изменил, а модель осталась прежней —
ровно тот случай, про который CLAUDE.md п. 1д говорит «ошибка чинится вместе с
причиной»: механизм, который не дал бы этому повториться, — правило, что поле
контракта, которое перестало быть единственным способом открыть запись, теряет
обязательность в том же слое, где появился второй способ.

Главная трудность решения — **поле файла появляется только у уже сохранённого
материала**: ключ объекта в R2 строится из его id (`materials/<id>/<uuid>`), а у
несозданного материала id нет. Значит правило «или ссылка, или файл» в момент создания
проверять нечем: там нет ни того, ни другого.

## Решение

**Ссылка у материала необязательна, когда у него есть файл.** `MaterialDto.url`,
`MyMaterialDto.url` и `CreateMaterialInput.url` — необязательные поля; ключа `url` в
JSON нет вовсе, когда ссылки нет (как у `file`). В `UpdateMaterialInput` `url`
принимает `null` — «убрать ссылку», тот же приём, что у nullable-полей занятия
(`NULLABLE_MATERIAL_FIELDS`, `splitUpdate`), а не пустая строка: пустая строка доехала
бы до базы значением и в ответе выглядела бы ссылкой, которой нет.

**Файл выбирается прямо в форме создания, а уходит в хранилище сразу после того, как
материал создан** (вариант 1 развилки). Для учителя это одно действие: название, вид,
«Добавить файл», «Сохранить». Внутри шагов два — `POST /materials`, затем
`POST /materials/:id/file` по id из ответа.

**Что происходит, если второй шаг не долетел.** Материал уже создан, и страница
становится страницей этого материала: заголовок, «Удалить материал», обычное поле файла
— второе «Сохранить» правит созданный материал, а не заводит дубль. Под формой стоит
ошибка «Материал сохранён, а файл не загрузился. Приложите его ещё раз.» Формат и размер
файла проверяются в момент выбора, до создания материала, — негодный файл не должен
приводить к материалу, который потом нечем открыть.

**Ученику не едет материал, у которого нет ни ссылки, ни файла.** Отбор — условием
запроса Mongo (`STUDENT_OPENABLE_FILTER`: есть `url` или есть `fileKey`) в
`MaterialsService.listForStudent` и `LessonMaterialsService.findByLessonIds`, а не после
выборки: иначе такие материалы съедали бы лимит списка — та же причина и тот же приём,
что у `access: { $ne: 'staff' }` (ADR-0058). Строка без «Открыть» и «Скачать» ученику
бесполезна, а живёт такой материал секунды — ровно между двумя шагами сохранения.
Штат видит его всегда: учитель как раз стоит на его странице и прикладывает файл.

**Короткая форма «Добавить ссылку» на странице даты занятия (ADR-0056) поля файла не
получает — там ссылка остаётся обязательной.** Форма так и называется: учитель
раскрывает её, когда адрес у него в руках прямо сейчас. Загрузка файла требует выбора
файла, проверки формата, ожидания и обработки сбоя — внутри формы занятия, в двух
пальцах от кнопки «Сохранить» самого занятия, это второй путь загрузки с теми же
шагами. Материал с файлом заводится на своей странице, она в одном шаге из
«Материалов». Текст ошибки формы поэтому разный: там, где файл возможен, — «Вставьте
ссылку на материал или приложите файл.», в короткой форме — прежний «Вставьте ссылку на
материал.».

## Альтернативы

- **Разрешить материал без ссылки и без файла** (вариант 2 развилки): дёшево —
  никакого второго шага, никакой обработки его сбоя, — но в библиотеке остаётся строка,
  которую не открыть и не скачать, а учителю после сохранения нужно вернуться и
  приложить файл вторым заходом. Отбор для ученика всё равно понадобился бы; здесь он
  прикрывает только сбой, а не обычный путь.
- **Ссылка обязательна при создании, но её можно убрать потом** (вариант 3): формально
  работает, на деле не решает задачу — чтобы выложить PDF, всё равно надо сперва
  что-то вписать.
- **Загружать файл до создания материала, в отдельный «черновой» ключ, и переносить
  объект после**: лишняя сущность в R2 и второй источник сирот (ADR-0079) ради того же
  двухшагового пути, что и сейчас.
- **Один запрос multipart вместо двух**: пришлось бы вводить разбор multipart на
  инстансе рядом с уже работающим разбором сырого тела (ADR-0057) — вторая механика
  загрузки ради экономии одного запроса.
- **Откатывать созданный материал, если файл не долетел**: удаление только что
  сохранённых данных из-за сбоя сети пугает сильнее, чем материал без файла, и имеет
  свой сбой (`DELETE` тоже может не пройти).

## Последствия

- Миграция не нужна: у всех существующих материалов ссылка есть, поле просто становится
  необязательным (expand без contract) — старый и новый код при деплое уживаются, старый
  читает `url` там, где он есть, новый переживает его отсутствие.
- Название материала в строке на странице даты занятия — ссылка только когда ссылка
  есть, иначе обычный текст; `VideoEmbed` строится по адресу и без него не рисуется
  вовсе. У ученика в карточке остаётся одно действие «Скачать файл».
- Гейты: `materials-without-url.e2e-spec.ts` (создание без `url`, ключа `url` в ответе
  нет, ученик такого материала не видит), spec сервиса на `mongodb-memory-server`
  (`url: null` снимает ссылку, материал с файлом ученику едет),
  `useNewMaterialFile.test.ts` (сбой второго шага не создаёт дубль), тесты формы
  (ссылки нет и файла нет — что говорит форма) и строки ученика без ссылки.
