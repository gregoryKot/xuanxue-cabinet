# Приложение на телефоне и уведомления

Кабинет с первого дня — устанавливаемое приложение (PWA); push-уведомления —
этап 2 (PLAN.md §5), Telegram и email закрывают этап 1 сами. Решение и
ограничения iOS — [ADR-0006](adr/0006-pwa-and-web-push.md). Правила:

- Manifest и service worker собирает `vite-plugin-pwa` при обычном `npm run build`.
  Гейт: `scripts/check-pwa.mjs` после сборки (manifest, иконки 192/512, SW).
- **`/api/*` никогда не кешируется** SW (NetworkOnly): устаревшее расписание =
  пропущенное занятие, на общем телефоне — чужие данные. Прекеш — только оболочка.
  Обновление — `autoUpdate` + тост.
- **Push — ещё один `ChannelAdapter`** (`webpush`, `VAPID_*` через валидатор env).
  Подписки — `push_subscriptions` в `USER_OWNED_COLLECTIONS`, endpoint и ключи
  зашифрованы (endpoint — capability-URL). 404/410 от push-сервиса → подписку удаляем.
- **Push никогда не единственный канал**: Telegram и email остаются.
- Разрешение на уведомления — по нажатию пользователя после объяснения, не при загрузке.
  На iOS сначала подсказка «На экран „Домой“». Настройки уведомлений — у пользователя.
- Safe-area iOS только в `@media (display-mode: standalone)`. Сессия долгая и rolling:
  в установленном приложении iOS отдельное хранилище, вход заново — норма.
