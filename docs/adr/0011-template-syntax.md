# 0011. Синтаксис шаблонов постов: allow-list плейсхолдеров и `[ … ]`

Дата: 2026-09-05. Статус: принято.

## Контекст

Шаблоны постов (PLAN §6) хранятся в `settings.templates`, учитель редактирует их с
экрана «Шаблоны» и может переопределить на слот. Это пользовательский текст, который
переживёт код: смена синтаксиса позже — миграция чужих данных, а не рефакторинг.
SECURITY.md §4 требует, чтобы подстановка была заменой по allow-list, без `eval` и без
шаблонизатора с выражениями.

## Решение

Два элемента синтаксиса: плейсхолдер `{имя}` из фиксированного allow-list
(`TEMPLATE_PLACEHOLDERS`) и необязательный фрагмент `[ … ]`, который исчезает вместе со
скобками, если внутри нет ни одного плейсхолдера или все плейсхолдеры внутри пустые.
Рендер — один проход по исходному тексту шаблона: сегменты (литералы и фрагменты)
выделяются до подстановки, значения вставляются как есть и не разбираются повторно.
Результат — plain text, без экранирования. Скобки внутри значения («Комплекс [24
формы]») остаются текстом: парсер фрагментов и плейсхолдеров читает только шаблон и
никогда не читает значения. Вложенные `[` не поддерживаются.

## Альтернативы

- Mustache/Handlebars — условные выражения и циклы для двух текстов из PLAN §1 не
  нужны; HTML-экранирование по умолчанию противоречит plain text постов; ещё одна
  зависимость в `shared`, которая по правилу «зависимости» должна остаться голым
  TypeScript.
- `{: тема}` из первой версии PLAN — разделитель `:` захардкожен в синтаксис,
  необязательный текст с любым другим разделителем (« — », через запятую) потребовал
  бы второго варианта синтаксиса.

## Последствия

- `shared/src/templates.ts` — единственное место, которое понимает `{имя}` и `[ … ]`;
  `api` и `web` вызывают `renderTemplate`/`findUnknownPlaceholders`, не пишут свой
  парсер.
- Гейт — `shared/src/templates.spec.ts` на реальных постах канала (PLAN §1): изменение
  поведения без обновления этих тестов не пройдёт CI.
- Новый плейсхолдер — правка allow-list и defaults в одном PR, форма показывает
  устаревший `{имя}` учителю через `findUnknownPlaceholders`, не тихо теряет текст.
