# ADR — записи архитектурных решений

Одно решение — один файл `NNNN-короткое-название.md`, номер по порядку. Решение
записывается **в том PR, где принимается** (CLAUDE.md, правило 1в). Без записи через
полгода выбор выглядит случайностью, и его переделывают, наступая на те же грабли.

Что считается решением: выбор библиотеки или сервиса, схема данных, протокол, способ
деплоя, отказ от чего-то очевидного, правило, которое ограничивает будущий код.

Шаблон (заполнять коротко, 15–30 строк):

```markdown
# NNNN. Название решения

Дата: ГГГГ-ММ-ДД. Статус: принято | заменено ADR-NNNN | отменено.

## Контекст

Какая задача или боль. Какие ограничения (люди, деньги, сроки, платформа).

## Решение

Что выбрали. Одним абзацем.

## Альтернативы

Что ещё рассматривали и почему нет. По строке на вариант.

## Последствия

Что становится проще, что сложнее, что теперь запрещено или обязательно.
Какие гейты (тест, eslint, CI) закрепляют решение.
```

Отменённое решение не удаляется: статус меняется, добавляется ссылка на новое.
