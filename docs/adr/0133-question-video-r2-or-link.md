# 0133. Видео в вопросе и вариантах — файлом в R2 или ссылкой

Дата: 2026-09-23. Статус: принято. Загрузка и плеер уточнены
[ADR-0165](0165-one-video-pipeline.md): частями, со сжатием и кадром-превью.

## Контекст

Отзыв владельца 2026-09-23: «Добавить возможность прикреплять видео к вопросам
экзамена и выбирать правильное из двух (как с фото), или говорить, что не так в
одном». Смысл: текстовый вопрос может нести видео к формулировке («что не так в
этом движении»), а варианты `single`/`multiple` — видео вместо или вместе с
текстом, тем же способом, что уже несут картинку (ADR-0035, дополнено
ADR-0105/ADR-0118).

Это не тот же случай, что ADR-0023: там видео — **ответ ученика**, несколько
десятков коротких роликов с телефонов, которые незачем хранить у себя, — Telegram
справляется бесплатно. Здесь видео — **референс учителя**: несколько клипов на
весь экзамен, которые учитель готовит заранее и должен видеть каждый сдающий,
включая тех, кто пришёл через почту без Telegram (ADR-0029) — путь ADR-0023 для
них закрыт. R2 уже поднят для файлов материалов (ADR-0057): тот же бакет, тот же
`FileStoreService`, вторая карта в Cloudflare не заводится.

## Решение

Видео — файл в R2, когда `FileStoreService.isEnabled` (`fileStorageEnabled` в
`GET /auth/config`), иначе https-ссылка (YouTube и подобное). Модель данных несёт
оба поля разом (`videoId`/`videoUrl`) независимо от того, подключен ли R2 —
какой способ доступен, решает экран по `fileStorageEnabled`, не тип поля. Не
больше одного видео на вопрос и не больше одного на вариант; у варианта видео и
картинка — тоже взаимоисключающие (`OPTION_ONE_MEDIA_MESSAGE`).

Новая коллекция `exam_videos` — `{ key, contentType, sizeBytes, createdBy }`,
зеркало `exam_images`, но байты в R2, не в Mongo: `POST /api/exam-videos` сырым
телом (штат школы, до 50 МБ — короткий клип движения, не запись всего занятия),
`GET /api/exam-videos/:id` — 302 на подписанную ссылку `FileStoreService.signedGetUrl`
(инлайн, без `attachment`, TTL час — плеер перематывает и переспрашивает адрес на
каждый seek). Доступ: штат — по роли, ученик — только если видео стоит в снимке
его попытки (`exam_attempts.videoIds`, тот же приём, что `imageIds`, SECURITY §3).
Формат байтов определяет сигнатура (`sniffVideoSignature` — ISO-BMFF `ftyp`/бренд
`qt  ` для `.mov`, EBML для WebM), не заголовок `Content-Type` (SECURITY §4).

Порядок записи — ADR-0079: журнал сирот раньше объекта в R2, снятие — после того,
как запись создана. Сирота старше суток (не сославшийся ни один вопрос/попытка)
убирается тем же шагом планировщика, что и картинки (`ExamVideoSweepService`).

Бот (ADR-0024) не проигрывает видео — только не молчит о нём: ссылка на видео
попадает прямо в текст вопроса, файл R2 отмечается строкой «К вопросу есть
видео — оно в кабинете». Конструктор вопроса в боте видео не получает — это
решение учителя за компьютером, не с телефона на бегу.

**Уточнено 2026-09-27**: отзыв владельца — «в Telegram видео не видно ни в
вопросе, ни в вариантах», строка-отметка не заменяет сам ролик. Бот теперь
присылает клип сам, той же последовательностью, что альбом картинок вариантов
(ADR-0035/ADR-0118): видео формулировки — первым сообщением, затем по каждому
варианту — картинка или видео в порядке вариантов. Файл R2 — `sendVideo` с
байтами (`FileStoreService.get`, новый метод на подпись SigV4 у GET, тем же
приёмом, что `put`/`remove`) в первый раз, дальше — по кэшированному
`telegramFileId` (новое поле `exam_videos.telegramFileId`, зашифровано как у
`exam_images`); Telegram отказался слать по кэшу — один повтор байтами. Доступ
ученика — тот же `ExamVideosService`, что у `GET /api/exam-videos/:id`
(`loadAccessibleDoc`), вторая проверка не заводится. Ссылка (`videoUrl`) —
отдельным сообщением с `link_preview_options.is_disabled: false`, чтобы
Telegram показал плеер YouTube, у варианта — с префиксом «Вариант N». Строка
«К вопросу есть видео — оно в кабинете» остаётся только как деградация:
R2 выключен или объект пропал — экран вопроса всё равно выходит (CLAUDE.md
«Ноль нагрузки»), но без самого клипа; текст вопроса больше не повторяет
ссылку и не пишет отметку заранее — то же самое дважды. Видео вариантов при
сбое молчит так же, как картинки — только warn в логе, без строки на экране.

## Альтернативы

- **Presigned direct upload** (браузер грузит в R2 напрямую, минуя инстанс) —
  отклонено: требует CORS бакета и `connect-src` на R2 в CSP — больше настройки
  для владельца ради 50 МБ раз в несколько вопросов, тогда как через инстанс
  (тот же приём, что материалы, ADR-0057) работает без единой новой переменной
  окружения сверх уже заданных `R2_*`.
- **Только ссылка, без R2** — не годится для владельца без Cloudflare: он либо
  не сможет показать референс без стороннего хостинга, либо будет вынужден
  публично выкладывать учебные материалы школы на YouTube.
- **Видео через Telegram, как у ADR-0023** — не работает для этого случая:
  ученику без Telegram, вошедшему по почте, показать нечего, а видео нужно
  каждому сдающему, а не только тем, у кого есть бот.

## Последствия

- Байты видео идут через инстанс на загрузке (как материалы) — бюджет
  одновременных сырых загрузок (`raw-upload-concurrency.ts`) пересчитан на
  четыре по 50 МБ (200 МБ худший случай) вместо четырёх по 30 МБ.
- `mediaSrc` в CSP пополнился маской `https://*.r2.cloudflarestorage.com` —
  `<video>` запрашивает `/api/exam-videos/:id`, а браузер сверяет CSP по адресу
  редиректа, не по адресу самого запроса (SECURITY §7).
- `exam_items`/`exam_attempts` несут новое плоское поле `videoIds` (индекс) —
  тем же приёмом, что `imageIds`, ради уборщика сирот и права ученика на видео
  своей попытки.
- Версия опубликованного вопроса поднимается и при правке одного только видео —
  `hasContentChanged` теперь сравнивает `videoId`/`videoUrl` наравне с `prompt`.
- **Байты видео в боте — лениво, без общего потолка (2026-10-02, аудит
  [2026-10-01](../audits/2026-10-01-pre-exam-audit.md) F02).** Раньше объект R2 до
  50 МБ ложился в память при каждом показе вопроса, даже когда в Telegram уходила
  строка `file_id`: N учеников на одном видео — N × 50 МБ в куче. Теперь `file_id`
  идёт строкой, а объект читается только когда `file_id` ещё нет или Telegram
  отверг сам идентификатор (400 «wrong file identifier», `FILE_REFERENCE`;
  429, 5xx и сеть байтами не повторяются — тот же отказ, а память занята зря).
  Параллельные чтения одного видео сводит `SingleFlight` по `videoId`
  (`ExamVideosService.loadForBot`): N учеников — одно чтение. Семафор-потолок в
  `FileStoreService.get` (предложенный при разборе F02) не заведён: на экзамене
  вопросов с видео единицы, поэтому и разных видео в памяти бота одновременно
  единицы. Бюджет памяти — число разных видео × размер файла (до 50 МБ), он
  задан составом экзамена, а не числом учеников. Потолок стал бы очередью перед
  сдающим ради защиты, которой в этой нагрузке нет; если вопросов с видео станет
  десятки, решение пересматривается с замером памяти (F68).
- Web-экран конструктора вопроса и загрузка через интерфейс — следующий PR,
  этот ограничен API, `shared` и ботом.

Уточнение к [ADR-0023](0023-exam-video-via-telegram-and-links.md): видео **ответа
ученика** там и видео **референса вопроса** здесь — разные механики с разными
владельцами байтов, уточнено ADR-0133.

Уточнено [ADR-0137](0137-answer-video-file-upload-in-parts.md): видео ответа ученика
тоже живёт в R2, но в своей коллекции `answer_videos` и частями через инстанс — довод
против прямой загрузки разобран там для файла до 1 ГБ.
